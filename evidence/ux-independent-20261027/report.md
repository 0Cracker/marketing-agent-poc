# 분석 도구 사용성과 정보 시각화 독립 평가

## 1. 탐색과 해석을 지원하는지 판정

**기본 조사 경로는 사용할 수 있지만, 조회 맥락 보존과 지표 적용 범위의 표현은 보완이 필요하다.** 특히 비교 표를 왕복할 때 행 구분과 정렬이 초기화되고, 콘텐츠 캠페인의 광고 전용 지표에 실제 0처럼 읽히는 값이 나타난다. 현재 상태를 오독 방지가 충분한 분석 화면으로 판정하기는 어렵다.

평가 대상은 로컬 `dev`, 커밋 `8029ac7`, 패키지 버전 `0.4.1`의 `/workbench`다. 2026-10-27 기준으로 인앱 브라우저에서 직접 조작했다. 기본 뷰포트 1280×720과 추가 1366×768을 사용했다. 배포 사이트와의 일치는 검증하지 않았다. 앱 코드와 데이터는 수정하지 않았다.

첫 사용에서는 S16 기본 화면을 먼저 탐색했다. 시작 지침에 따라 문서 안내와 실행 README를 읽어 최근 변경 요약과 과거 별도 시연 설명에는 노출됐다. 현재 S01~S18의 정답과 검수 경로는 기본 탐색 루프를 마치기 전에 읽지 않았다. 이후 예외 상태를 찾는 과정에서 구현과 기존 테스트 일부를 참고했다. 따라서 완전한 사전 지식 없는 사용자 시험은 아니다.

평가 범위는 정보 구조, 실제 상호작용, 시각 표현과 해석 위험이다. 전략의 타당성, 수식과 원천 데이터의 정확성은 판정하지 않았다. 사용자 성공률과 소요 시간도 측정하지 않았다. 아래 위험과 탐색 부담은 전문가 관찰이며 실제 사용자 행동의 확정 결과가 아니다.

유지할 장점은 다음과 같다.

- 상단에 사례, 분석 날짜, 직전 14일 날짜, 보고 기준, 캠페인과 기기를 표시하고 스크롤 중에도 유지한다.
- 현황, 지표 상세, 비교 표의 역할이 제목과 경로로 구분된다. `상세 분석`, `세부 수치와 운영 기록`, 근거 창의 복귀 버튼을 실제로 사용할 수 있다.
- 큰 추이 차트는 두 기간을 같은 0 기준 축에 표시한다. 직전 기간은 점선, 현재는 실선이어서 색상 외 구분도 있다. 이중축은 확인한 교육 화면에 없다.
- ROAS 상세에서 매출과 비용을 함께 볼 수 있다. 표에는 현재, 직전, 증감이 한 행에 연결되고 가로 이동 중 행 이름이 고정된다.
- CAC 미집계 사유, 주문 0인 상품의 계산 불가, 광고와 콘텐츠의 미적용 상태를 구분하는 기본 표현이 있다.
- 브라우저 뒤로 가기, 근거 닫기와 전체 현황 복귀가 동작한다. 키보드 정렬, 포커스 표시, 방향키를 통한 큰 추이 차트 값 조회도 확인했다.

## 4. 시각화 목록과 요소별 판정

전체 목록은 [시각화 목록](visualization-inventory.md)에 기록했다. 교육 화면의 KPI 7종, 큰 추이와 작은 추이, 집단 비교, 퍼널, 6개 조사 목적의 표, 근거와 기준 정보, 전체 데이터 탐색의 41개 자료 화면을 구분했다. 각 항목에 사용자 질문, 지표와 집단, 기간, 표현의 적합성, 오독과 영향, 판정을 기록했다.

큰 추이는 시간 변화, 공통 0 기준의 쌍 막대는 집단과 기간 비교에 적합하다. 표는 매출, 비용, 주문과 비율을 함께 비교할 수 있으므로 유지한다. 도넛은 소수 범주의 구성 확인에 유지하며 정밀한 범주 순위 판단은 옆의 수치나 표로 보완한다. 가격 범위도와 관측 달력 역시 현재 질문에 맞는다. 유지 판정은 개별 값의 정확성까지 승인한다는 뜻이 아니다.

관계나 인과를 보여주는 산점도는 확인한 화면에 없다. ROAS, 매출, 비용을 함께 읽는 질문은 기존 관련 지표 표로 지원할 수 있으므로 새로운 이중축이나 산점도를 기본 해법으로 권하지 않는다.

## 5. 근거를 갖춘 상세 발견

### UX-01, 높음: 미적용 상태가 실적 0과 데이터 부재로 바뀌어 보인다

S14에서 네이버 블로그를 선택하고 CTR 상세를 열면 상단은 `해당 없음`이고 추이 영역도 광고 노출 기준이라는 사유를 설명한다. 그런데 계산에 연결된 지표는 `광고 노출 0`, `클릭 0`, CPC와 광고 CPM은 `데이터 없음`이다. 비교 표는 콘텐츠 링크 클릭률 열까지 제시하면서 0개 그룹이 된다.

조회 캠페인은 콘텐츠인데 하위 계산은 광고 집계만을 대상으로 한다는 차이가 각 표에 표시되지 않는다. 사용자가 전체 캠페인 클릭이 0이거나 CPC 수집이 실패했다고 읽을 수 있다. 산식 오류로 단정하지 않으며, 적용 모집단과 빈 상태 설명의 문제다. 광고 전용 구역을 미적용으로 통일하고 콘텐츠 유입 자료로 가는 경로를 제공한다.

근거: `frontend/workbench/training-dashboard.tsx`의 MetricDetails, DataWorkspace에서 광고 CTR에 한해 행을 제한하는 부분, 직접 조작 기록.

### UX-02, 높음: 조회 필터를 보존해도 조사 중인 표 설정은 보존하지 않는다

S14 계측 대조에서 기기별 비교와 변화량 순위를 선택했다. ROAS 상세를 방문하고 브라우저 뒤로 가기를 누르자 캠페인별 현재 수치 순위로 돌아왔다. 기간과 Meta Ads는 남으므로 사용자는 원래 조사 상태가 복원됐다고 생각하기 쉽다. CPC 검색어별 표에서 콘텐츠 캠페인으로 범위를 좁힐 때도 소재별 비교로 바뀌지만 변경 사유 안내가 없다.

지표, 조사 목적별로 행 구분, 정렬 열, 정렬 기준과 방향을 유지한다. 호환되지 않는 설정만 변경하고 이전 선택과 대체 선택을 안내한다. 캠페인에서 다른 집행처로 바꿀 때 이미 제공하는 안내 방식을 확장하면 된다.

근거: `training-dashboard.tsx:133`, `:159`, `:200` 부근의 탐색 이력 처리, 직접 왕복 재현.

### UX-03, 높음: 진입한 지표가 표의 중심이 아니다

AOV 비교 표는 주문 순위와 주문 추이로 시작하며 AOV는 오른쪽 끝에 있다. CPC 표는 노출/조회 순위와 추이로 시작한다. CPA의 성과 비교 표는 ROAS로 시작한다. CAC 비교 표는 ROAS 중심이며 CAC 열이 없다. 열 정렬을 누르면 추이 지표도 함께 바뀌지만 사전에 이를 알리는 설명은 없다.

이 표들은 다른 질문에는 유용하므로 제거하지 않는다. 진입 지표를 첫 수치 열과 기본 순위, 추이로 연결한다. CAC는 계산에 필요한 자료가 없음을 유지하고 대체로 보는 자료임을 제목에서 밝힌다.

### UX-04, 중간: 조사 자료가 존재해도 그 진입 지표를 알아야 찾을 수 있다

계측 대조는 ROAS 또는 CVR, 결제 실패는 CVR 또는 CPA, 상품과 매출은 AOV 경로에 있다. 성과 현황에서는 이런 조사 목적의 전체 목록을 볼 수 없다. `세부 수치와 운영 기록`은 자료의 종류를 알려주지만 어느 업무 질문을 다루는지는 드러내지 않는다.

기본 루프를 찾을 수 있다는 것과, 결제 장애라는 질문에서 올바른 진입점을 바로 고를 수 있다는 것은 다르다. 현황에 조사 목적별 짧은 바로가기 목록을 추가하거나 기존 버튼 옆에 제공 자료를 표시한다. 별도 대시보드를 만들 필요는 없다.

### UX-05, 중간: 핵심 정의와 일별 값의 해석이 설명 안에 묻힌다

현황은 CTR, CVR, CPA로 표시하지만 상세 표에서는 광고 CTR, 클릭 기준 구매율, 구매 CPA로 이름이 바뀐다. CVR 상세 제목의 정의는 `title` 속성에 있고, 귀속 주문/클릭과 같은 세션 퍼널의 차이는 다른 구역의 설명을 연결해야 이해된다. 귀속 매출의 7일 창, 접점일 기준, 환불 제외와 가상 배분은 접힌 집계 기준에 있다.

큰 차트는 일별, KPI는 기간 전체 비율인데 같은 지표명으로 연결된다. 화면만으로 일별 비율의 단순 평균이 기간 값인지 판단하기 어렵다. 실제 집계 규약을 담당 평가자에게 확인한 뒤 관계를 한 문장으로 명시한다. 화면의 주요 지표명과 부제에 적용 범위와 분모를 고정 표시하고 긴 정의는 기존 접기 안에 유지한다.

계산 불가 셀은 키보드 포커스와 접근성 이름이 있지만 시각적 사유는 포커스만으로 열리지 않았다. 툴팁에만 의존하지 않는 펼치기나 짧은 사유를 제공한다. 큰 추이 차트의 방향키 툴팁은 실제로 동작했다.

### UX-06, 중간: 작은 추이의 높이는 지표 간 변동 규모 비교에 쓸 수 없다

KPI 카드의 작은 차트는 축과 날짜, 자체 범위를 표시하지 않는다. 서로 다른 단위의 지표가 같은 높이에 놓여 있다. 구현상 지표별 계열로 그리며 카드 간 공통 축을 제공하지 않는다. 같은 높이의 굴곡을 같은 변동률이나 중요도로 읽을 수 있다.

카드 간 눈금을 억지로 통일하지 말고 `지표별 눈금, 방향 확인용`임을 알린다. 캠페인 표 안의 작은 차트는 공통 눈금과 선 종류를 명시하므로 유지한다. 다만 그 숫자 범위는 이미지의 접근성 이름과 title에 있으므로 필요하면 표 설명에 노출한다.

### UX-07, 중간: 증감색의 의미가 성과의 좋고 나쁨과 구분되지 않는다

증가를 빨강, 감소를 파랑으로 표시한다. 매출 증가와 비용 증가가 같은 색이고, ROAS 감소와 CPA 감소도 같은 색이다. 부호와 % 또는 %p가 있어 색상만의 구분은 아니지만, 색이 성과 평가처럼 읽힐 가능성이 남는다.

중립색으로 통일하거나 `색은 증감 방향이며 성과 평가는 아님`이라는 설명을 둔다. 지표별로 좋은 방향을 임의 확정하지 않는다.

### UX-08, 중간: 운영 사건과 추이의 시점을 머릿속에서 대조해야 한다

S16 검색 A의 08.17 예산, 타깃 변경과 구체적 적용 시각을 열 수 있었다. 그러나 큰 성과 추이에 해당 사건 표시나 선택한 날짜로 돌아가는 연결이 없다. 사건은 비교 표 아래 접힌 운영 근거에서 다시 찾아야 한다.

기존 날짜축에 사건 표시를 선택적으로 추가하거나, 운영 기록을 선택하면 관련 날짜를 강조한다. 직전 기간이 같은 요일 위치에 겹쳐 있으므로 사건은 실제 해당 기간의 날짜에만 연결해야 한다. 표시 자체가 원인 입증이라는 인상을 주지 않도록 관측 사건으로 이름 붙인다.

### UX-09, 중간: 근거 목록은 ID를 알아야 탐색하기 쉽다

112행 근거 목록은 `S14-baseline-2-0-0` 같은 제목으로 시작한다. 날짜, 캠페인, 기기를 보려면 개별 행을 펼쳐야 한다. 30개 더 보기는 동작한다. 근거 창이 오른쪽을 가려 사례와 보고 기준을 창 내부에서 확인할 수 없고, 제목에는 원래 기기와 조사 목적이 충분히 남지 않는다.

상품 기준 정보에는 `label`, `listPrice`, `discountRate: 0.2`가 단위 없이 나타난다. 전체 탐색의 협업 표에는 `synthetic_signed`가 그대로 보인다. 필드와 상태의 정확한 뜻을 확인한 뒤 사용자용 이름과 단위를 붙이고 원래 ID는 보조 정보로 유지한다. `0.2`의 단위나 상태 의미를 이 평가에서 임의 확정하지 않는다.

### UX-10, 중간: 반올림이 표시된 현재값과 증감을 모순처럼 보이게 한다

S16 전체 지표 표의 광고 CTR은 직전 2%, 현재 2%, 변화 +0.1%p다. 검색 A 표에는 직전 1.8%, 현재 1.8%, +0%p가 나타난다. 계산 오류라고 판단할 근거는 없지만, 화면만 보면 같은 값의 증가나 0의 양수 변화를 이해하기 어렵다.

작은 비율 변화에 한해 필요한 자릿수를 제공하고, 표시 정밀도 미만 변화는 정의된 임계값과 함께 설명한다. 평균 비용의 원 단위 소수점과 상품 기준 필드의 원시 소수 비율을 같은 정밀도 규칙으로 처리하지 않는다.

### UX-11, 중간, 의미 확인 필요: 퍼널의 단위 설명이 세션과 인원을 혼용한다

퍼널의 첫 단계는 랜딩 세션, 마지막은 같은 세션 구매다. 설명에는 `같은 인원 눈금`과 `같은 세션에서 순차 도달한 수`가 함께 나온다. 고유 사람 수인지 세션 수인지 일관되게 읽히지 않는다. `재방문 구매 제외`, `이탈이 곧 결제 오류는 아님`은 유용하며 유지한다.

담당자에게 모집단과 중복 제거 단위를 확인한 뒤 단위를 일치시킨다. 단계별 공통 눈금, 두 기간 병렬 배치, 이탈 수와 비율은 현재 질문에 적합하므로 유지한다. 확인 전 인원 수나 사용자 이탈률이라고 단정하지 않는다.

### UX-12, 높음: 전체 데이터 탐색이 별도 분석 체계로 전환된다

교육 사례에서 전체 데이터 탐색을 누르면 일본, JPY, 2026.08, 시장 현황으로 바뀐다. 교육 상품과 별도 기존 상품을 다루며, 교육 화면의 ROAS는 %인데 광고 탐색에서는 배로 표시한다. 원래 교육 화면의 접힌 범위 설명에 두 상품 체계가 별도라는 문구는 있다. 전환 위치에는 이 차이와 필터 비공유를 알리는 설명이 없다.

전체 탐색의 시장 현황은 상단 기준월이 2026.08인데 추이는 25.10부터 08까지 펼쳐진다. 광고 성과도 상단 월과 다른 긴 추이를 표시한다. 표의 해당 월 값과 역사적 추이의 구분을 사용자가 축만 보고 추론해야 한다. 기존 `chart.subtitle`은 주로 툴팁과 근거 안에 전달된다.

전환 버튼에 별도 원천 탐색임을 표시하고, 탐색 화면에서 교육 사례 필터가 적용되지 않음을 알린다. 각 차트에 실제 추이 기간, KPI와 표에 집계 대상 기간을 노출한다. 복귀는 동작하므로 버튼 이름만 성과 현황과 일치시킨다. 상품, 통화, ROAS 표기 단위를 같게 바꾸는 작업은 이 평가의 제안이 아니다.

### UX-13, 중간, 의미 확인 필요: 보고 기준시점을 바꾸는 위치와 의미가 멀다

보고 기준은 상단에 보이지만 변경 컨트롤은 하단 테스트 케이스 안에 있다. 같은 곳의 사례 설명은 기본 사례의 변화 방향을 미리 알려준다. 기준시점 변경에서는 분석 기간이 유지되고 보고 날짜만 바뀌는 것을 확인했지만, 그 시점이 수집 완료 시점인지 귀속 반영 마감인지 화면은 설명하지 않는다.

상단 보고 기준 옆에서 해당 컨트롤을 열 수 있도록 연결한다. 데이터 담당자가 의미를 확정한 뒤 분석기간과의 차이를 짧게 설명한다. 사례 설명은 필요할 때 열람하게 하면 정답 단서를 보지 않고 조사하려는 사용자도 지원할 수 있다.

| UX-11 | 확인된 모집단에 맞춰 퍼널 단위 통일 | 단계 수와 이탈 수의 단위가 하나로 명시되고, 고유 사람 수인지 세션 수인지 모호하지 않다. |
| UX-12 | 별도 원천 전환 안내, 차트/표 각각 실제 기간 표시 | 교육 사례와 원천 탐색의 필터 비공유를 인지한다. 상단 월, 추이 기간, 표 집계 기간을 각각 설명할 수 있다. |

기능 검증은 기존 UI에서 위 재현 경로를 반복한다. 실제 사용자가 발견하거나 올바르게 해석하는지는 아래 실험으로 따로 확인해야 한다. 기능 검사만 통과했다고 사용성 문제가 해결됐다고 결론 내리지 않는다.

## 7. 실제 마케터 사용자 실험에서 확인할 가설

| 가설 | 과업과 관찰 항목 |

| 조사 목적 바로가기가 진입 부담을 줄인다 | 지표 이름을 주지 않고 결제 실패와 계측 누락 확인을 요청한다. 첫 선택, 잘못 들어간 경로, 도움 요청, 완료 여부를 비교한다. |
| 표 설정 보존이 조사 대상 혼동을 줄인다 | 기기별 변화량 조사 중 근거와 상세를 왕복시킨다. 복귀 후 비교 집단과 순위 기준을 말하게 한다. |
| 적용 범위 표시가 0, 미집계, 미적용 오독을 줄인다 | 콘텐츠 CTR, CAC, 주문 0인 상품을 각각 설명하게 한다. 유입 없음, 고객 없음, 미제공, 미적용을 구분하는지 기록한다. |
| 비율의 분모 표시가 CVR와 퍼널 해석을 돕는다 | 클릭 기준 구매율과 같은 세션 구매율이 다른 이유, 재방문 구매의 포함 여부를 설명하게 한다. |
| 작은 추이와 증감색의 설명이 중요도 판단 왜곡을 줄인다 | 같은 높이의 서로 다른 카드, 매출 증가와 비용 증가를 비교시킨다. 색과 굴곡만으로 우열을 정하는지 관찰한다. |
| 사건 표시가 시간 대조를 돕지만 인과 단정을 늘리지는 않는다 | 성과 변화와 운영 변경 날짜를 찾아 대조시킨다. 근거 날짜 식별과 인과 확신을 별도 평가한다. |
| 원천 전환 안내가 서로 다른 데이터의 혼합을 줄인다 | 교육 사례에서 전체 데이터 탐색을 사용한 뒤 상품, 통화, 기간과 ROAS 단위를 설명하게 한다. 수치를 직접 연결하는지 관찰한다. |
| 근거 행 요약이 내부 ID 지식 없이 기록을 찾게 한다 | 캠페인명과 날짜만 주고 운영 기록과 집계 행을 찾게 한다. 실제 과업 시간은 이 실험에서 측정한다. |

수정 전후에 동일한 질문과 성공 기준을 사용한다. 참가자 역할, 분석 도구 숙련도, 도움 제공 조건을 기록하고 수치 해석의 정답 기준은 데이터 담당 평가자와 먼저 합의한다. 이 보고서에서 효과 크기, 성공률, 시간 절감률을 추정하지 않는다.
