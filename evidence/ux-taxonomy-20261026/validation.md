## PC Chrome 실제 조작

주소는 `http://127.0.0.1:5173/workbench`, 기본 S16이며 분석기간은 2026-08-17~08-30, 비교기간은 08-03~08-16이다.

1. 기존에 선택돼 있던 인스타그램 콘텐츠 협업 캠페인에서 ROAS 상세로 진입했다. 관련 기록 8건을 펼치고 2026-08-21 간편결제 처리 기록의 상세 항목을 확인한 뒤 닫고 전체 현황으로 돌아왔다. 캠페인, 기기와 기간이 유지됐다.
2. 전체 범위에서 구글 검색 첫 캠페인을 선택한 뒤 페이스북 매체로 바꿨다. 캠페인이 전체로 초기화되고 이유를 설명하는 상태 메시지가 나타났다.
3. 전체 매체 상세 표에서 ROAS 분석기간 값 오름차순의 첫 캠페인은 인스타그램 피드, 96.5%였다. 증감 오름차순으로 바꾸면 구글 검색 첫 캠페인, -293.7%p가 먼저 나타났다. 현재 정렬 기준도 변경됐다.
4. 운영 기록 종류를 장애와 점검으로 선택했다. 표시 이름의 한국어화 시 option value가 번역 문자열로 바뀌어 필터가 전체로 돌아가는 문제를 조작 중 발견했다. canonical value를 명시해 수정한 후 36건에서 2건으로 좁혀지는 것을 확인했다.
5. 해당 기록을 열어 한글 필드명과 시작, 종료, 오류코드, 결제수단, 브라우저를 각각 읽었다. 캠페인의 null은 공통, 상품의 null은 특정 상품 미지정으로 표시했다. 원본 값은 수정하지 않았다. 상세 표로 돌아온 뒤 전체 현황 복귀도 확인했다.
6. 보고 기준을 2026-08-31에서 2026-09-07로 바꿨을 때 실제 로딩 데이터의 기준일과 상단 표시가 함께 변경됐다.
7. 메인 ROAS 차트의 0, 200, 400%와 날짜 4개, 실선과 점선, 보조 지표의 축과 개별 범례 제거를 화면에서 확인했다. 현재 데이터와 기간 집계값은 유지됐다.

## 후속 보조 지표 툴팁, 같은 날

사용자는 작은 차트의 축과 개별 범례 없이, ROAS처럼 포인터를 올려 날짜별 수치를 읽을 수 있게 요청했다. 공통 PeriodPlot의 툴팁을 보조 차트에도 연결하고, 숨긴 날짜 축으로 대응 날짜를 유지했다. 첫 시도에서 body portal에는 좌표 배치가 자동 적용되지 않아 툴팁이 화면 위치와 맞지 않는 것을 확인했다. 기존 Recharts 배치를 재사용하고 해당 카드의 hover와 focus-within에서만 overflow를 허용하는 방식으로 수정했다.

PC Chrome의 S16 전체 범위에서 포인터를 옮겨 CTR, CPC, CVR, CPA, AOV의 표시를 확인했다. 예를 들어 CPC는 분석 08-23, 직전 08-09에 598.5원과 533.5원, CVR은 같은 날짜에 3.3%와 4.9%, AOV는 분석 08-24, 직전 08-10에 33,333.3원과 38,181.8원을 표시했다. [CPC 툴팁 화면](metric-hover.jpg)을 저장했다. CAC는 기존 데이터에 신규 고객 수가 없어 숫자 추이를 만들지 않고 사유를 title과 접근성 설명으로 제공한다.
