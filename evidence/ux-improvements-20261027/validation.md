# UX-02, 03, 06, 07 반영과 검증

2026-10-27, dev `8029ac7` 이후 미커밋 작업본. 기존 ROAS 대화 기능의 미커밋 변경을 보존한 상태에서 교육 대시보드만 수정했다. 이 기록은 독립 평가 당시 보고서를 덮어쓰지 않는다.

## 승인 범위와 구현

- UX-02: 표 상태를 대시보드 부모에서 지표, 조사 목적별로 관리한다. 행 구분, 정렬 열, 현재값/변화량 기준, 정렬 방향과 운영 기록 종류를 유지한다. 탐색 이력에 표 상태와 조사 목적을 함께 보관한다. 호환되지 않는 검색어 비교와 운영 기록 종류를 바꿀 때는 사유를 알린다. 새로고침 후 영구 보존은 추가하지 않았다.
- UX-03: 진입 지표와 관련 분자, 분모를 표 앞에 배치하고 기본 순위와 일별 추이의 기준으로 사용한다. CPC에는 기존 집행비, 클릭, CVR에는 기존 귀속 주문, 클릭을 연결한다. 사용자가 바꾼 정렬은 유지한다. CAC는 신규 고객 자료 부재를 명시하고 확인 가능한 집행비를 분리해 제시한다. 운영 기록 열람은 보존한다. 계측 대조와 결제 실패처럼 질문이 바뀌는 표는 해당 목적의 기존 지표를 사용한다.
- UX-06 최종 요청: 주요 지표 카드의 작은 추이는 0을 강제 시작점으로 삼지 않고, 현재와 직전의 실제 값 범위를 함께 감싸는 옅은 상한/하한 눈금 2개만 표시한다. 데이터가 실제 0을 포함할 때는 0이 하한일 수 있다. 값이 일정하면 양옆 범위를 확보하고, 미집계는 숫자로 바꾸지 않는다. 큰 기간별 추이의 0 기준 축은 유지한다. 별도 범위 문구는 없으며 카드 안의 176px 차트와 제목/수치/그래프 행 정렬은 유지한다. 임의로 변경했던 자동 열 배치는 되돌려 일반 PC에서는 기존 3열, 좁은 화면에서는 2열, 모바일에서는 1열로 사용한다. 새 설명 패널은 만들지 않았다.
- UX-07: ROAS, 구매율, 매출, 구매 주문, AOV 등의 증가와 CPC, CPA, 실패율 등의 감소는 개선 빨강, 반대는 악화 파랑이다. 집행비, 비용 비중, 할인 조건 등 방향만으로 판단할 수 없는 값은 중립이다. 오른쪽 상단에 `빨강: 개선, 파랑: 악화, 회색: 중립`을 표시한다. 기간 구분용 실선/점선과 보라색/회색은 유지한다.
- 후속 요청: 실제 동일값과 화면의 소수 첫째 자리에서 반올림해 0이 되는 증감은 `0%`, `0%p`와 같은 중립색으로 처리한다. 분모 0으로 상대 증감을 비교할 수 없는 값도 중립이다. 수치 자체와 계산 산식은 변경하지 않았다.
- UX-04 조사 목적 바로가기는 사용자 요청에 따라 보류했다.
- 추가 화면 피드백: 기기를 상단 1차 필터에서 제거했다. 지표 상세의 기기별 성과 비교 표는 캠페인 범위 안의 모바일과 PC를 함께 보여 주며, ROAS, 구매율, CPC, CTR과 매출/비용/주문을 비교한다. 한 기기 조회는 상세 영역의 일반 선택기로 옮겼다. 기기별 비교를 고르면 전체 기기로 조회 범위를 맞추고 사유를 표시한다. 현황으로 돌아가거나 다른 지표로 새 진입할 때는 전체 기기를 보며, 브라우저 뒤로 가기에는 해당 상세의 기기 선택을 함께 복원한다. 이 복원 동작의 실제 브라우저 조작은 미검증이다. 없는 태블릿 분류나 예시 수치는 만들지 않았다.
- 캠페인 선택 창: 검색창 아래 전체 캠페인/전체 집행처 헤더가 목록을 감싸게 했다. 전체 캠페인 조회를 헤더 안의 테두리 있는 버튼으로 옮기고, 집행처 전체 조회에도 버튼 테두리, hover와 키보드 포커스를 적용했다. 전체 캠페인 조회는 검색 결과와 무관하게 원래 전체 범위를 선택한다.
- ROAS 카드 최종 스케치 반영: ROAS 제목과 구매 전환 매출 기준을 카드 왼쪽 위에 독립 배치했다. 그 아래에 직전 작은 값 → 굵은 직선 화살표 → 큰 현재 값을 한 줄로 배치하고, 변화량(%p)을 화살표 아래로 옮겼다. 곡선 화살표는 제거했다. 기간 식별을 위해 직전 값 위에는 `직전 14일`, 현재 값 위에는 `분석 기간`을 표시하고 `직전 14일 대비`는 반복하지 않는다. 상승/하락 단어와 추가 산식은 넣지 않는다. 화살표는 개선 빨강, 악화 파랑, 표시 정밀도의 0 변화는 중립색이고 일별 궤적을 새로 만든 것은 아니다. 모바일에서는 같은 순서를 유지하며 폭과 현재 수치 글자 크기를 줄인다.

변경 파일은 `frontend/workbench/training-dashboard.tsx`, `training-dashboard.css`, `training-scope-picker.tsx`, `training-presentation.ts`, `tests/training-presentation.test.ts`와 이번 기록이다. 기존 원천, 데이터 스키마, 데이터 생성기와 집계 모듈은 변경하지 않았다.

표현 검사는 기존 S16의 ROAS와 CPC 방향, 집행비와 할인 조건의 중립, 모든 기존 18개 사례의 두 기간 최대값과 공통 축, 열 우선순위와 입력 순서 보존, 실제 0과 반올림 0의 중립색을 확인한다. 상태 복원의 실제 UI 조작 시험을 이 단위 검사로 대체했다고 주장하지 않는다.

추가 검사는 ROAS 주 수치가 각 기간 매출 합계/집행비 합계이며 일별 ROAS 평균이나 마지막 날 값과 다름을 S16으로 확인한다. 직전 매출 37,280,000원/집행비 10,478,096원은 약 355.8%, 분석 기간 매출 38,560,000원/집행비 16,929,052원은 약 227.8%다. 두 값의 차이는 약 -128%p이며 상대 감소율과 구분한다. 일별 추이의 각 점은 해당 날짜 매출/집행비다. 원래 집계 방식은 변경하지 않았다.

작은 추이 범위 검사 2개를 추가했다. 예시 범위 10,000~20,000원, 2.5~5%와 함께 기존 18개 사례의 현재/직전 값이 공통 상하한 안에 포함되는지, 기간 순서를 바꿔도 범위가 같은지, 일정한 값/0/미제공 상태의 범위 처리가 가능한지 확인한다. 이는 축 계산 검사이며 화면 배치의 시각 검증은 아니다.

린트 도구는 저장소에 Next 기본 pages 경로가 없다는 설정 안내를 출력했다. 대상 코드의 ESLint warning은 0이다. 빌드는 SUIT와 Pretendard 폰트 경로를 실행 시점에 해석한다는 안내, 플러그인 소요 시간 안내를 출력했다. 폰트가 실제 브라우저에서 로드되는지는 이번에 검증하지 않았다.

## 브라우저 검증 한계와 남은 확인

`http://127.0.0.1:5173/workbench`의 실제 화면을 검증하려 했으나 자동 승인 심사가 계정 사용량 제한으로 실패하여 페이지 접근이 실행되지 않았다. 위험한 페이지라는 판정은 아니다. 다른 브라우저, 터미널 기반 브라우저 또는 다른 포트로 우회하지 않았다. 따라서 수정 후 PC 화면의 배치, 뒤로 가기, 포커스와 스크롤 복원은 미검증이다. 이전 독립 평가의 조작 결과는 수정 전 결과다.

기기와 캠페인 선택 추가 피드백 반영 후 같은 경로의 브라우저 접근을 다시 시도했으나 `Work 설정에서 로컬 브라우저 사용 비활성화`로 실행되지 않았다. 현재 화면 검증의 직접적인 차단 조건은 이 설정이다.

남은 실제 확인 경로:

1. ROAS → 계측 대조 → 기기별 → 변화량 정렬과 운영 변경 선택 → 상세 → 브라우저 뒤로 가기. 행 구분, 정렬과 운영 기록 종류가 복원되는지 확인한다.
2. 같은 표에서 집계 근거 열기, 닫기, 현황 복귀와 재진입 후 설정과 상단 범위를 확인한다.
3. CPC 검색어별 표에서 콘텐츠 캠페인을 고른다. 소재별 전환 사유와 남아 있는 유효 정렬을 확인한다.
4. CPC, CPA, AOV, CVR 표의 첫 수치와 분자, 분모, 초기 추이 지표를 확인한다. CAC의 자료 부재 설명과 운영 근거가 함께 남는지 확인한다.
5. 작은 차트의 현재와 직전 선이 같은 눈금을 쓰며 왼쪽 상한/하한 2개 눈금과 일치하는지, 큰 차트는 여전히 0 기준인지 확인한다. 0 또는 반올림 0 증감은 회색, CPC 증가와 ROAS 감소는 파랑인지 확인한다. ROAS 카드가 직전 → 현재 순서이고 화살표 방향과 %p 변화가 두 기간 값과 일치하는지도 확인한다.
6. 1280×720, 1366×768과 AI 대화 패널을 연 상태에서 우측 상단 범례의 겹침과 표 가로 이동을 확인한다.
7. 상세 조회를 모바일로 바꿔도 기기별 비교 표에는 모바일과 PC가 함께 남는지, 현황 복귀 시 전체 기기로 돌아가고 뒤로 가기 시 상세 기기가 복원되는지 확인한다.
8. 캠페인으로 찾기와 집행처로 찾기 양쪽에서 목록을 감싸는 헤더와 전체 조회 버튼의 클릭, 검색, 키보드 포커스와 닫은 뒤 복귀를 확인한다.

커밋과 배포, 패치 증가를 수행하지 않았다. 같은 파일의 기존 미커밋 대화 기능을 임의로 함께 커밋하지 않았으며 화면 조작 검증도 남아 있다.
