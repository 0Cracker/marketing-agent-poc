현재 PoC는 성과 점검과 원인 후보 조사에는 조건부로 사용할 수 있지만, 복합 사례의 조사와 집행 변경 판단을 화면만으로 끝내기에는 부족하다.

# 독립 퍼포먼스 마케터 평가

평가일: 2026-10-26, 평가 대상: 로컬 `/workbench`, 기준 커밋: `3c11e4237c4d74e9efd96fbe5cab4a7391dc4651`, 브랜치: `main`.

## 1. 실무 조사와 판단 도구로 사용 가능한지

**교육용 조사 도구로는 조건부 사용 가능, 실제 예산 변경을 단독으로 정당화하는 도구로는 부족하다.** ROAS와 매출의 방향이 다를 수 있다는 사실, 캠페인 구성 변화, 결제 실패와 추적 누락, 후행 전환을 비교할 자료는 있다. 반면 타깃과 상품의 구매 과정까지 연결하는 탐색, 사건 전후 기간의 비교, 보고 기준시점의 명시가 충분하지 않다.

이 평가는 처음 전달받은 마케터의 업무를 AI가 수행한 전문가 점검이다. 실제 마케터 사용성 실험은 아니다. 탐색 성공률, 소요 시간, 학습 효과를 측정하거나 추정하지 않았다.

### 검증 순서와 독립성

1. 프로젝트 `AGENTS.md`, `docs/README.md`, 실제 Git 상태부터 확인했다. 시작 시 미커밋 변경은 없었다. 버전 대응표를 확인했으나 패키지 버전을 현재 화면의 발행 버전으로 간주하지 않았다.
2. 실행 방법을 확인하고 Vite를 `127.0.0.1:5173`에서 실행했다. 초기 연결 실패와 로딩 이후 실제 화면에 접근했다. 정적 교육 데이터 화면이므로 실제 모델 호출과 광고 집행은 하지 않았다.
3. **시나리오 정답, 생성 규칙, 검수용 원인 설명을 읽기 전에** 기본 S16을 조사했다. 이후 S01~S15, S17, S18의 전체 기간 수치를 화면에서 비교하고, S07, S14, S15, S17, S18의 관련 상세를 추가 조사했다. 모든 사례를 동일한 깊이로 검증한 것은 아니다.
4. 화면 탐색과 잠정 판정을 먼저 마친 뒤 `docs/design/roas-training-dashboard.md`, 현재 UI 코드와 생성 규칙을 대조했다. 필수 문서에서 S16 기본값과 복합 사례가 존재한다는 사전 정보는 얻었지만, 원인 조합과 액션 정답은 이 단계 전에는 읽지 않았다.
5. 다른 평가자의 보고서는 읽지 않았다. 설계 문서에 포함된 과거 자동 검증 수치는 이번 평가의 통과 근거로 사용하지 않았다.
6. 후속으로 공개 JSON 응답을 직접 합산했다. 애플리케이션의 집계 함수를 재사용하지 않았다. 산술 결과와 응답 해시는 [calculations.json](calculations.json)에 기록했다. 전체 산식 구현 감사는 이번 역할의 범위가 아니다.

실제 브라우저 조작은 데스크톱 폭에서 수행했고, 이후 더 좁은 폭의 화면도 관찰했다. 체계적인 반응형, 모바일, 접근성 검증은 미실행이다. 일부 선택 실패는 접근성 인덱스와 숨겨진 메뉴 상태를 다시 읽어 해결했으며 제품 결함으로 세지 않았다. 캡처 이미지는 도구 출력에서 확인했으나 별도 이미지 파일로 저장하지 않았다. 아래 재현 경로와 관찰 수치, API 및 코드 위치가 재확인 근거다.

### 판단의 증거 수준

- **관찰 확인:** 화면에 표시된 값, 실제 선택 가능한 필터, 상세 기록과 메뉴 이동.
- **계산 확인:** 공개 JSON의 합계와 비율, 화면에서 읽은 수치의 산술 비교.
- **전문가 추정:** 정보의 배치나 누락이 초래할 수 있는 업무 오판, 개선 우선순위. 실제 발생률은 미측정.
- **미검증:** 실제 마케터의 이해도와 과업 성공, 변경의 인과효과, 현실의 매출과 이익, 실제 광고 플랫폼과의 일치.

## 2. 가장 위험한 업무 오판

**전체 ROAS 하락을 확장 타깃이나 소재 하나의 문제로 단정하고, 정상 집단과 개선 소재까지 일괄 축소하는 판단**이 가장 우려된다. 이는 관찰된 사용자 행동이 아니라 전문가의 위험 평가다.

기본 S16은 ROAS가 355.8%에서 227.8%로 하락하지만 매출은 37,280,000원에서 38,560,000원으로 증가한다. 비용은 10,478,096원에서 16,929,052원으로 증가하고, 주문도 963건에서 1,180건으로 늘었다. 따라서 매출 감소 사례가 아니라 **규모 확대에 비해 비용 효율이 나빠진 사례**다.

구글 검색 01, 02와 피드 캠페인의 예산 변경, 08-21~24 모바일 간편결제 오류, 08-24 페이스북 소재 v2 투입이 겹친다. PC 결제 실패가 0이라는 대조 자료도 있다. 이 상황에서 전체 캠페인 중단, 결제 실패 73건을 영구 손실 주문 73건으로 환산, 신규 소재의 CTR 개선을 증분 매출 효과로 확정하는 것은 정당하지 않다.

다른 위험은 S17의 ROAS 상승을 사업 성장이나 순이익 개선으로 해석하는 것이다. S17은 ROAS 456.9%지만 귀속 매출이 43.3%, 주문이 49.3% 감소한다. 원가, 공헌이익, 환불, 쇼핑몰 전체 매출과 목표 우선순위가 없으므로 수익성과 사업 전체 성장을 판정할 수 없다.

## 3. 과업별 수행 결과

아래 경로는 실제 사용한 경로다. 정답을 읽은 뒤 알게 된 사실은 별도로 표시했다. 첫 화면의 전체 범위는 전체 매체, 전체 캠페인, 전체 기기, 분석 08-17~30, 비교 08-03~16, 보고 기준 08-31이다.

### 과업 1, 현재 성과와 중요한 변화

- **업무 질문:** 효율, 규모, 구매 중 무엇이 변했는가?
- **실제 경로와 필터:** 기본 S16, 성과 추이 → 전체 성과 지표와 기간별 수치 펼침 → ROAS 상세 분석.
- **화면 근거:** ROAS -128%p, 매출 +3.4%, 비용 +61.6%, 주문 +22.5%, CPC +12.1%, AOV -15.6%.
- **가능한 결론:** 비용 증가가 매출 증가보다 크고, 구매율과 객단가도 하락했다.
- **불가능한 결론:** 순이익 감소, 쇼핑몰 전체 매출 변화, 특정 원인의 기여액.
- **화면 밖 필요 정보:** 사업 전체 매출과 이익을 판단하려면 필요. 귀속 성과의 변화 확인에는 불필요.
- **결과:** 완료. 다만 매출의 집계 범위는 하단 설명을 열어야 명확해진다, MKT-04.

### 과업 2, 먼저 조사할 변화 선정

- **업무 질문:** 어떤 집단과 운영 변화를 먼저 확인할 것인가?
- **실제 경로와 필터:** ROAS 상세의 캠페인, 기기 비교와 관련 운영 기록 18건 → 모바일 결제 오류 상세.
- **화면 근거:** 검색 01은 596.6%→302.9%, 페이스북은 550.6%→296.1%. 비용도 증가한 캠페인이므로 우선 조사 후보로 삼았다. 콘텐츠 협업 캠페인은 변화가 상대적으로 작다.
- **가능한 결론:** 예산 확대 캠페인의 효율과 모바일 구매 경로를 먼저 조사한다. 업무 차단 가능성이 있는 결제 문제는 별도 우선 확인한다.
- **불가능한 결론:** ROAS 하락폭이 가장 큰 캠페인이 손실 기여액도 가장 크다는 결론.
- **화면 밖 필요 정보:** 장애가 현재도 지속되는지 확인하려면 결제 운영팀의 현재 상태가 필요하다. 기록상 종료는 08-25다.
- **결과:** 완료. 우선순위는 전문가 판단이며 유일한 정답으로 제시하지 않는다.

### 과업 3, ROAS 분해

- **업무 질문:** 비용, 구매율, 객단가가 ROAS 변화와 어떻게 연결되는가?
- **실제 경로와 필터:** ROAS 상세 → 계산에 연결된 지표, 전체 범위 유지.
- **화면 근거:** CPC 531.9→596.3원, 클릭 기준 구매율 4.9%→4.2%, AOV 38,712.4→32,678원.
- **계산 확인:** 원시 합계로 계산하면 ROAS 비율은 0.6401929다. 구매율 비율 × AOV 비율 ÷ CPC 비율도 0.6401929로 같다. ROAS의 상대 감소는 약 36.0%, 화면의 -128%p는 절대 차이다.
- **가능한 결론:** 세 요인이 함께 ROAS 하락과 산술적으로 연결된다.
- **불가능한 결론:** 비용 증가를 CPC 상승과 별도의 독립 원인으로 중복 계산하거나, 이 분해를 인과 기여도로 해석하는 것.
- **화면 밖 필요 정보:** 정확한 곱셈 검산에는 공개 JSON과 별도 계산을 사용했다. 화면의 반올림 수치만으로 정밀 기여도 계산은 하지 않았다.
- **결과:** 조건부 완료. 방향 분해는 가능, 정확한 산술 검산은 화면 밖 계산 사용.

### 과업 4, 캠페인, 기기, 상품과 유입 집단으로 축소

- **업무 질문:** 구매 성과가 나빠진 범위는 어디인가?
- **실제 경로와 필터:** 상세 데이터 → 캠페인 성과, 퍼널, 상품 매출, 클릭 효율 → 기기 모바일/PC 전환 → 검색 01 캠페인 선택 → 타깃별 비교.
- **화면 근거:** 검색 01의 확장 타깃 클릭은 1,283→2,983, CPC는 380→267.6원. 기존 타깃 CPC는 543.8→1,054.1원. 상품별 주문과 단가는 볼 수 있다.
- **가능한 결론:** 집단별 유입 구성과 비용은 다르게 변했다. 확장 타깃이라는 이름만으로 고비용 유입이라고 부를 수 없다.
- **불가능한 결론:** 기본 표만으로 해당 타깃의 구매율과 ROAS를 연결하거나 SKU별 어느 퍼널 단계에서 이탈했는지 판단.
- **화면 밖 필요 정보:** 구매 지표가 포함된 공개 상세 행을 별도 집계하면 일부 연결 가능. UI에서는 같은 타깃의 성과표로 이어가지 못했다.
- **결과:** 조건부 완료, MKT-01. 캠페인과 기기 축소는 완료, 타깃과 상품의 구매 경로 연결은 미완료.

### 과업 5, 설명 후보 비교

- **업무 질문:** 집행 확대, 소재, 구매 과정, 결제, 재고, 계측 중 어느 후보가 관찰과 맞는가?
- **실제 경로와 필터:** S16 관련 운영 기록 → 예산 변경 상세, 모바일 결제 상세, 소재 v2 상세 → 상세 데이터의 퍼널과 결제 수단별 비교 → 캠페인 설정 보기.
- **화면 근거:** 검색 01 일예산 240,000→420,000원, 확장 타깃 포함 기록. 모바일 간편결제 714회 중 실패 73회, 10.2%. PC 카드 539회 중 실패 0회. 페이스북 v2 투입일은 08-24. 검색 01 현재 목표는 `targetRoas: 3.5`다. 운영 기록에서는 목표ROAS 350으로 제공된다.
- **가능한 결론:** 모바일 결제 문제는 별도 조사할 근거가 있다. 집행과 상품 구성, 소재도 병행 검토해야 한다.
- **불가능한 결론:** 결제 오류만으로 전체 하락을 설명하거나, 목표 350%를 이익분기점으로 간주하는 것. 재고의 오래된 정상 기록만으로 현재 정상도 단정할 수 없다.
- **화면 밖 필요 정보:** 장애 복구 확인, 변경의 인과효과와 추가 집행 여력. S16 원장 일치는 후속 API 합산에서 확인했으며, 정답 전 화면에서 원장 전체를 검산했다고 주장하지 않는다.
- **결과:** 조건부 완료. 후보 비교 가능, 원인 확정과 기여도 분리는 불가.

### 과업 6, 정상 집단과 다른 기간 대조

- **업무 질문:** 모바일만의 문제인가, 오류 이전과 이후에도 같은가?
- **실제 경로와 필터:** S16 결제 실패 → 모바일과 PC 전환, 직전 14일 비교. S07 개별 캠페인 비교. S15 테스트 케이스 → 보고 기준 09-07로 변경.
- **화면 근거:** S16 PC 실패 0, 모바일 실패 증가. S07 모든 개별 캠페인 ROAS 유지. S15 같은 분석기간의 ROAS 240%→400%, 후속 퍼널에 재방문 구매 제공.
- **가능한 결론:** 집단별 차이, 구성 변화, 후행 보고의 중요성을 확인할 수 있다.
- **불가능한 결론:** S16의 08-17~20, 08-21~24, 08-25~30을 같은 표에서 나눠 대조하거나, 소재 v2 투입 전후의 다른 조건을 통제한 효과 비교.
- **화면 밖 필요 정보:** 일별 상세 행의 수동 합산 또는 외부 분석. 09-07 값은 당시 화면의 실제 후속 자료로 읽었으며 08-31에 미리 알 수 있는 값으로 쓰지 않았다.
- **결과:** 조건부 완료, MKT-02, MKT-03. 다른 합리적 조사 경로로 재진입하고 필터를 바꾸는 것은 가능했다.

### 과업 7, 행동 선택

- **업무 질문:** 유지, 확대, 축소, 수정 요청, 추가 조사, 판단 보류 중 무엇을 선택할 것인가?
- **실제 경로와 필터:** 위 결과와 목표, 예산, 운영 기록을 대조했다. 액션 작성 UI는 현재 범위에 없으므로 화면 밖에서 판단했다.
- **가능한 행동:** S16은 결제팀에 복구 상태와 실패 범위 확인 요청, 예산 확대 집단과 소재별 추가 조사, 일괄 중단과 추가 확대는 보류. 종료된 장애 기록만 보고 현재 광고 중지를 지시하지 않는다.

### 과업 8, 근거와 불확실성 설명

- **업무 질문:** 다른 담당자가 재현할 수 있게 무엇을 전달할 것인가?

## 4. 근거를 갖춘 상세 발견

### MKT-01, 타깃과 소재의 구매 성과, 상품별 구매 과정을 이어서 조사할 수 없다

1. **ID와 제목:** MKT-01, 유입 집단에서 구매 결과로 이어지는 조사 경로 단절.
2. **심각도:** 높음. 비효율 집단을 식별하고 선택적으로 축소하는 핵심 판단을 막는다.
3. **근거 상태:** 확인. 화면 선택지와 코드로 확인했다. 실제 사용자 오판 발생은 추정이다.
4. **위치, 사례, 조회 범위와 재현:** S16, 전체 매체 → 검색 01 → 상세 데이터 → 클릭 효율 → 타깃별 비교. 이후 퍼널 또는 캠페인 성과를 선택한다. 타깃 구분이 사라지고 캠페인/기기만 남는다. 상품 매출을 선택하면 주문과 매출은 보이지만 상품별 세션과 퍼널 선택이 없다. S18의 소재별 클릭 효율도 구매 결과로 이어지지 않는다.
5. **기대와 실제:** 동일 타깃의 클릭, 구매율, 매출, ROAS를 연결하고, SKU별 구매 단계와 재고를 대조해야 한다. 실제로 타깃/소재/검색어는 유입 지표만, 구매 성과와 퍼널은 캠페인/기기만 제공한다.
6. **근거:** `frontend/workbench/training-dashboard.tsx:77`의 `allowedDimensions`, 같은 파일 83행의 지표 묶음, 134행의 전역 필터. 공개 `training-S16-initial.json`의 traffic 행에는 구매와 매출이 존재한다. 독립 합계에서 검색 01 현재 기존 타깃은 클릭 1,767, 주문 189, 확장 타깃은 클릭 2,983, 주문 79였다. 이 값은 후속 API 계산이며 화면 표에서 찾은 값이 아니다.
7. **막히는 업무와 오판:** 클릭이 싼 확장 타깃을 성과가 좋다고 간주하거나, 전체 구매율 하락을 모든 소재에 적용할 수 있다. 품절 SKU와 정상 SKU의 유입과 퍼널도 직접 대조하기 어렵다.
8. **최소 개선안:** 제공된 집계에서 의미가 검증된 조합에 한해 타깃, 소재별 구매 성과와 상품별 퍼널 보기를 허용한다. 선택한 집단을 유지해 다음 표로 이동시키고, 지원하지 않는 조합은 제한 이유를 명시한다. 무제한 교차 분석이나 신규 원본 수집은 필요하지 않다.
9. **수용 기준:** S16에서 검색 01의 기존/확장 타깃을 같은 범위의 클릭, 비용, 주문, 매출, ROAS로 대조한다. S18에서 품절 SKU와 정상 SKU의 유입/퍼널을 구분한다. 해당 조합의 합계와 의미를 검증한 뒤, 다른 조합을 중복 합산하지 않게 한다.
10. **다른 역할 확인:** 데이터 담당은 traffic/product 분할의 구매 귀속과 합계의 적합성을 확인해야 한다. 또한 S16 검색 01의 08-17 변경 기록은 ‘확장 타깃 포함’이라고 쓰지만 비교기간에도 확장 클릭 1,283이 있다. 신규 도입인지 추가 확대인지 의미 확인이 필요하며, 기록 축약일 수 있어 데이터 결함으로 확정하지 않았다. UX 담당은 표 전환 후 범위를 이해하는지 확인해야 한다. 현재 값이 있다는 사실만으로 모든 조합이 유효하다고 판단하지 않는다.

### MKT-02, 사건 전후를 나눠 비교하는 업무가 일별 원시 행의 수동 조사로 남는다

1. **ID와 제목:** MKT-02, 복합 사건의 날짜 범위를 표에서 분리하지 못함.
2. **심각도:** 보통. 일별 상세 행을 열어 수동 합산하는 우회는 있지만 조사 부담이 크다.
3. **근거 상태:** 확인. 고정 기간과 표의 집계 방식은 확인, 업무 부담과 오판 가능성은 전문가 추정이다.

5. **기대와 실제:** 오류 기간과 복구 뒤 기간의 같은 지표, 정상 기기/상품을 비교해야 한다. 실제 표는 직전 14일과 분석 14일로 묶이며 일별 지표 추이는 제한된 KPI 차트에서 제공된다. 일별 행은 집계 근거로 열 수 있으므로 날짜 데이터 자체가 없는 것은 아니다.

10. **다른 역할 확인:** 데이터 담당은 날짜가 광고 접점일인지 실제 사건 발생일인지 확인해야 한다. 접점일 귀속 구매를 오류 발생 시각과 그대로 맞추면 안 된다. UX 담당은 두 기간 길이와 범위를 혼동하지 않는지 확인해야 한다.

### MKT-03, 전환 지연 판단에 필수인 보고 기준시점이 주 화면에 없다

1. **ID와 제목:** MKT-03, 분석기간은 같아도 값이 달라지는 보고 기준시점의 노출 부족.

8. **최소 개선안:** 상단에 보고 기준시점을 표시하고 주 화면에서 변경할 수 있게 한다. 7일 귀속과 최근 구간의 반영 가능성을 간단히 연결한다. 미래 최종값이나 원인 정답은 미리 표시하지 않는다.
9. **수용 기준:** S15 두 시점에서 상단에 서로 다른 기준시점이 표시되고 분석기간은 동일함을 확인한다. 캡처만 받아도 보고 조건을 알 수 있어야 한다. 후속 기준 선택 전에는 120건이나 400%를 예상 확정값으로 노출하지 않는다.
10. **다른 역할 확인:** 데이터 담당은 귀속 기간과 수집 주기로 언제 성숙하다고 볼지 확인해야 한다. UX 담당은 처음 받은 마케터가 기능을 발견하고 원장 일치와 완결성을 구분하는지 검증해야 한다.

### MKT-04, 귀속 매출의 범위가 접힌 설명에 있어 사업 전체 성과로 읽힐 수 있다

1. **ID와 제목:** MKT-04, ‘매출’의 범위와 판단 한계가 주 지표에서 분리됨.
2. **심각도:** 보통. 상세 설명을 확인하는 우회가 가능하지만 규모와 수익성 판단에 영향을 준다.
3. **근거 상태:** 확인. 표현과 설명 위치는 확인, 실제 오해 여부는 전문가 추정이다.
4. **위치, 사례, 조회 범위와 재현:** S16/S17 → 성과 추이 또는 ROAS 상세의 매출과 기간 비교. 하단 집계 기준과 데이터 범위를 펼쳐야 7일 마지막 유료 클릭, 광고 접점일 귀속, 쇼핑몰 전체 매출과의 구분, 환불 제외를 읽을 수 있다.
5. **기대와 실제:** 규모 축소와 효율을 판단하는 곳에서 어떤 매출인지 즉시 알아야 한다. 실제 표와 ROAS 상세에는 ‘매출’, ‘매출/광고비’로만 표시된다. 한계 설명은 존재하므로 정의 부재로 평가하지 않는다. 화면이 순이익이라고 직접 주장한 사실도 없다.
6. **근거:** 브라우저의 S16 전체 성과 표와 S17 비교, 하단 집계 기준의 실제 문구. UI 21행의 revenue 라벨, 38행의 ROAS 설명, 133~136행의 상단 맥락, 147행의 하단 범위 안내. 공개 계약의 귀속 규칙과 일치한다.
7. **막히는 업무와 오판:** S17의 귀속 매출 감소를 쇼핑몰 전체 매출 감소로 전달하거나, 높은 ROAS를 순이익 개선으로 해석할 수 있다. 전체 매출, 비광고 매출과 이익을 판단할 정보는 없다.
8. **최소 개선안:** 매출 라벨을 ‘광고 귀속 매출’로 표시하고, 지표 옆에서 귀속 기간과 환불 제외 범위를 확인하게 한다. 순이익 지표를 새로 만들기보다 수익성 판단에는 별도 정보가 필요함을 짧게 밝힌다.
9. **수용 기준:** 주 성과 영역만 읽어도 귀속 매출과 전체 매출을 구별한다. S17 설명에서 이익 개선을 단정하지 않는다. 정의를 바꾸거나 기존 매출 값을 재계산하는 수정은 필요하지 않다.
10. **다른 역할 확인:** 데이터 담당은 원장 대사의 매출도 같은 귀속 범위인지 확인해야 한다. UX 담당은 실제 사용자의 범위 이해를 검증해야 한다. 원가와 환불 기능 자체는 현 교육 범위 밖이다.

## 5. 교육에서 가르칠 수 있는 것과 오해를 유발하는 것

| 가르칠 수 있는 것 | 경계해야 할 잘못된 학습 |
| --- | --- |
| ROAS와 매출, 주문 규모를 함께 본다 | ROAS 상승이면 사업 성장, 순이익 개선이라는 결론 |
| ROAS를 CPC, 구매율, AOV로 산술 분해한다 | 산술 분해를 독립 원인의 인과 기여액으로 해석 |
| 전체와 개별 캠페인의 방향이 다를 수 있다 | 전체 하락을 모든 캠페인의 성과 악화로 해석 |
| 계측과 원장을 대사한다 | 원장과 일치하면 전환도 충분히 반영됐다는 결론 |
| 후속 보고 기준시점과 재방문 구매를 확인한다 | 지연 사례의 회복을 실제 미래 성과의 보장으로 일반화 |
| 정상 PC와 장애 모바일을 대조한다 | 실패 시도 수를 영구 손실 고객/주문 수로 변환 |
| 변경과 장애 기록에서 후보를 찾는다 | 같은 날짜의 변경이 원인을 증명한다는 결론 |
| CTR과 콘텐츠 링크 클릭률의 분모를 구분한다 | 클릭 반응이 개선되면 구매 성과도 개선됐다는 결론 |
| 신규 고객 미집계와 CAC 계산 불가를 인정한다 | CPA나 주문 수를 CAC로 대체 |
| 판단 보류와 추가 조사를 결론으로 선택한다 | 사례마다 반드시 단일 원인과 즉시 액션을 내야 한다는 학습 |

설계 정답은 복합 사례에서 시간 일치와 생성자가 아는 인과를 학습자의 확정 원인으로 취급하지 말라고 명시한다. 이 제한은 타당하다. 다만 S10의 ‘확장 집단 평균 효율 저하’, S11의 ‘SKU별 퍼널’, S16의 ‘소재별 추이와 날짜별 분리’는 현재 기본 표의 지원 범위를 넘어선다. 정답의 조사 요구가 화면 기능보다 강한 부분이다. 해당 결론을 내리지 못한 학습자를 곧바로 오답 처리하면 안 된다.

‘정상 캠페인/개선 소재 유지’도 자동 정답이 아니다. 이번 관찰에서는 일부 소재의 클릭 반응 개선을 확인했지만, 해당 소재의 증분 구매 효과를 확인하지 못했다. 중단을 보류하고 더 조사하는 결론은 정당하지만 구매 성과 개선을 확정하는 결론은 정당하지 않다.

## 6. 반드시 필요한 개선과 사용자 실험 질문

### 필요한 최소 개선

1. **선택적으로 행동할 수 있게 구매 성과까지 연결:** 타깃/소재별 구매 결과와 상품별 퍼널을 지원 가능한 집계 범위에서 제공한다, MKT-01.
2. **복합 사건의 시간 범위 분리:** 제공된 날짜 안의 사건 전후 비교를 지원한다, MKT-02. 한 달 전 자료 확장이나 자동 원인 추론은 필요하지 않다.
3. **보고 조건의 상시 표시:** 기준시점을 주 화면에 표시하고 조작하게 한다, MKT-03.
4. **매출의 범위 표시:** 광고 귀속 매출과 전체 매출, 수익성의 차이를 해당 지표 근처에서 알게 한다, MKT-04.

목표와 예산 정보는 실제 존재한다. 다만 하단 설정, 변경 기록과 원시 필드에 분산돼 있고 목표 우선순위, 추가 집행 여력, 이익은 제공하지 않는다. 판단 보류를 허용하는 교육용 도구라면 이 경계를 명확히 하면 된다. 이익 데이터, 실행 승인, 광고 자동 집행, 보고서 저장/전송 부재를 각각 결함으로 추가하지 않았다.

### 변경 뒤 확인할 지표와 재평가 조건

- **결제 경로 수정:** 같은 기기/브라우저/수단의 실패율과 시도 수, 결제 완료율을 정상 집단과 대조하고 원장/계측 일치도 확인한다. 오류가 실제로 복구됐는지 먼저 확인한다.
- **타깃/예산 수정:** 같은 범위의 비용, 클릭, 주문, 귀속 매출, ROAS와 전체 매출 규모를 함께 본다. 비교할 수 있는 기간과 전환 반영 상태를 맞춘다.
- **품절 대응:** 판매 가능 상태와 광고 연결 상품의 일치, 해당 SKU 유입과 구매, 정상 SKU를 확인한다. 입고 뒤 수요 회복을 자동 가정하지 않는다.
- **계측 복구:** 누락과 중복, 원장/계측 차이와 재처리 상태를 점검한다. 대사 신뢰 회복 전에는 보고 ROAS만으로 예산을 바꾸지 않는다.
- **소재 변경:** CTR뿐 아니라 같은 소재의 구매율, 매출, ROAS와 랜딩 경험을 확인한다. 비교 기간의 타깃/지면 변화도 대조한다.

정량 임계값, 최소 표본과 관찰 기간은 목표, 정상 변동, 전환 지연과 실무 제약을 확인해 합의해야 한다. 실제 데이터 없이 성공률, 유의성이나 적정 관찰일을 만들어 제시하지 않는다. S15의 09-07은 사례의 제공 시점이며 모든 업무의 일률적 재평가일이 아니다.

### 실제 마케터 사용자 실험에서 확인할 질문

- 정답을 숨긴 S16에서 효율 하락과 매출 증가를 함께 설명하는가? 어떤 자료를 먼저 찾고, 무엇을 보류하는가?
- S07에서 전체 악화와 개별 성과 유지를 구분하고 비용 비중을 확인하는가?
- S14와 S15를 같은 문제로 취급하지 않는가? 원장 일치만으로 최근 성과를 확정하지 않는가?
- 보고 기준시점을 도움 없이 발견하고, 분석기간과 다른 조건임을 이해하는가?
- S18에서 품절, 모바일 로딩, 상품 구성, 소재 변화를 비교하고 정상 SKU와 PC를 보존하는가?
- 같은 타깃의 클릭과 구매 지표를 연결할 수 있는가? 다른 표로 이동한 뒤에도 범위를 정확히 말하는가?
- 목표 ROAS와 이익분기 ROAS, 광고 귀속 매출과 쇼핑몰 전체 매출을 구별하는가?
- 근거가 부족할 때 판단 보류와 추가 조사 항목을 설명하고, 다음 재평가 조건을 정하는가?
- 인수받은 다른 마케터가 기간, 보고 기준시점, 범위, 기록 ID와 불확실성을 재현할 수 있는가?

이 질문들은 검증 계획이며 실행 결과가 아니다. 학습자의 결론이 설계 정답과 다르더라도 화면 근거, 대안 가설, 판단 조건이 타당하면 별도로 평가해야 한다.

### 실행과 보존 범위

애플리케이션, 데이터 원본, 스키마와 생성 규칙을 수정하지 않았다. 자동 테스트는 실행하지 않았으며 기존 통과 기록을 실무 적합성 근거로 대체하지 않았다. 새로 만든 것은 이 평가서와 계산 근거뿐이다. 커밋, 배포와 외부 전송은 수행하지 않았다.
