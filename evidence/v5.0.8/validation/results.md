### 변경 전후와 시행착오

- 수정 전 소스로 리뷰 렌더 검사를 실행하면 중립 증감 표식 기대 5개에 실제 0개로 실패한다. [실패 원문](review-before.txt). 수정 후 같은 입력의 S16/S17 검사가 통과했다.
- 첫 전체 회귀에서는 기존의 '차트 이벤트 마커 없음' 계약 검사 1건만 실패했다. 이번 요청은 해당 표시 계약을 바꾸므로 검사를 기존 원천 9건의 날짜, 기기, 캠페인, 보고 시점과 보존 검증으로 교체했다.
- 브라우저 검사 초안은 날짜 정규식의 슬래시와 숨겨진 상세 텍스트 중복 선택 때문에 실패했다. 날짜 문자열과 대화상자의 summary로 선택자를 구체화했다. 앱 결함으로 집계하지 않는다.
- 모바일 캡처에서 공통 버튼의 줄바꿈 금지 스타일이 이벤트 제목을 잘랐다. 이벤트 버튼에 줄바꿈을 허용하고 제목 잘림 검사를 추가했다.
- 768→1024px 변경 직후의 가로 넘침 검사는 Recharts 크기 재계산 전 값을 읽어 실패했다. 별도 1024px 진입 화면은 정상임을 확인했으며, 경계 크기 검사는 레이아웃 갱신을 기다리는 재시도 assertion으로 수정했다.

## 실제 화면과 독립 검산

- 매출: 37,280,000원 → 48,200,000원, +29.3%. 집행비: 10,478,096원 → 16,929,052원, +61.6%. 두 기간 원천 facts를 독립 합산해 화면과 일치함을 확인했다.
- CPC +12.1%에 '악화'를 병기한다. 집행비 증가에는 개선/악화를 부여하지 않는다.
- S16 운영 9건을 8/17, 8/21, 8/24의 3개 날짜에 연결한다. 8/17 예산/타깃 변경과 할인 종료는 기존 표시 묶음을 재사용한다.
- 8/21 원문에서 `PAYMENT_CALLBACK_TIMEOUT`, 모바일, 8/25 종료 시각을 확인하고 닫기 후 현황으로 복귀했다.
- 배송 언급 +4.7%p를 포함한 기간 비교 5건을 중립색으로 표시한다. 언급 증감의 비인과적 의미를 설명한다.
- 캠페인 선택 시 매출/집행비가 선택 facts 합계로 갱신된다. 전체 18개 사례의 이벤트 날짜/보고 시점/매체 필터는 회귀에서 확인했다.
- 공유 Cloud Chrome에서 성과 현황, 이벤트 원문, 리뷰 화면을 직접 조작했다. 별도 headless Chromium으로 같은 흐름과 모바일 키보드 활성화를 검사했다.
- 1440×1000 데스크톱, 390×844 모바일 캡처를 육안 확인했다. 390/768/1024px 화면 가로 넘침과 모바일 이벤트 제목 잘림을 자동 검사했다.
