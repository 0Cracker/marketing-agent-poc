## 4. 통합할 때 유지할 데이터 의미

- D008 현재 비교 표본: 한국 6,825행 / 일본 8,987행 / 미국 14,582행. 리뷰는 560 / 730 / 1,120개, 제품별 별점·표본·광고 형식 비율이 다르다. 이 값은 이전 생성 결과이며 새로운 변경 없이 유지할 수용 기준이다.
- 가상 여부·출처·수집 범위·관측일·조회 가능 시각·통화·단위·분모·결측을 유지한다. 리뷰 구매 확인 null을 임의 true/false로 채우지 않는다.
- 리뷰 주석 4,820행은 실제 문장 발췌에 연결한 규칙 기반 가상 주석이다. 사람 검토·LLM 감성 분석으로 표시하지 않는다.
- 추가 주문은 주문·환불·배송·코호트·CRM 연결을 함께 늘렸다. 참조와 금액 관계를 끊지 않는다.
- 다른 국가 통화, 시장 분모, 정규화 범위가 다른 검색 관심지수, 월간/일간 중복 보고를 합치지 않는다.
- 사용자 흐름 이벤트와 구매 표본의 수집 범위가 달라 수량만으로 구매 전환율·이탈률을 만들지 않는다.
- 관측 사이를 실제 재고/장애 상태로 채우거나 장애 기록으로 가동률을 만들지 않는다.
- 같은 지표라도 모의 시장 자료와 주문 자료가 서로 다른 수집 범위면 강제로 일치시키지 않는다. 원천에 없는 승인·예측 정확도·실제 집행 이력을 생성하지 않는다.

## 5. 목표 폴더 구조 — 다음 구현안

사용자 확정 사항은 data/ 통합과 배치 중심 분할 제거다. 아래 세부 파일명은 구현 권장안이며 아직 생성하지 않았다. **업무 데이터는 data/ 바로 아래 의미 있는 유형별 파일로 둔다.** 국가·월·배치마다 폴더를 늘리지 않는다. 기존 data/db와 data/drizzle은 확인된 템플릿이므로 덮어쓰지 않는다.

예시 구조:

    data/
      README.md                 데이터 의미·추가/교체·검증 방법
      manifest.json             활성 파일 목록·계약/스키마 버전·해시·집계 정책
      products.jsonl            제품·브랜드 정의
      market-sales.jsonl        시장 판매 관측
      reviews.jsonl             리뷰
      review-annotations.jsonl  문장 발췌 주석
      customer-inquiries.jsonl  고객 문의
      public-ads.jsonl           공개 광고
      prices.jsonl              판매처 가격 관측
      inventory.jsonl           재고 관측
      ...                       나머지도 실제 유형 의미에 맞는 파일 1개씩
      provenance.jsonl          활성 레코드 ↔ 원본 경로/ID/해시/변환 규칙 매핑
      migration-map.jsonl       유지·대체·동등·미적합·보류 판정과 이유
      archive/                  기존 원문·검증 문제·해시 목록, KPI에서 제외
      db/                       기존 템플릿 보존
      drizzle/                  기존 템플릿 보존

위 예시는 명칭만 제시한 것이며 레코드나 수치를 생성한 것이 아니다. T01–T40/H01의 모든 유형에 빠짐없이 실제 파일 매핑 표를 작성한다. 원천 코드 Txx는 내부 검증 메타데이터로 유지할 수 있지만 화면 제목이나 사용자가 고르는 데이터 버전으로 노출하지 않는다.

새 데이터가 들어오면 같은 업무 파일을 검증 후 교체/추가하고 manifest와 변경 기록을 갱신한다. 데이터·스키마·화면 계약 버전은 manifest 메타데이터로 관리한다. 실행 경로를 버전 폴더마다 추가하지 않는다. DB·대규모 파이프라인·범용 온톨로지 프레임워크 도입은 이번 통합의 필수 조건이 아니다.

## 6. 통폐합 규칙: 파일 이동만 하거나 단순 연결하지 말 것

1. 실제 입력 파일을 전수 목록화한다. 원래 저장소와 public 조회본, 고정 D003B, 기존 TS 데모 자료를 구분한다. 동일 내용의 복사본은 물리적 복사 관계로 기록하며 새 관측으로 세지 않는다. 현재 이관의 중심은 /workbench다. 다른 페이지의 demo-scenarios.ts/marketing.ts는 사용처를 조사하고 무관한 레거시 시연을 임의 제거하지 않는다.
2. 원본 파일 해시와 레코드별 출처를 보존한다. D008 생성기의 원형 재사용/새 표본/식별자 치환 규칙을 읽어 이전 자료와의 대응을 복원한다. 새 통합 ID가 꼭 필요한지 먼저 판단하고, 유지할 수 있는 기존 ID는 유지한다.
3. 유형별 업무 식별키를 정의한다. 국가·제품·대상 시각/기간·기기/채널·지표 정의·수집 범위 등을 포함한다. 같은 업무 키라도 다른 시나리오/표본이면 자동 중복으로 삭제하지 않는다. 동일 ID만 비교하는 중복 제거는 부족하다.
4. 현재 비교 표본은 D008을 우선 후보로 사용하되 D008이 보유하지 않는 유효 제품 정의·독립 검증/업무 자료도 조사한다. 모든 D007을 덮어쓰거나 모든 과거 배치를 무조건 활성화하지 않는다. 레코드별 유지/대체/동등 복사/독립 자료/미적합/판정 보류와 근거를 남긴다.
5. 자동 확정할 근거가 없는 충돌은 미해결 목록에 남긴다. 해당 자료를 조용히 버리거나 기존 KPI에 섞지 않는다. 독립적이고 적합한 다른 유형의 통합은 계속한다. 통합 활성 행수는 전수 판정 후 확정한다. 현재 단계에서 30,394 또는 52,636으로 고정하지 않는다.
6. 제품·광고·문의·주문·리뷰·주석·모형의 참조 ID를 끝까지 검사한다. 바꾸는 ID는 모든 참조·정의·Agent 근거 조회·저장된 실행 문맥에 반영한다. 예전 실행은 호환 조회 또는 명시적 만료로 처리하고 새 데이터로 옛 결과를 가장하지 않는다.
7. 명세 미적합 790행은 원문·진단을 archive에 남기고 활성 분석에서 제외한다. 새 수치로 보완하지 않는다. 최종 입력 수량을 활성/대체/동등 복사/미적합/보류 등 상호 배타적인 판정으로 대사한다. 보존 총량과 활성 분석 총량을 별도 보고한다.
8. 검증된 통합본을 먼저 복사 생성하고 조회 전환·회귀 검증을 끝낸다. 기존 public/원래 저장소의 원본을 먼저 이동·삭제하지 않는다. 전환 후 런타임의 옛 경로 의존성을 제거하되 역사 문서·고정 회귀 근거는 보존한다. 중복 배포 파일 정리는 추적 가능한 보존본을 확인한 뒤 수행한다.

2–3은 신규 마케팅 수치 생성 작업이 아니다. 재배치·기존 자료 재사용/변환 범위를 실제 매핑과 함께 기록한다. 통합 중 새로운 표본이나 내용을 추가해야 하는 경우 그 범위는 기존 다양화 승인과 별도로 판단한다. 승인된 작업에 대해 형식적인 재확인을 반복하지 않는다.

Agent는 sibling marketing-agent-poc의 scripts/agent-server.mjs와 해당 저장소 AGENTS.md/검증 계약을 확인해야 한다. 이번 문서 작성은 sibling 수정이나 통합 API 완료를 뜻하지 않는다. 두 저장소의 담당 변경이 충돌하면 근거를 보고하고 영향을 받지 않는 파일 정리·검증을 계속한다.

## 8. 유지할 화면과 남은 문제

현재 기본 7도메인, 예산·실험/기준·품질은 데이터·검증 도구 아래다. 기존 명세의 9도메인 기본 노출은 사용자의 최신 축소 피드백으로 변경됐으며 원문은 보존했다. 밝은 화면·SUIT 글꼴·보라 중심 색상·필요할 때 여는 우측 Agent 패널을 유지한다. 이번 데이터 통합을 임의 전면 디자인 개편으로 확대하지 않는다.

완료된 화면 수정: 처리 상태 고정 순서, 전체 기간 리뷰/검색/문의/조사 복구, 국가별 비교, 상품 행동별 수량/일별 추이, 가격 추이·범위, 재고 추이·품절 달력, 사이트 사건 발생일·지속시간 달력, 예산 후보 비교 표. ‘구매 패널’은 구매 경험 조사, 경쟁 활동은 공개 광고·발행 관측, 외부 요인은 보조 맥락으로 설명한다.

남은 확인 사항:

- **Agent 공통 자료 연결 미완료:** 현재 D007만 지원. 데이터 통합의 최우선 후속 사항이다.
- **린트:** agent-conversation.tsx effect에서 동기 setState/reconnect 관련 오류 1개·의존성 경고 2개를 마지막 확인했다. 현재 상태를 재검사하고 단순 경고 숨김/규칙 해제로 처리하지 않는다.
- **로딩·번들:** 전체 카탈로그를 한 번에 읽는 현재 구조, 500KB 초과 번들 경고가 남는다. 통합 후 같은 데이터를 여러 번 번들/다운로드하지 않도록 하고 실제 로드 비용을 측정한다. 성능 개선을 이유로 일부 유형을 빠뜨리지 않는다.
- **보조 도구 국가 비교:** 예산·일부 기준 유형은 국가 비교가 아직 표본 수 중심의 보조 요약이다. PoC 기본 화면 밖이라는 현재 범위를 유지하고, 유의미한 비교가 불가능하면 조건·모형을 선택하게 하거나 분석 불가 이유를 표시한다. 의미 없는 표본 수를 성과로 포장하지 않는다.
- **데이터 언어:** 일본/미국 가상 리뷰에도 한국어 본문과 ko가 있다. 현지어 데이터 생성 완료로 설명하지 않는다. 번역/언어 재생성은 이번 통합에 자동 포함하지 않는다.
- 이전 검증은 당시 미커밋 트리에 대한 결과다. 통합 뒤 수치·브라우저·Agent를 새로 검증해야 한다. 사용자 최종 수용이나 배포 완료는 확인하지 않았다.

## 9. 검증 계획

기존 명령은 회귀 근거로 유지하되, 통합 경로에 맞는 새 검증을 추가한다. 기존 검사를 삭제하거나 기대 수치를 조용히 갱신해 통과시키지 않는다.

- node scripts/check-marketing-redesign.mjs — 이전 323조회, 국가/제품 분포·통화·금액·코호트 대사.
- node scripts/check-screen-contract.mjs — D003B 보존 모델 496조회.
- node scripts/check-standard-query.mjs — 기존 D007 123조회.
- node scripts/check-all-connected.mjs — 기존 22,242행·91파일·41유형 전수 접근/원본 대조.
- node --experimental-strip-types tests/agent-client.test.ts — 기존 7시험. 신규 통합 자료·옛 실행 복원·범위 변화 시험을 추가.
- node node_modules/typescript/bin/tsc --noEmit
- node node_modules/eslint/bin/eslint.js frontend/workbench
- node node_modules/vite/bin/vite.js build

node는 사용 가능했고 npm/npx는 세션 PATH에 없어 직접 node_modules 엔트리로 실행했다. 다음 환경에서 명령 가용성을 재확인한다.

통합 수용 조건:

- data/의 manifest가 현재 자료의 유일한 관리 진입점이고 프론트·Agent가 같은 계약/해시를 읽는다. public 결과가 필요하면 data/에서 빌드로 파생하며 수동 두 벌 관리를 없앤다. Vite가 루트 data/를 어떤 방식으로 읽고 배포할지는 구현 시 명시한다. 실제 비공개 자료를 public으로 무조건 복사하지 않는다.
- 사용자 데이터 선택에서 D007/D008을 고르지 않아도 모든 업무 유형을 조회한다. 국가·제품·기간·채널 등 업무 필터를 유지한다. 출처 버전은 필요할 때 근거/관리 도구에서 확인한다.
- 활성 자료 중복 0, 끊긴 참조 0, 원문 발췌 불일치 0, 주문행·환불·코호트 산식 통과. 결측값·통화·분모·시각 의미 유지.
- 기존 자료의 행마다 활성/대체/보존/미적합/보류를 추적할 수 있다. 과거 자료를 삭제하거나 집계 손실을 숨기지 않는다.
- 3국가·국가 비교 × 특정월·전체 기간 × 기본 34화면, 390px 및 약1125px에서 빈 화면·레이블 겹침·잘림·페이지 가로 넘침을 확인한다. 긴 표/달력은 카드 내부 스크롤을 허용한다.
- 차트/지표 클릭으로 실제 통합 원천 근거가 열리고 CSV와 화면 합계가 일치한다.
- Agent는 같은 국가·제품·기간·asOf에서 화면과 근거를 대사한다. 서버 중단·재시작·복원·응답 유실·후속 분석의 승인 무효화를 확인한다. 외부 LLM/실제 Ads 집행을 새 완료 조건으로 추가하지 않는다.
