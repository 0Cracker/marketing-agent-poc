# 002 — 두 역할의 B 흐름과 오프라인 TDD 실행 기반

날짜: 2026-10-18. 관련 사이클: 기존 v0.2.0. 상태: **B 흐름은 사용자 채택, Node 실행 기반은 구현 판단**. 시작 HEAD: `d0f6267`. 미커밋 작업이다.

분석·예산 두 역할을 자유 탐색으로 연결하되 자료·의미·수치·근거·승인은 코드로 통제한다. 성공뿐 아니라 단계별 보류·실패·수정·재시작을 테스트 먼저 작성해 검증한다. 기존 가상 데이터만 재사용하고 실제 LLM·Ads·원천 변경을 완료 조건으로 추가하지 않는다.

| 기반 | 장점 | 비용/판단 |
| --- | --- | --- |
| Python LangGraph | 단계·중단·재개 기능과 기존 Python 자산 | 현재 일반 공통 조회는 Node 카탈로그에 있음. 첫 사이클에 런타임/의존성/연결 계층이 추가됨 |
| Python ADK | Python 도구·모델 실행 기반 | 승인 영속성·API 조합 검증과 Node 조회 연결이 필요 |
| 기존 Node + 표준 라이브러리 | 공통 카탈로그 직접 재사용, 패키지 추가 없이 SQLite·테스트 사용 | 제한된 루프·상태 전이를 직접 소유. 초기 로컬 단일 프로세스 범위 |

Node 표준 라이브러리로 고정 관문과 역할별 제한된 루프를 구현한다. 모델은 교체 가능한 함수이며 Gemini/Groq JSON 행동 연결부와 명시적인 오프라인 모델 대역을 제공한다. 모델 대역을 실제 LLM의 이해 능력이나 성능으로 표시하지 않는다. 기존 비교 보고서의 Python 우선 후보를 자동 확정으로 취급하지 않는다.

ORM·별도 그래프 DB·메시지 버스·분산 워커는 도입하지 않는다. SQLite에 분석/제안/승인/실행 의도와 버전을 저장하며 승인·제출 경합은 CAS로 차단한다. 외부 반영의 정확히 한 번 실행은 보장하지 않는다. 응답 유실은 불명 상태로 두고 대사한다.

[설계·결과](../design/agent-tdd-20261018.md), [상세 시험](../design/agent-test-cases-20261018.md), [98시험·기존 회귀·입력 보존](../../evidence/v0.2.0/agents-tdd/result-2.json)을 확인했다. 실제 모델 품질·UI·Ads는 미검증이다. 모델별 대화 처리·병렬 도구·분산 재개 요구가 커져 이 루프의 유지 비용이 하네스 도입보다 커질 때 재검토한다. 업무 도구·검증 규칙은 그대로 유지한다.

새 발행 버전·태그·커밋은 생성하지 않았다. [Iteration](../iterations/v0.2.0.md)에 이번 근거를 연결한다.
