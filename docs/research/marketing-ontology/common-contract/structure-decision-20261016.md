# D005와 공통 사전의 역할 — 2026-10-16 결정

**목표 구조는 공통 사전 중심이 적합하다. D005는 원천 어댑터와 회귀 시험 자료로 보존한다.**

최신 범위 확정: 사용자 “실제 데이터랑 연결할 필요는 없어. 그렇게까지 안할거야.”에 따라 실제 데이터 연결·공급자 파일럿·실제 자료 적합성 검증은 **프로젝트 범위 밖**이다. 이전 ⑥A의 파일럿 후속 계획을 철회하며 미완료 과제나 완료 조건으로 집계하지 않는다. 기존 보고서의 실제 공급자 `not_run`은 실행 이력으로 보존하고, 현재 상태에서는 범위 밖으로 해석한다. 가상 데이터의 공통 사전 미충족과 업무 의미 검토는 계속 해결한다.

후속 사용자 응답 “현재구조로가고 d005 문서 수정하는걸로가자”로 이 방향을 확정했다. [D005 안내](../batches/D005/README.md)와 [승인 문서의 D005 절](../data-proposal.md#d005-200--30종-신규-자료-생성규격-검증-상세-제안)에 내부 규격/전역 계약 구분을 반영했다. 문서 수정으로 미충족 필드나 검증 상태가 해소된 것으로 처리하지 않는다.

| 비교 | D005 원천 규격 | 공통 사전 중심 구조 |
| --- | --- | --- |
| 목적 | 승인한 가상 상황을 반복 검증 | 서로 다른 자료를 같은 업무 의미로 해석 |
| 장점 | 작고 명확하며 기존 검산·오류 검사가 있음 | 출처·시각·단위·표본·분류 기준을 함께 표현 |

흐름은 **D005 등 원천 → 명시적 변환 → 공통 사전 검증 → 질문별 조회·정책·독립 검산**이다. 둘 중 하나를 버리거나 D005에 맞춰 사전의 필수 조건을 없애지 않는다.

## OOPS 전송 보류

로컬 HermiT는 [수정 정의 검사](runs/2026-10-16-logic-decisions-1.json)에서 통과했다. OOPS 접속은 제한 환경에서 DNS 실패로 미실행이었다. 이후 네트워크 권한 요청은 자동 승인 심사에서 “⑤A만으로는 특정 payload와 외부 destination 전송 승인이 명시적이지 않다”는 사유로 거절됐다. 우회 전송하지 않았다.

재검사 대상은 `ontology.ttl`의 정의 그래프만 RDF/XML로 직렬화한 내용이며, 목적지는 `https://oops.linkeddata.es/rest`다. 원본 TTL SHA-256은 `32dfb7402d49047b48841f021771ad51ef02c0d2a3367111a5ee24b135891316`이다. JSONL·리뷰 원문·인스턴스 RDF·공급자 자료는 제외한다. 전송 시 모델 정의가 외부 서비스에 공개된다는 점에 대한 명시 승인이 필요하다. [차단 기록](oops-approval-20261016.json)을 따른다.

PROV 용어 선언은 [W3C PROV-O](https://www.w3.org/TR/prov-o/)의 Entity·Activity·wasGeneratedBy·wasDerivedFrom 정의를 따른다. 설명 추가는 추론 조건을 바꾸지 않는다. domain/range·역관계와 `supersedes`의 대칭성·추이성을 검사 점수만을 위해 일괄 추가하지 않았다. OOPS 재실행 전까지 기존 지적의 해소를 완료로 표시하지 않는다.
