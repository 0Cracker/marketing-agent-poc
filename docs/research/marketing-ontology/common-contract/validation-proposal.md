# D004-SPEC 메모리 투영 검증 제안 — 두 단계 승인·실행

2026-10-15 현재 상태: 제안1.1.0의 기존214행/전체1,652행 메모리 검사는 [후속 승인](../data-proposal.md#승인-기록)으로 승인·실행되었다. 아래 승인 대기 문장은 당시 이력이다. 동일 범위의 RDF 재조회·계산·재실행 보강은 기존 승인을 유지한다. 신규 자료는 [D005 제안](../data-proposal.md#d005--1순위-격리-가상-배치-제안-승인-대기)을 별도로 따른다.

## 2026-10-15 범위 수정 (제안 1.1.0)

사용자 확정 계획에 맞춰 아래 1.0.0 제안의 **별도 D004 폴더에 변환 결과 저장** 문구를 폐기한다. RDF 개체는 실행 중 메모리에만 투영하고, 원천 레코드·RDF payload를 포함하지 않는 계수·검사 결과 보고서만 저장한다. 원본 수정·DB 적재·새 원천·오류 주입은 각각 0건이다. 이 수정도 실행 승인이 아니다.

승인 대상은 두 단계다. 먼저 아래에 고정된 ID **214행→예상547관측**을 검사하고, 통과하면 같은 D003B 원천의 **전체1,652행→예상4,105관측**으로 확장한다. 전체 행수는 T01 6, T03 432, T12 6, T13 312, H01 144, T08 504, T22 168, T24 72, T09 1, T35 1, T36 6이다. 전체 관측은 T03 제품864+동일 국가월 분모 중복 제거72, H01 864, T13 1,560, T08 504, T22 168, T24 별점72, T09 할인1로 계산했다. 앞 단계 실패, manifest의 파일별 SHA-256·정확 행수 불일치, 예상 관측 수 불일치 시 중단한다.

두 단계에서 원천 ID·필드 경로·정확값·단위/통화·기간/시장·결측 상태·원천 파일/행 계보를 대조한다. 변환기와 별도 코드 경로로 Decimal/정수·결측·중복 분모 ledger를 계산해 검산한다. SHACL·참조 무결성과 두 대표 과제 계산, 재실행·입력 순서·기준일 검사를 수행한다. 결과에는 단계별 행/관측/노드/관계 수, pass/fail/not_run, 입력·모델·매핑·도구 버전과 해시, 종료 코드, 실패 재현 정보를 남긴다. 원천 값·리뷰 원문·RDF 개체 payload는 보고서에 기록하지 않는다. 실제 공급자 샘플 적합성, 새 반대 근거/오류 자료, AI 판단과 52시험 전체 실행은 이 범위 밖이다.

아래 1.0.0의 214행 대상 ID와 변환·계산 규칙은 이 수정에 반하지 않는 한 유지한다. 저장 방식과 전체 확장 범위는 이 수정이 우선한다.

2026-10-14 / 제안1.0.0. **이 문서는 실행 승인이 아니다.** 사용자 요청과 [AGENTS.md](../../../../AGENTS.md)의 “가상 데이터 생성·수정·재사용·변환·보완은 … 사용자 명시 승인 후 수행한다”에 따라 아래 범위를 검토한 뒤 별도로 승인받는다. DB/LLM/Git 발행은 이 제안에도 포함하지 않는다.

## 목적·입력·대상

목적은 국가/기간/지표 의미·원천 계보를 보존하는 변환과 두 대표 과제의 저장소 독립 계산 검증이다. **기존 D003B JSONL 중214행 재사용·변환**, 새 원천0행, 오류 주입0행, 원천 덮어쓰기0건, DB 적재0건. 검색/소셜은 모의 원천 프로필이며 실제 Google/Meta 응답으로 꾸미지 않는다. 실제 API 보고 계약 적합성은 별도 미검증이다.

기준 D003B-1.0.0, seed 300320261014, [manifest](../batches/D003B/manifest.json)의 원천 11종 SHA-256를 사용한다. 이번에 원본 보존 확인을 위한 바이트 해시만 읽었으며, 행 파싱·선택·복제·변환은 하지 않았다. 아래 ID는 generate.mjs의 루프/record_id 규칙을 **코드로 읽어 계산한 선택 명세**다. 승인 후 ID 존재·대상·정확 건수·hash가 불일치하면 즉시 중단하고 보완 승인 없이 선택을 늘리거나 대체하지 않는다. ## 승인 후 변환 규칙·정확한 출력 계수 계획

1. 확정 namespace와 원천ID만으로 제품/브랜드/캠페인/판매처/위치 참조를 파생한다. T01 상충 이름/규격은 격리한다. 원천은 immutable, 변환 결과는 별도 `D004` 폴더를 승인 후 생성한다.
2. 수치 필드별 Observation을 만든다. T03 36×2=72 제품 관측 +6개 국가월 분모관측=78(반복 필드36개 모두계보), H01 6×6=36, T13 68×5=340, T08 56, T22 28, T24 별점8, T09 할인1 → **547관측 제안**. T35 before/after는 사건 속성으로 보존하고 새로운 과거재고 관측으로 만들지 않는다.
3. T13 소셜2결측행→10개의 missing 관측(no value+reason), 나머지537 관측은 present 예상이다. 상세실제수신54행·정규화56행을 분리한다. 이 예상도 승인 후 기존 입력을 읽어 검증한다.
4. 원천행214·관측547을 그래프 총노드수로 부르지 않는다. Product/Brand/Campaign/Seller/Location/Scope/SourceRecord/Artifact/Interval/Instant/Event/Review/Transformation별 수와 관계수는 변환 후 별도 계수한다. 관리 metadata를 원천 추가행으로 더하지 않는다.
5. 금액2자리 lexical 보존·정확 decimal 사용, JPY .00 검증; money 최소단위오차0. 원래 null을0/false로 대체하지 않는다. T08 가격 존재와 availability=unknown은 별개다.
6. 현지 date [start,end), IANA·원래offset, measurement/observed/written/changed/available 시간을 분리한다. Q3 계산은 월baseline만; 상세창 계산은 day/detail만. 월/일 중복 금지. 정정정보 없는 D003B는 원천 변경판이 없다는 프로필을 명시하고 initial revision0 metadata만 사용한다.
7. source artifact/hash→record_id→fieldPath→mappingVersion/codeVersion→계산입력까지 계보 유지. source_record 구조 자체는 원본행/필드null marker를 보존하며 공개 claims와 계산은 분리한다.
8. T09 조건과 T35 이유는 원천 Claim. 리뷰 원문을 그대로 표현하되 새 감성/측면라벨·EvidenceSpan·Hypothesis 생성은 이214행 기본변환 승인 범위에 포함하지 않는다. 발췌/해석 검증은 별도규칙/건수 승인을 요구한다.

## 남은 승인 항목

검토할 구체적 범위는 **D004-SPEC의 기존 214행 재사용·별도 547관측 변환·두 대표 과제 계산·원본 불변·오류 주입 0·DB 적재 0**이다. 승인 전 원천 행 파싱/선택/복사·변환·분석 결과 생성/적재·원문 추출·오류 fixture를 실행하지 않는다. 외부 원천 계약은 필수 미확정 정보를 확보한 뒤 별도 샘플을 제안한다.
