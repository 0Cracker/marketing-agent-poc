## 실행 인터페이스와 판정

`run-question-cycle.py --inventory`는 tests.json·두 manifest만 읽어 대조표와 정확한 실행 범위를 갱신한다. 원천 행은 읽지 않는다. `--self-check`는 52 ID 전수 대응, 조회/oracle 연결 일치, 승인 누락, pass/fail/not_run 집계·지원 밖 요청·보류/실질지원 분리 등 15개 프로토콜 검사를 수행한다. 마케팅 레코드나 오류 fixture는 만들지 않는다.

개별 승인 후 실행기는 D004 실제 메모리 RDF의 Observation을 읽는다. 비관측 필드는 SourceRecord.sourceContext에 null/부재를 보존해 메모리로만 표현하고 다시 읽는다. sourceContext는 수치 Observation을 대체하지 않는다. 기존 변환기의 기본 호출/기존 RDF hash는 유지하며 질문용 호출만 일시 그래프를 전달받는다. 모든 필드의 재조회 결과를 원천과 대조한다.

질문 구현과 독립 원천 oracle는 계산/조회 함수를 공유하지 않는다. oracle는 별도로 manifest·원천 바이트를 확인하고 Decimal로 계산한다. 각 결과는 답변 상태, 값/명시적 null·이유, 사실별 file/hash/record/field/asOf/버전 근거, 완전성, 지지 범위를 반환한다. 정책 태그는 설명용이며 시험 통과 판정은 독립 값/상태·필수 출력·근거·완전성 assertion과 재실행 결과로 결정한다. exact 원문 span이 필요한 시험은 승인된 span 입력이 없으므로 미실행으로 남긴다.

전체시험 pass는 모든 필수 assertion이 통과했을 때만 가능하다. 보류 성공은 guard_passes로 집계하고 substantive_answers와 분리한다. 미구현/입력 부족을 execution_failed 답변으로 위장하지 않는다. 원천 조건 부족은 not_run, 실행한 조회/검산 오류는 fail이다. 종료0=전체시험 통과, 1=실패, 2=필수 미실행/불완전이며 시스템 전체 완료는 별도다.

통합 실행기는 `run-system-cycle.py`다. 기존 승인 범위의 D004 두 단계·독립 계산을 새로 실행하고 D005 `validate`로 정상534행/오류60케이스·RDF 재조회·경계/재실행을 새로 검사한다. D005 과거 D004 결과 재사용 옵션은 쓰지 않는다. 같은 사이클에 HermiT와 52시험 결과를 기록하며, 승인 없는 질문 실행은 원천을 파싱하지 않고 not_run52 보고서를 남긴다. 입력·코드 hash와 Git HEAD/refs/index를 전후 대조하고 이전 보고서는 덮어쓰지 않는다.

## 실제 논리 검사와 수정

HermiT는 검증 전용 폴더의 portable Temurin JRE17과 Owlready2 0.51 배포에 포함된 HermiT1.3.8.1099를 사용한다. 프로젝트/전역 의존성·PATH를 변경하지 않았다. 공식 배포 체크섬을 확인했으며 이 배포가 수정판이라는 점을 보고서에 명시한다.

첫 시도는 Windows sandbox TEMP 접근 거부로 미실행이었다. 임시 정의 파일을 쓰기 가능한 runs 아래에 한정한 뒤 실행하자 xsd:date range가 HermiT에서 거부됐다. xsd:date는 [OWL 2 datatype map](https://www.w3.org/TR/owl2-syntax/#Datatype_Maps)에 포함되지 않는다. startDate/endDateExclusive의 OWL range는 rdfs:Literal로 바꾸고 **SHACL의 xsd:date·lessThan 검사와 원천 날짜/시간대·반개방 구간 계약은 유지**했다. 지원되지 않는 datatype을 무시하는 옵션은 쓰지 않았다. 모델 식별은 MC-1.0.0-logic-1이며 앱 발행 버전이 아니다.

[실패 근거](runs/2026-10-15-cq52-logic-2.json)와 [수정 후 실행](runs/2026-10-15-cq52-logic-3.json)을 보존했다. 수정 후 정의 온톨로지 일관성, 선언 클래스25개의 충족가능성, Product→Subject/비Campaign과 Promotion→Event/비Product 검사2건이 통과했다. 인스턴스 전체 OWL DL 검사나 독립 업무 의미 검토 통과로 확대하지 않는다.

승인 전에는 자동 승인 검토가 **내부 온톨로지의 외부 제출에 대한 명시 승인 부재**로 OOPS 제출을 거절했고 당시 POST를 실행하거나 우회하지 않았다. 이후 사용자 명시 승인으로 정의 내용 전체를 `https://oops.linkeddata.es/rest`에 제출했다. JSONL 원천·리뷰 원문·RDF 인스턴스는 제출하지 않았다. 공식 [OOPS API](https://oops.linkeddata.es/webservice.html)의 XML POST가 HTTP200으로 실행됐으며 위 검토표의 지적을 확인했다. 제출 승인 기록은 모델 hash·목적지·사용자 명시 응답을 포함한다. 지적 원문을 보존하며 수정/허용 여부를 자동 면제하지 않는다.

## CQ52-READONLY-1 — 필요한 개별 데이터 재사용 승인

기존 [D004 제안](validation-proposal.md)은 “52개시험 전체 실행 승인이나 완료가 아니다”라고 명시한다. 저장소 [AGENTS.md](../../../../AGENTS.md)는 계획 실행 지시를 개별 데이터 승인으로 간주하지 않는다. 따라서 이번 구현 지시로 이 범위를 승인 완료로 기록하지 않았다.

- 목적: 기존 52시험을 빠짐없이 추적하고, 현 입력이 있는 32건의 정형 응답 전체 assertion을 실제 실행한다. 조건 부족20건은 not_run으로 남긴다.
- 원천 재사용: D003B 기존11파일/1,652행. T01 6, T03 432, T12 6, T13 312, H01 144, T08 504, T22 168, T24 72, T09 1, T35 1, T36 6. 각 ID는 `D003B-{유형}-0001`부터 해당 건수까지이며 정확한 파일/hash와 시험 ID는 [기계 실행 범위](question-execution-scope.json)에 고정했다.
- 내용/관계: 기존 제품·국가·기간·설정·결측·원문·ID/참조를 그대로 사용한다. 기본 asOf는 2026-10-06, CQ02-3은 명세의 2026-09-30이다. 이름 매칭·관계 추정·D005 조건 대체는 하지 않는다.
- 메모리 작업: 승인된 D004 투영을 재사용하고 원천 비관측 필드 context와 질문 응답/근거를 메모리에서만 계산한다. 새로운 마케팅 원천0행, 신규 주석/span0건, 신규 오류 케이스0건, 원천 수정0건, 영구 RDF/DB0건이다.
- 검산: 별도 원천 Decimal oracle, 상태/값/완전성·사실별 근거·확보시각·범위·동일 입력 재실행/순서 불변을 검사한다. 필수 근거 삭제·무관 원천 추가·새 DST/ID충돌/정정판 fixture는 이 승인에 포함하지 않는다.
- D005는 기존 승인된 정상534행과 오류60케이스의 회귀만 재실행한다. 원천 데이터 추가나 새 오류 변형은 없다.
- 저장 결과: 시험별 응답에 필요한 값(기간별 관측값·집계 포함)·상태·근거 참조·assertion 결과만 새 보고서로 기록한다. 원천 행 전체·리뷰 원문·sourceContext/RDF payload는 저장하지 않는다.

승인 후 사용자 원문 응답·시각·scope_id·실행 범위 hash를 별도 승인 기록에 남기고 `--approval-record`로 전달한다. 플래그나 임의 기록만으로 실제 사용자 승인을 대신하지 않는다. 승인 범위의 원천 hash나 조건이 바뀌면 재확인한다.
