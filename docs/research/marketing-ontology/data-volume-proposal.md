### 숫자·문장·출처의 제안 범위

- 가격은 제안 가정으로 KRW 8,000–25,000 / JPY 800–2,500 / USD 8–25 범위. 실제 표본에서 추정한 시장 가격이 아니다. 통화별 자리와 금액 문자열을 유지한다.
- 18개 offer 중 10개만 변경한다. 변경 비율은 기준 가격의 −20%부터 +20% 범위로 제안한다. 나머지는 그대로 유지한다. 광고 효과·판매 반응은 이 묶음에서 만들지 않는다.
- 판매 상태는 unknown으로 둔다. 세금·배송 포함 여부는 null, 프로모션·재고·판매량은 필드로 임의 보완하지 않는다.
- 별점 척도는 5점. 긍정 원문은 4–5, 부정은 1–2, 혼재/중립은 3으로 단순화한 검토안이다. 별점과 감성의 일반적 동치로 주장하지 않는다. 이후 불일치·분류불확실 사례는 별도 승인안으로 추가한다.
- 리뷰의 구매 인증은 null. 자사 주문·경쟁 주문·실제 작성자 정보가 없으므로 구매 사실·개인 실명을 만들지 않는다. 작성일은 2026-04-01부터 2026-04-16 미만, 원문은 1–3문장.
- 리뷰에서 사용할 측면은 세정감·사용 후 건조감·향·거품·용기 사용성·가격 만족. 이는 분석 라벨 제안이지 제품의 객관적 효과가 아니다. 별도 T25 주석은 아직 생성하지 않는다.
- 가상 원천 파일의 record_key·artifact_ref로 추적한다. 실제 쇼핑몰 상품 URL·뉴스 URL·실제 리뷰를 만들어 붙이지 않는다. source.system은 모의 카탈로그·상품관측·제품리뷰·내부변경 로그로 명확히 구분한다.
- 모든 레코드 is_synthetic=true. 자동 난수/문장 생성은 승인한 위 범위만 사용하며, 재현용 생성 seed는 사용자가 승인한 배치의 생성 메타데이터로 기록한다.
- 지원 정의 최대40개는 Scope3·Scenario1·Brand3·Product/Variant 참조·Seller3·SourceArtifact·카테고리/측면/지표 정의를 연결하는 데 필요한 항목만 만든다. 실제 노드 수는 매핑 뒤 별도 보고한다.

### 생성·검증·온톨로지 수정 순서

1. 사용자에게 이 제안을 보여주고 D002A의 명시 승인 또는 수정 요청을 받는다.
2. 승인 후 별도 배치 폴더에만 원천을 저장한다. 기존 `lib/demo-scenarios.ts`는 이 제안으로 수정하지 않는다.
3. JSON Schema·참조·가격 변화·날짜·언어·원문 조건을 검사한다.
4. 제품–변형–브랜드, 국가별 offer–가격 관측, 제품–리뷰, offer–변경 사건의 최소 관계를 정의한다.
5. 스키마/그래프를 조정하고 수정 이유·검증·남은 질문을 기록한다. 실제 LLM 연결은 별도 단계다.
6. 이어 광고·웹·주문·재고 등 전체 목표의 다음 묶음을 구체적으로 제안한다. D002A 승인을 나머지 약2.3만 건 생성 승인으로 확대하지 않는다.

**승인 질문: 샴푸·가상3브랜드·6제품·한국/일본/미국을 기준으로, 위 D002A의 100건과 지원 정의 최대40개부터 만들까요?** 응답 전 생성·변환·적재하지 않는다.
