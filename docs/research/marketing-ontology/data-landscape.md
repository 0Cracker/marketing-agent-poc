# 실제 마케팅 분석 데이터 분류·상세 필드

최신 기록 간격·기간·수량은 [40유형 시간 설정](temporal-catalog.md), 집계·온톨로지 연결은 [시간 계약](temporal-design.md)을 따른다. 아래는 데이터 영역과 소스의 조사 목록이며 모든 자료를 같은 날짜 간격으로 생성하라는 의미가 아니다.

2026-10-13. 목적: 국가·카테고리 열위 진단 Agent와 매체 예산 제안·승인 Agent가 사용할 실제 자료 형태를 조사하고, 이후 온톨로지·가상 데이터 설계의 근거로 삼는다. 가상 레코드는 생성하지 않았다.

18개 분류, 40개 데이터 유형(T01–T40)을 정리했다. [소스 44개와 확인 수준](data-source-register.md)을 함께 읽는다. 아래 필드는 여러 소스를 통합하는 **분석용 표준화 설계 제안**이다. 한 API가 모든 항목을 그대로 반환하거나 모든 회사가 전부 수집한다는 뜻은 아니다. 원천에서 확인 가능한 항목과 내부 문서·추출 작업이 필요한 항목을 구분한다.

## 먼저 구분할 데이터 층

| 층 | 자료 | 의미 |
| --- | --- | --- |
| 업무·대상 정의 | 제품·시장·캠페인·목표·정책 | 숫자가 무엇에 관한 것인지, 가능한 행동은 무엇인지 |
| 원천 기록 | 주문·이벤트·리뷰·문의·변경 기록 | 실제 있었거나 관측된 내용. 원문/원시 필드 보존 |
| 기간별 측정 | 지출·노출·전환·매출·비중 | 정의·단위·기간·출처·집계 범위를 가진 Observation |
| 해석·주장 | 리뷰 주제·기사의 주장·원인 후보 | 누가 무엇을 주장/추출했는지, 근거·한계·버전 연결 |
| 예측·시뮬레이션 | 후보 예산·예상 성과·반응 모형 | 목표·가정·제약에 따른 결과. 실제 측정과 분리 |

## 추천 조사·데모 데이터 묶음 — 아직 승인된 범위 아님

전부를 처음부터 만들기보다 원인 후보를 구별하는 데 필요한 자료를 묶는다. 아래는 우선순위 제안이며 레코드 수·수치·문장·기간·시나리오의 생성 승인은 아니다.

| 묶음 | 포함 후보 | 확인 가능한 질문 | 부족하면 할 수 없는 것 |
| --- | --- | --- | --- |
| 공통 기반 | T01/T02/T40, 출처·시장·기간·지표 정의 | 어느 제품·목표·기간·근거를 말하는가 | 의미·권한이 불명확한 상태로 실행 |
| 광고/매출 진단 | T12/T13/T16/T17/T18/T19/T20/T35/T36 | 비용 상승·유입 저하·전환 하락·수집 장애 구별 | 광고 효율·정확한 매출 연결 |
| 경쟁/상품 원인 | T05/T08/T09/T10/T11/T22/T24/T25 | 경쟁 활동·가격·품절·리뷰 악화 대조 | 제품/시장의 원인을 광고 수치만으로 판정 |
| 예산/검증 | T21/T38/T39, T40 제약·승인 | 현행 대비 후보·실험·승인 검토 | 실제 증분 최적화·자동 집행 |
| 후속 확장 | 패널·소셜·CRM·설문·외부 환경·물류 | 별도 가설을 지지·반박 | 현재 자료로 커버하지 않은 영향 판단 |

국가·카테고리는 기존 일본·헤어케어 사례를 참고하지만 새 생성 범위로 확정하지 않았다. 일본 후보로 Rakuten·LINE·Amazon 일본 인사이트·e-Stat·JMA를 조사했다. 세계 모든 국가/제품에서 동일하게 확보 가능하다고 가정하지 않는다.

## 현실성을 유지할 조건

- 검색 지수·경매 비중·패널 추정·직접 주문·리뷰 감성·모형 결과의 숫자를 같은 종류로 취급하지 않는다.
- 게시일·실제 발생일·수집일·지표 기간을 따로 둔다. 가격·타깃·SKU 속성에도 유효기간을 둔다.
- 일부 API 값은 누적·근사·억제·귀속·지연 상태다. 완벽한 일별 전수 관측만 있는 가짜 세계를 만들지 않는다.
- 실제로 없는 경쟁사 비용·매출·고객 연결은 숨겨진 정답이나 전체 관측처럼 꾸미지 않는다.
- LLM 추출 주제와 원인 가설은 원문 위치·추출 버전·미확인 상태를 갖는다. 실제 원천 필드와 분리한다.
- CTI의 기존 검색·긍정 리뷰·참여·노출 네 값은 서로 다른 실제 소스에서 그대로 같은 의미로 확보된다고 볼 수 없다. 실제형 소스와 연결할 때 정의·비교 범위를 재설계해야 한다.
