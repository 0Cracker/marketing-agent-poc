## Discover, 확인한 문제

사용자 제공 QA는 신입 마케터 관점의 자체 탐색이며 실제 사용자 테스트와 실모델 평가는 아니다. 외부 비공개 리포트의 전체 15건은 재검증하지 않았다.

- 현재 코드에서 추이 차트에 운영 이벤트가 없고, 첫 화면 매출과 집행비가 접힌 표에 있음을 확인했다.
- 빨강 개선, 파랑 악화 범례는 이미 존재한다. 각 증감값에는 의미를 나타내는 문구가 없다.
- 리뷰 언급률의 증감은 긍부정을 구분하지 않는데, 양수는 개선색으로 표시한다.
- 기존 회귀에는 이벤트 마커가 없어야 한다는 검사가 있다. 이번 사용자 요청이 그 표시 계약을 변경한다.

## Define, 인수 기준

| 범위 | 성공 기준 |
| --- | --- |
| 이벤트 연결 | 현재 조회 범위, 분석 기간과 보고 시점에 맞는 운영 기록만 차트 날짜에 표시, 선택하면 기존 원문 확인 |
| 매출과 집행비 | ROAS 인접 영역에 두 기간 금액과 상대 증감 표시, 필터와 동기화 |
| 색 표기 | 기존 개선/악화 색 규칙을 유지하고 증감값에 텍스트 병기, 집행비는 방향만으로 성과 판단하지 않음 |
| 리뷰 | 언급 증감은 부호와 %p를 유지하고 중립 표시, 증가를 개선으로 간주하지 않음 |

목표 ROAS 기준선과 신규 데이터, 스키마 변경은 포함하지 않는다. 기존 원천만 조회한다.

## Develop, 선택과 구현

- 기존 `selectRecords`와 날짜/집계 함수를 재사용한다. 차트에는 날짜별 번호를 표시하고 아래 버튼에서 기록을 연다. 작은 추이 차트는 마커를 생략해 혼잡을 줄인다.
- 운영 기록은 관측 사실이며 ROAS 변화의 원인으로 확정하지 않는다.
- 기존 범례를 유지하고 수치 옆에 개선/악화를 병기한다. 리뷰는 언급 빈도이므로 중립색을 사용한다.
- 한 목적의 개발 패치 v5.0.8로 묶으며 패키지와 루트 잠금 버전을 함께 올린다.

## AI 활용과 다음 확인

저장소와 실제 UI를 대조해 사용자 제공 QA 중 현재 계약과 겹치는 항목을 확인했다. 기존 색상 범례는 이미 있었으므로 증감 옆 의미 표기로 보완했다. 실제 사용자 테스트나 인과 효과 검증으로 확대 해석하지 않는다. [기존 UI 교훈](../ai-lessons/lesson-002.md)과 같은 범주의 근거이며 별도 Lesson을 만들지 않았다.

목표 ROAS 생성, 나머지 QA 항목과 실제 신입 마케터 3~5명 과업 검증은 후속 범위다. 초기 구현 종료 시 원격 push와 배포는 미실행이었다. 2026-11-17 사용자 후속 요청에 따라 `fix/marketing-qa-v0.4.28` 브랜치를 원격에 올리고 dev 대상 PR로 검토를 요청한다. 클라우드 작업 완료 후 원격 PR 생성 규칙을 AGENTS.md에 기록했다. main 병합, 태그와 Release는 이 요청 범위에 포함하지 않는다.
