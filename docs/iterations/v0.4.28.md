## 1. Discover, 문제 발견

2026-11-20 사용자 요청으로 대시보드를 실무 마케터 기준으로 엄격하게 점검했다. 빌드한 화면을 Playwright로 조작해 확인했다(1440×900, iPhone 13). S16 첫 화면의 KPI 수치는 원천과 일치했지만 판단 정보가 부족했다.

- 첫 화면에 ROAS와 비율 지표만 있었다. 매출 +29.3%, 집행비 +61.6%, 주문 +22.5%는 맨 아래 접힌 표에만 있어, "증액 후 효율 하락"이 "성과 악화"로만 읽혔다.
- 데이터에 목표 ROAS(350%)가 있지만 화면에 표시되지 않았다. 목표에 미달한 캠페인(Instagram 피드 120.7% 등)도 표시되지 않았다.
- 08/21~08/24 모바일 결제 오류 기간에 구매 CPA가 급등하지만, 같은 화면에서 운영 기록을 알 수 없었다. 결제 실패율 지표도 없었다.
- 같은 지표의 이름이 화면마다 달랐다. 카드의 "CTR"은 광고 CTR이었고, CVR/클릭 기준 구매 CVR, 구매 전환 매출/귀속 구매 매출이 섞여 있었다.
- 작은 추이 그래프의 축이 좁아 +0.06%p 같은 변화도 급등처럼 보였다.
- 고정된 AI 버튼이 페이지 끝의 표 값을 가렸다.
- CAC 미집계 카드와 모든 행이 "링크 없음"인 리뷰 열이 공간을 차지했다.
- CSV 내보내기가 없었다.
- AI 서버가 없을 때도 입력창이 활성화돼, 질문을 입력한 뒤에야 보낼 수 없다는 것을 알게 됐다.

## 2. Define, 핵심 문제 정의

- 범위: 위 문제를 수정한다. 사용자 결정에 따라 다음은 제외한다.
  - 기간 선택: 여러 기간의 가상 데이터가 없다.
  - 빨강=개선, 파랑=악화 색 규칙: 프로젝트 규칙이다.
  - 수치 재검증과 데이터 현실성 보정: 신규 데이터 생성에 해당해 별도 승인이 필요하다.
- 제약: 실사용자나 현업 피드백이 불가능하다. 따라서 성공 기준을 사람이 없어도 반복 실행할 수 있는 과업 시나리오로 정의한다.
- 성공 기준: `scripts/roas/diagnostics/ux-walkthrough.mjs`의 12개 과업을 모두 통과하고, 기존 회귀 검사를 유지한다.

## 3. Develop, 해결책 탐색

- **운영 기록 표시:** 그래프에 세로선을 넣는 안은 채택하지 않았다. 과거 사용자 피드백으로 "ROAS 추이 그래프의 세로 운영 기록 점선을 제거하고 원래 차트 형태를 유지"하기로 했기 때문이다([설계 문서](../design/roas-training-dashboard.md)). 대신 그래프 아래에 분석 기간의 운영 기록을 날짜와 함께 나열했다. 장애처럼 기간이 있는 기록은 `08/21~08/24`로 표시한다. 같은 날 여러 건은 운영 기록 화면의 묶음 제목을 재사용한다.
- **목표 ROAS:** 같은 이유로 그래프 목표선은 넣지 않고, ROAS 카드와 캠페인 표에만 표시했다. 조회 범위의 캠페인 목표가 하나로 같을 때만 보여 준다.
- **예산 집행률(페이싱): 제외했다.** `dailyBudget`은 기간 중 변경 기록(240,000원 → 420,000원)과 섞여 있고, 클릭당 정산인 콘텐츠 제휴에는 의미가 다르다. 계산하면 오해할 수 있다고 판단했다.
- **CAC 카드:** v0.4.9에서 의도적으로 남긴 미집계 카드였지만, 이번 사용자 승인에 따라 결제 실패율 카드로 바꿨다. CAC를 제공하지 않는 이유는 "집계 기준" 안내로 옮겼다.
- **작은 그래프 축:** 두 기간을 모두 감싸는 공통 축이라는 기존 결정(UX-06)은 유지한다. 축 범위만 최댓값의 40% 이상으로 넓혔다. 이미 변화가 큰 범위는 그대로다.
- **라벨 통일:** 귀속 구매 매출, 귀속 구매 주문, 광고 CTR, 구매 CVR, 구매 CPA로 맞췄다. 화면, 예시 답변, 채팅 답변 표기에 같은 이름을 쓴다. Jev 도구 설명 등 백엔드의 모델 입력 문구는 바꾸지 않았다.
- **성능:** AI 대화와 운영 기록 화면을 처음 열 때 불러오도록 분리했다. 리뷰 화면은 필터 보존을 위해 마운트를 유지하는 기존 계약 때문에 분리하지 않았다.
- **AI 활용과 시행착오:** 대화 모듈을 지연 로딩하자 AI 버튼 CSS도 늦게 적용돼 버튼 모양이 깨졌다. 화면 캡처로 발견했고, 대화 관련 CSS를 대시보드에서 먼저 불러오도록 고쳤다.

## 4. Deliver, 검증 및 개선

### 변경

- **성과 현황 첫 화면:** 귀속 구매 매출, 유료 마케팅 집행비, 귀속 구매 주문 카드(직전 값과 절대 증감 포함)를 추가했다. ROAS 카드에 목표 ROAS와 목표 대비 차이를 표시한다.
- **ROAS와 지표 상세의 추이:** 그래프 아래에 분석 기간 운영 기록을 나열하고, 운영 기록 화면으로 가는 링크를 둔다.
- **보조 지표:** CAC 카드를 결제 실패율 카드로 바꿨다. 이 카드의 링크는 구매 CVR 상세의 구매 퍼널로 연결한다. 구매 CPA 상세의 관련 지표에도 결제 실패율을 추가했다.
- **ROAS 상세 표:** 목표 ROAS보다 낮은 행에 "목표 미달" 표시를 추가했다. 캠페인 표와 전체 성과 표에서 CSV를 내려받을 수 있다(UTF-8 BOM 포함, 수식 문자열 방어, 화면 반올림 전 값).
- **기타 화면:** AI 버튼 아래 여백을 확보했다. 링크가 하나도 없으면 리뷰 "원문 확인" 열을 숨긴다. AI 서버가 없을 때는 입력창을 비활성화하고 이유를 안내한다.
- **첫 화면 JS:** 589KB에서 482KB로 줄었다(gzip 기준 180KB → 145KB).

### 남은 문제와 한계

- 자동 시나리오는 정해진 과업과 휴리스틱만 확인한다. 실제 마케터의 이해도, 판단 품질, 만족도는 검증하지 않았다.
- 기간 선택은 데이터 제약으로 미구현이다. 예산 집행률은 의미가 모호해 제외했다.
- 배포 화면의 AI는 여전히 로컬 서버 연결이 필요하다. 이번에는 연결이 없을 때의 안내만 개선했다.
- 데이터 현실성 문제(결제 실패율이 평소 0%, 콘텐츠 제휴 수치가 두 기간 동일 등)는 신규 데이터 생성 승인 대상이라 수정하지 않았다.
- Vercel Preview와 원격 CI 결과는 이 일지 작성 시점에 확인하지 않았다.

## 5. AI 활용 회고

- **효과적이었던 점:** 브라우저 자동 조작과 캡처로 화면 배치, 가림, 스타일 누락을 직접 확인했다. 과업형 시나리오는 수정 전 코드에도 같은 스크립트를 돌려 기준선을 만들었다.
- **부족했던 점:** 시나리오와 휴리스틱은 AI가 정의한 것이다. 실사용자 행동을 대신하지 못한다.
- **사람의 결정:** 기간 선택과 색 규칙 제외, 수치 재검증 생략은 사용자가 결정했다. 과거 결정과 충돌한 운영 기록 점선은 기존 결정을 유지하는 쪽으로 AI가 판단했다.
- **노하우:** 컴포넌트를 지연 로딩할 때는 그 모듈이 함께 불러오던 전역 CSS(고정 버튼, 패널 배치)를 먼저 확인한다.
