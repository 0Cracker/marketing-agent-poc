## Discover, Define

기존 로컬 Agent는 외부 Vercel Preview에서 직접 사용할 수 없었다. 개발 브랜치에 인증된 외부 접근 코드를 통합하되, 별도 Worktree의 다른 미커밋 작업과 Production을 보존한다.

## Develop

- 공유 QA 비밀번호 인증, 2시간 HttpOnly Secure SameSite=Strict 세션, 로그인과 로그아웃 API.
- `/api/qa/agent`의 Origin, 경로, 메서드, JSON 크기 검사 및 HMAC-SHA256 서명.
- 요청별 nonce, 30초 서명 유효기간, 로컬 단일 프로세스의 서명 재전송 차단.
- Cloudflare Tunnel에 대한 프록시 요청, 타임아웃과 비정상 응답 차단.
- 기존 Run Engine, 7개 데이터 도구, SQLite 기록과 ROAS UI 유지.
- QA 인증 및 Run API 회귀 테스트를 GitHub Actions의 Agent 테스트 단계에서 실행.
- QA 워크트리에서 검증된 변경을 기존 dev의 자손으로 통합했으며, 다른 워크트리 변경사항은 대상에서 제외.

- 로컬 비밀 파일 `.env.local`이 레거시 모드 통합 테스트에 영향을 주는 것을 확인하고 테스트 실행 동안만 격리했다. 복원 후 SHA-256이 동일함을 확인했다. CI에는 해당 비밀 파일이 존재하지 않는다.
- 유료 모델 API 호출은 하지 않았다. Vercel Preview에서 실제 Cloudflare Tunnel을 통한 전체 왕복은 미검증이다.

## 남은 제한사항과 배포 설정

- QA 기능은 `VERCEL_ENV=preview`, `QA_GATEWAY_ENABLED=true`, `QA_GATEWAY_BRANCH=VERCEL_GIT_COMMIT_REF`와 필수 비밀값이 모두 일치해야 활성화된다.
- dev Preview에서 사용하려면 Vercel 환경변수를 **Preview + dev 브랜치 전용**으로 설정하고 `QA_GATEWAY_BRANCH=dev`를 지정한다.
- 로컬 Agent의 `AGENT_QA_GATEWAY_SECRET`과 Vercel의 값이 일치해야 하며, `QA_TUNNEL_ORIGIN`은 활성화한 Cloudflare HTTPS Tunnel 주소여야 한다.
- 공개 접근 전 Vercel Deployment Protection, WAF 또는 중앙 로그인 Rate Limiting을 적용한다.
- 브라우저의 쿠키 삭제만으로 탈취된 세션의 중앙 폐기는 불가능하다. 강제 만료가 필요한 경우 세션 키를 회전한다.
- 단기 QA용 Quick Tunnel과 장기 운영용 Named Tunnel을 구분한다.
- 상세 구성: [Agent QA 인증 게이트웨이](../agent-qa-auth-gateway.md). dev 반영은 Production 배포 또는 main 병합이 아니다.
