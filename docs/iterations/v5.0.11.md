# v5.0.11 Deep 답변 구역 배치와 고정 소제목

- 날짜: 2026-11-17
- 기준: `b871edf` (v5.0.10)
- 작업 브랜치: `claude/fervent-lovelace-50b3me`
- 범위: 답변 형식 개선 계획 3단계. 최종 생성 지침의 Deep 소제목을 고정하고, 대화 렌더러가 이를 구역으로 배치한다. 계약은 [SDD §36.19](../design/agent-development-sdd.md#3619-deep-답변-고정-소제목과-화면-구역-2026-11-17)에 있다.

## 문제

예시 답변(`RoasAnswerView`)은 핵심 결론, 결과 정리, 판단 근거, 추천 액션 구역과 강조를 갖췄다. 실제 모델 답변은 같은 서비스인데도 소제목만 있는 긴 문서로 보였다. 결론이 3줄짜리 문장 속에 묻혔고, 사실과 원인 후보가 똑같이 보였다.

## 선택과 이유

- 렌더러가 모델의 자유로운 소제목을 추측하면 오분류 위험이 있다. 그래서 지침에서 이름을 고정하고, 렌더러는 정확히 일치하는 이름만 구역으로 인식한다. 앞 번호(`## 1. 판단 근거`)는 허용한다.
- 대가로 모델 출력의 자유도가 줄어든다. 사용자는 계획 승인으로 이를 받아들였다.
- 지침을 지키지 않은 답변은 v5.0.10의 일반 Markdown 표시로 돌아간다. 답변 내용을 고치거나 보류하지 않는 §36.12 계약을 유지한다.
- 대표 변화 칩은 "지표는 A에서 B로 변화량 하락/상승" 문장 하나만 인식한다. 색은 지표 방향 규칙을 따르며, 방향을 알 수 없는 지표는 회색이다.

## 변경

- `backend/roas/engine/answer-guide.md`: Deep 소제목 4개와 각 구역의 내용 규칙을 정했다. 추천 액션은 "**대상과 조치** — 설명" 형태의 번호 목록으로 쓰고, 원인 후보 문장에는 "원인 후보"를 명시한다.
- `frontend/roas/run-markdown.tsx`:
  - `splitSections`: 고정 소제목으로 구역을 나누고, 소제목 앞 문단은 결론에 합친다.
  - `headlineChange`: 결론의 대표 변화를 직전 → 현재 칩으로 만든다.
  - 구역별 렌더링과 `원인 후보` 표시를 추가했다.
- `frontend/roas/run-markdown.css`: 결론 카드, 번호 액션 카드, 확인 필요 상자, 원인 후보 표시를 추가했다.
- `tests/agents/engine/answer-context.test.mjs`: 지침 전달 검사에 새 소제목을 반영했다. `tests/agents/ui/run-markdown.test.mjs`에 구역 테스트 2개를 추가했다. 첫 테스트의 소제목은 일반 Markdown 경로를 검사하도록 고정 이름이 아닌 것으로 바꿨다.

- 실모델(Jev, Gemini, Sail)이 새 소제목을 지키는 비율과 답변 품질은 미검증이다. 실모델 호출은 별도 승인 후 확인한다.
