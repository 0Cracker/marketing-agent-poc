## 1. Discover, 문제 발견

현재 구현의 기존 15개 파일과 기록 체계가 미커밋이었다. 로컬 원격 설정이 없어 GitHub 이력은 미확인이었다. 사용자 URL을 받은 뒤 조회/fetch한 결과 기존 main 커밋 2개와 Draft PR #1이 있었고 로컬 Sites 커밋과 공통 조상이 없었다. 로컬 main을 강제 push하면 기존 원격 이력을 잃는다.

## 2. Define, 핵심 문제 정의

기존 이력과 현재 결과물을 모두 보존하면서 첫 정식 버전을 발행한다. 기능·Mock 변경은 범위 밖이다. 사용자는 GitHub main을 v0.0.0으로 삼고 현재 로컬 결과물을 그 위에 반영하는 방식을 선택했다.

성공 기준: 기존 main/PR 보존, 후보 테스트·타입·빌드·대표 UI 검증, dev 세부 커밋과 원격 Annotated Tag 보존, main에 Squash Commit 1개 추가, 정식 태그·Release, 두 트리 동일, 원격 개발 태그 확인 후 안전한 dev 재정렬.

## 3. Develop, 해결책 탐색

대안은 로컬 main 강제 push, unrelated merge, 원격 main 위에 로컬 결과물 반영이었다. 이력 손실·불필요한 merge commit을 피하기 위해 마지막 방식을 선택했다. 로컬 초기 커밋은 별도 태그, 작업 트리는 stash/ZIP으로 보존했고 전체 로컬 소스를 dev에 가져왔다. TypeScript 캐시는 디스크에 보존하고 ignore한다.

AI는 Git 상태·diff·문서를 읽고 검증 명령과 CUA 조작을 실행해 기록을 구성했다. 원격과의 차이를 발견한 뒤 baseline 선택은 사용자에게 확인했다. 과거 구현은 이번에 새로 작성한 성과로 기록하지 않는다.

시행착오: 격리 서버에 브라우저가 접근하지 못해 호스트 서버로 전환했다. 명령별 임시 경로가 달라 최초 임시 백업 재조회가 불가능했으므로 보존된 stash 트리를 바탕화면 ZIP 두 개로 내보내 복원했다. stash는 삭제하지 않았다.

## 4. Deliver, 검증 및 개선

현재 결과물은 6개 CTI 사례·18개 고정 응답·36개 월 기록·차별화된 조사/실험/보류/유지 실행안과 더블 다이아몬드·Lesson·Skill 기록 체계다. GitHub baseline에는 없던 현재 로컬 결과를 함께 보존한다.

[baseline 근거](../../evidence/v0.1.0/before/baseline.md), [검증 요약](../../evidence/v0.1.0/validation/candidate-validation.md), [A 등록](../../evidence/v0.1.0/after/a-mock-request.png), [E 결측](../../evidence/v0.1.0/after/e-missing-data.png), [C 실험](../../evidence/v0.1.0/after/c-budget-experiment.png).

테스트 2개·타입·빌드가 통과했고 A 승인/등록, E 결측 차단, C 모의 배분과 가정, B/D/F의 다른 판단을 확인했다. 산식·Mock 정합성과 실제 효과·인과 입증은 구별한다. 가중치·임계값·승인 기준은 PoC 가정이다.

남은 문제: JS 청크 경고, 모바일/전 브라우저/전체 접근성 미검증, 마케터 이해·시간 절감 미측정. 이전 버전에 같은 CTI 입력이 없어 전후 동일 조건 UI 비교는 불가능하며 이전 UI 실행도 미수행이다.

## 5. AI 활용 회고

실제 Git·테스트·UI 결과를 연결한 기록은 유효했다. 원격 설정 부재가 원격 이력 부재를 뜻하지 않으며 임시 경로의 재조회 가능성도 확인해야 한다. 사용자 기준점 선택과 AI 실행 검증을 구분했다. 단일 경험을 보편적 검증 완료 Lesson으로 확정하지 않는다. 반복 근거가 생기면 교훈 문서를 작성한다.

## 6. 다음 Iteration

실제 사용자 피드백·마케터 이해·모바일/접근성 검증을 우선 검토한다. 번들 개선은 필요/효과를 확인한 뒤 결정한다. 다음 버전은 자동 생성하지 않으며 발행 완료 인덱스 갱신은 다음 dev 사이클에 포함한다.
