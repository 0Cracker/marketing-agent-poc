# 마케팅 분석 워크벤치 디자인 레퍼런스 조사

조사일: 2026-10-15. 상태: 사용자 레퍼런스 선택 대기.

**왼쪽 도메인 탭을 사용하는 분석 워크벤치 구조를 유지한다. 시각 디자인은 다시 선택한다.** 이번 조사는 화면의 글자·정보 밀도·차트·표·필터 배치를 고르는 자료다. 기존 데이터·기능 레퍼런스 조사와 목적을 구분한다.

- [시각 비교 보드](index.html): 기본으로 이미지가 있는 13개 후보를 표시한다. ‘이미지 있는 13개’를 해제하면 참고 지점 40개 전체를 볼 수 있다. 검색·분류·후보 체크·이미지 확대를 지원한다.
- [40개 상세 목록](catalog.md): 출처, 확인 범위, 볼 요소, 주의점, 적용 후보.

## 현재 초안에서 개선할 기준

아래는 디자인 제안이다. 사용자 선택 전에 실제 앱에 적용하지 않았다.

1. **글자 위계를 먼저 정한다.** 한글 본문·필터·표는 14–15px부터 검토하고, 11–12px 보조 글자에 핵심 정보를 몰지 않는다. 페이지 제목 24–28px, 섹션 제목 16–18px, 주요 숫자 28–32px를 시작점으로 실제 화면에서 조정한다. 보편 규칙이나 접근성 준수 판정이 아니라 우리 화면의 검토 시작값이다.
2. **한글과 숫자를 함께 검증한다.** 글꼴은 한국어 글리프·숫자 가독성을 기준으로 고른다. 숫자는 자릿수 폭을 일정하게 하고 오른쪽 정렬한다. 브랜드명·제품명은 왼쪽 정렬한다. 영문 예시 화면만 보고 글꼴을 확정하지 않는다.
3. **왼쪽 탐색에는 도메인 이름을 쓴다.** 시장·경쟁 / 브랜드·소비자 / 광고 성과 / 가격·재고 / 예산·승인 / 데이터 품질. 아이콘은 보조로 두고 선택된 위치가 분명하게 보이게 한다.
4. **페이지 전체의 조건과 차트별 조건을 구별한다.** 국가·기간·브랜드는 상단 공통 조건으로, 지표·분해 차원·비교 대상은 차트 가까이에 둔다. 현재 적용 조건을 숨기지 않는다.
5. **카드 크기를 모두 같게 만들지 않는다.** 핵심 질문을 답하는 큰 차트 1개와 보조 비교 영역을 먼저 잡고, 중요한 숫자 3–4개를 요약한다. 모든 정보에 테두리를 둘 필요는 없다.
6. **차트는 질문에 맞춘다.** 점유율 비교는 정렬 막대·100% 누적 막대, 시간 변화는 선, 매체 간 수치 비교는 표·가로 막대가 우선 후보다. 장식용 레이더·게이지·3D 그래픽은 근거 없이 추가하지 않는다.
7. **표를 분석의 핵심 화면으로 취급한다.** 단위·정의·비교 기간을 명시하고, 필요한 정렬·열 선택·행 상세를 제공한다. 높은 밀도는 작은 글씨로만 해결하지 않는다.
8. **색은 의미를 일관되게 유지한다.** 같은 브랜드·매체는 탭을 바꿔도 같은 색을 쓴다. 선택·정보·경고·오류는 구별한다. 상승이 항상 좋은 지표는 아니므로 단순 증감을 무조건 초록/빨강으로 판단하지 않는다.
9. **Agent 설명은 근거를 읽은 뒤 확인할 수 있게 둔다.** 긴 설명문이 차트보다 먼저 화면을 차지하지 않도록 우측 패널 또는 접을 수 있는 영역을 검토한다. 원본 데이터·필터·기간을 따라갈 수 있어야 한다.
10. **결측·미구축·가상을 정상 상태처럼 정돈해서 표시한다.** null을 0으로 바꾸거나, 검색 관심도·감성·예산 예측·승인 기능이 없는 상태를 임의 수치로 채우지 않는다. 원천 데이터의 통화·기간·귀속 기준을 유지한다.

## 확인 수준과 보존 범위

- **라이브 데모 직접 캡처 7개:** R01·R03·R04·R05·R11·R12·R13. 일부 컨트롤이 있는 화면을 확인한 것이며 전체 기능·반응형 동작을 테스트한 것은 아니다.
- **공식 공개 이미지 보존 6개 후보:** R02·R06·R07·R08·R09·R10. 제품 소개용 연출·축약 이미지가 포함되며 실제 고객 계정의 캡처가 아니다.
- **그 외 23개 공식/보조 자료:** 원문·검색 결과·안내 페이지 등 확인 수준을 각 항목에 명시했다. R18은 본문 수집 제한이 있었다. R38–R40은 접근 제한으로 상세 검증하지 못했다. R37도 상세 열람 범위가 제한될 수 있다.
- 브라우저가 관찰한 공개 파일을 `pageAssets`로 보존했다. `*-asset-provenance.json`에 원문 이미지 URL·보존 결과를 남겼다. 추적 픽셀·개인 데이터는 보존 대상으로 선택하지 않았다.
- 일부 서버가 파일 확장자와 다르게 AVIF를 반환했다. PNG 사본은 표시 호환성을 위한 형식 변환이며 색·구도·텍스트를 편집하지 않았다. 원본 파일도 남겼다.
- `screenshots`에는 직접 캡처와 공식 이미지가 섞여 있다. 실제 화면 여부는 파일 폴더명 대신 `references.json`의 type·evidence를 기준으로 판단한다. 보드에 표시하는 이미지 16개 외에 원본·미선정 공개 이미지도 보존되어 있다.
- 비교 보드는 이미지가 내장된 단일 HTML로, 외부 CDN·폰트·런타임이 없어도 연다. 원문 링크를 열 때만 인터넷이 필요하다. 후보 체크는 새로고침 시 초기화된다.
- 기존 초안 아카이브는 변경하지 않았다. 가상 데이터와 실제 앱 코드는 수정하지 않았고, Git 커밋·푸시·fetch·브랜치 변경도 하지 않았다. 이 폴더는 로컬 보존이며 원격 백업을 의미하지 않는다.

## 선택 기록

사용자 확정: 왼쪽 도메인 탭을 사용하는 분석 워크벤치형.

미확정: 기본 배경(밝음/어두움), 글꼴·밀도, 핵심 참조 화면, Agent 설명 영역, 개별 차트와 표의 최종 배치.

선택은 전체 분위기·글자·차트·표로 나누면 된다. 예: “전체 분위기 R02, 글자 R01, 차트 R07, 표 R12.” 해당 번호는 의견을 전달하기 위한 식별자이며 선택 전 앱 구현을 진행하지 않는다.

## 재생성

`references.json`을 수정한 뒤 이 폴더에서 `node build-board.mjs`를 실행하면 `index.html`과 `catalog.md`를 다시 만든다. 보존 이미지가 있어야 한다. 앱 빌드·설치·데이터 생성과 독립된 자료 생성 도구다.
