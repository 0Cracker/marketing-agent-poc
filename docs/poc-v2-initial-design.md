# 마케팅 AI Agent POC — 고정 시나리오 Mock-up 설계

수정일: 2026-10-08 · 기준: 최초 요구사항 v2.0 및 이후 사용자 범위 정정

이 문서는 기존 최초 설계를 대체한다. 사용자의 최신 지시에 따라 **고정 질문·고정 응답·파일에 하드코딩된 가상 데이터로 구성한 시연**을 목표로 한다. 앱 구현은 아직 변경하지 않았다.

## 1. 목표와 범위

시연 대상은 두 가지 업무 경험이다.

- Step 1: 마케터가 CTI 변화에 관해 질문하고, 추이·구성요소 기여도·매체/리뷰 근거·원인 가설·반대 근거·대응 방안을 확인하는 경험.
- Step 2: 분석 결과에서 광고 예산 재배분안으로 이어지고, 현재/추천 예산·가정·예상 CTI·승인·Mock 집행 결과를 확인하는 경험.

실제 서비스 수준의 동적 분석 에이전트를 구현하는 것이 아니다. 보여줄 질문과 답변을 미리 정하고, 필요한 가상 데이터와 차트·표·근거·설명을 파일에 직접 넣는다. 후속 질문도 미리 정의한 질문으로 연결한다.

**정교함은 런타임의 동적 기능이 아니라 시나리오를 작성하는 과정에서 확보한다.** 가상 원천값이 지표와 일치하고, 지표 변화와 설명이 연결되며, 대응안이 명시적인 수식과 가정을 따라야 한다. 완성된 결과를 하드코딩하는 것은 허용한다.

| 포함 | 제외 |
| --- | --- |
| 고정 질문·응답 쌍, 정해진 후속 질문 | 임의 자연어 질문 처리·표현 변형 대응 |
| 가상 원천값·지표·차트·근거의 논리적 설계 | DB 도입·외부 API·데이터 조회/탐색 계층 |
| 시나리오 작성 시 실제 수식으로 계산·검산 | 런타임 분석 계획·도구 선택·가설 생성 |
| 공통 UI로 고정 응답 표시 | 실제 LLM 연결·멀티 에이전트 프레임워크 |
| 사전 계산한 예산안·가정별 비교 | 사용자 임의 예산·제약에 대한 동적 최적화 |
| 시연용 승인·Mock 실행 상태 | 실제 광고 집행·서버 승인·인증·영속 이력 |

초기 전달서의 고정 응답 금지, 입력 변이 대응, 자동 데이터 탐색 요구는 최신 사용자 지시로 대체됐다. 일반화 성능이나 실제 에이전트 기능을 완료 기준으로 삼지 않는다.

## 3. 데이터 작성 구조 — 한 파일 안의 고정 시나리오

첫 구현은 `lib/demo-scenarios.ts` 같은 **단일 콘텐츠 파일**로 시작한다. DB·검색·조회 어댑터를 추가하지 않는다. 파일에 공통 가상 데이터와 질문·응답 쌍을 함께 하드코딩한다. 같은 자료를 여러 질문에서 사용하면 동일 파일의 상수를 참조해 중복 숫자 수정 실수를 줄인다.

권장 논리 구조:

```ts
// 구현 전 계약 개요. 하위 타입은 콘텐츠 작성 시 구체화한다.
const demoCase = {
  id: 'jp-haircare-a',
  context: {
    country: '일본', category: '헤어케어',
    product: '제품 A', competitor: '제품 B',
    baseline: '2026년 6월', current: '2026년 9월',
    comparisonScope: ['제품 A', '제품 B'],
    metricDefinition: 'CTI_demo_v1',
  },
  rawData: { search: [], reviews: [], social: [], media: [], events: [] },
  calculated: { components: [], ctiSeries: [], contributions: [] },
  budget: { assumptions: {}, current: [], recommended: [], expected: {} },
};

const demoScenarios = [
  {
    id: 'B01',
    question: '제품 A의 CTI가 왜 떨어졌어?',
    caseId: 'jp-haircare-a',
    response: {
      title: '제품 A의 CTI 하락 분석',
      conclusion: '',
      metricSummary: [],
      charts: [],
      observations: [],
      hypotheses: [],
      limitations: [],
      recommendations: [],
    },
    nextScenarioIds: ['B02', 'B03', 'E02'],
  },
];
```

위 내용은 구조 예시이며 빈 배열을 실제 분석 데이터처럼 표시하지 않는다. 구현 단계에서 각 질문·답변·수치·그래프 자료를 완성해 넣는다. 질문의 의미를 해석해서 분석하는 대신, 선택한 scenario ID의 응답을 표시한다. 배열/상수 참조는 파일 내부 콘텐츠 연결이며 데이터 조회 계층을 뜻하지 않는다.

시연의 입력 방식은 추천 질문·시나리오 버튼을 기본으로 한다. 채팅 입력창을 유지하면 등록된 질문의 정확한 일치만 연결하고, 다른 입력에는 '시연 질문을 선택해 주세요'를 표시한다. 키워드 추측이나 유사도 검색은 필요하지 않다.

고정 필터도 실제 선택 가능한 데이터만 제공한다. 선택할 수 없는 국가·기간·제품은 정적인 분석 조건으로 보여준다. 여러 조건을 시연하려면 해당 조합을 별도 시나리오로 작성한다.

## 4. 시나리오 작성 Flow — 실제 분석 절차를 콘텐츠로 정교화

```text
시연할 질문 확정
  → 대상·기간·경쟁 범위 확정
  → 가상 원천 데이터 작성
  → 수식으로 지표·변화·기여도 계산
  → 매체/리뷰/경쟁사 관측 작성
  → 지지·반대 근거를 대조해 가설 작성
  → 권고와 한계 작성
  → 차트·표·텍스트에 동일 결과 반영
  → 완성된 질문·응답 쌍을 파일에 하드코딩
```

여기서 데이터 지정/미지정은 **시연 장면의 차이**다.

| 장면 | 고정 질문 예 | 준비할 응답 |
| --- | --- | --- |
| 데이터 지정 | '리뷰 데이터를 중심으로 제품 A의 CTI 하락을 분석해 줘.' | 리뷰 건수·긍정률·상대 점유율·평점·주제·반대 근거를 중심으로 한 고정 분석 |
| 데이터 미지정 | '제품 A의 CTI가 왜 떨어졌어?' | CTI 정의·기여도·매체/리뷰 관측·가설·한계를 포함하는 통합 고정 분석 |

화면에서 사용 자료 목록과 분석 단계는 보여줄 수 있다. 이는 사전 구성된 시연 내용이며 실제 자동 탐색이나 모델 도구 실행이 일어난다는 뜻으로 표시하지 않는다. 단계 애니메이션이 필요하면 시연용 연출로 사용한다.

## 5. CTI 계산과 가상 데이터의 정합성

데모 정의:

`CTI = 0.35S + 0.25R + 0.20E + 0.20M`

- S: 자사 검색 관심량 / 비교 집합 전체 검색 관심량 × 100
- R: 자사 긍정 리뷰 건수 / 비교 집합 전체 긍정 리뷰 건수 × 100
- E: 자사 참여 건수 / 비교 집합 전체 참여 건수 × 100
- M: 자사 광고 노출 수 / 비교 집합 전체 광고 노출 수 × 100

모든 분모는 같은 국가·카테고리·기간·제품 집합과 측정 기준으로 구성한다. CTI는 포인트(pt), 점유율 차이는 퍼센트포인트(pp), 상대 증감은 %로 구별한다. 광고 노출과 고유 도달 인원은 혼용하지 않는다.

### 기준 사례

| 원천값 | 6월 | 9월 |
| --- | ---: | ---: |
| A 검색 관심량 | 6,000 | 5,500 |
| B 검색 관심량 | 4,000 | 4,500 |
| A 긍정 리뷰 | 650 | 450 |
| B 긍정 리뷰 | 350 | 550 |
| A 디지털 참여 | 5,500 | 5,300 |
| B 디지털 참여 | 4,500 | 4,700 |
| A 광고 노출 | 600,000 | 450,000 |
| B 광고 노출 | 400,000 | 550,000 |

| 구성요소 | 6월 | 9월 | 기여도(pt) |
| --- | ---: | ---: | ---: |
| S | 60 | 55 | -1.75 |
| R | 65 | 45 | -5.00 |
| E | 55 | 53 | -0.40 |
| M | 60 | 45 | -3.00 |
| CTI | 60.25 | 50.10 | -10.15 |

`기여도 = 가중치 × (9월 값 − 6월 값)`이며 합계 −10.15가 CTI 차이와 일치해야 한다. 이 사례는 가상 데이터 설계 기준으로 사용할 수 있으며 기존 앱 실적이 아니다.

6개월 추이 시연을 만들려면 중간 달도 검색·리뷰·참여·노출 원천부터 채우고 각 월 CTI를 검산한다. 차트의 보기 좋은 모양만 먼저 정하고 원천과 무관한 값을 넣지 않는다. 일별 차트가 필요하면 일별 원천 합계가 월 집계와 일치하게 작성한다.

여러 기간을 합친 점유율은 원천 합계의 비율로 계산한다. 월별 점유율 단순 평균과 구별한다. 산식이나 경쟁 범위가 달라진 사례는 별도 조건과 한계를 표시한다. 결측 사례는 null/계산 불가로 표시하고 0으로 대체하지 않는다.

## 6. 원인 설명의 정교함

계산으로 확인된 사실, 가상 데이터에서 관측된 현상, 설명 후보를 구별한다. 하드코딩된 응답도 이 구별을 지켜야 한다.

### 매체 데이터

채널별 광고비·노출·클릭·전환, 캠페인 시작/종료, 경쟁사 활동을 같은 기간으로 작성한다. `CPM=광고비/노출×1000`, `CTR=클릭/노출`, `CVR=전환/클릭`이다. 통화와 귀속 기준을 명시한다.

광고비 증가/노출 감소 사례에는 CPM 상승 등 수치상 설명을 준비한다. CPM 상승만으로 소재 피로도·광고 경쟁·타기팅 실패를 확정하지 않는다. 캠페인 종료가 하락 이후에 발생했다면 하락 시작의 원인으로 작성하지 않는다.

### 리뷰 데이터

긍정·중립·부정·미분류 합계가 전체 리뷰 수와 일치해야 한다. 자사 긍정 비율과 비교 집합 긍정 리뷰 점유율은 따로 저장한다. 평점은 척도·유효 표본 수를 함께 명시하고, 주제 빈도와 인용 원문을 맞춘다.

- 자사 평점/긍정률 유지 + 경쟁사 긍정 리뷰 증가: 상대 경쟁력 변화 사례. 품질 악화로 단정하지 않는다.
- 자사 긍정률/평점 하락 + 특정 불만 주제 증가: 제품 경험 악화 가설 사례.
- 수집량 급감/플랫폼 변경: 수집 범위 문제를 대안 설명으로 포함한다.

단순히 긍정 리뷰 건수가 줄었다는 사실만으로 긍정률·평점도 하락했다고 쓰지 않는다. 해당 수치를 별도로 설계해야 한다.

### 가설 카드 계약

각 고정 가설은 다음 내용을 갖는다.

```text
가설 / 관련 구성요소
지지 근거: 구체적인 수치·기간·원천 행
반대 근거: 가설과 맞지 않는 관측
시간 관계: 변화의 선후관계
대안 설명: 경쟁사 성장·수집 변화·외부 요인
판단: 지지됨 / 근거 혼재 / 근거 부족 / 반대 관측
한계 및 추가 검증: 실제 데이터에서 무엇을 확인해야 하는가
```

산술적 CTI 기여도는 실제 원인의 인과 기여율이 아니다. 가설에 임의 확률을 붙이지 않는다. 인과가 검증되지 않은 시나리오는 '관련 가능성', '추가 확인 필요'로 설명한다. 대응안은 데이터가 지지하는 범위에서 작성한다.

| 2 통합 진단 | '제품 A의 CTI가 왜 떨어졌어?' | 60.25→50.10, 네 기여도, 매체/리뷰 가설과 반대 근거 |
| 3 리뷰 상세 | '리뷰 쪽을 더 자세히 확인해 줘.' | 긍정 건수/비율/점유율·평점·불만 주제·수집 한계 |
| 4 매체 상세 | '광고비가 늘었는데 왜 성과가 나빠졌어?' | 지출/노출/CPM·캠페인·경쟁 변화 |
| 5 예산 | '광고 예산 1,000만원을 재배분해 줘.' | 현재/추천안·반응 함수·제약·예상 M/CTI·비광고 문제 |
| 6 승인 | '추천안으로 진행할게.' | 해당 고정 예산안의 확인·승인 동작·Mock 완료 |

중간에 버튼 순서를 바꿔도 선택한 시나리오의 조건을 표시한다. '리뷰를 더 확인해줘' 같은 질문은 그 장면에 연결된 case ID로 응답하며 일반적인 대화 이해는 구현하지 않는다.

확장할 사례는 상대 점유율 하락/품질 유지, 광고비 증가/노출 감소, 리뷰 개선/광고 악화, CTI 상승, 일시 급락 후 회복, 결측, 측정 기준 변경 등이다. 별도 사례끼리 숫자를 섞지 않는다.

이전 문서의 20개 시나리오는 콘텐츠 후보 목록으로 사용할 수 있다. 모두를 일반화된 분석 기능으로 구현할 필요는 없다. C01–C04의 시장 매출·퍼널·유통·설문 사례를 선택하면 그 장면의 가상 원천과 수식을 따로 설계한다. 모든 국가·카테고리·제품 조합을 생성할 필요는 없다.

## 8. Step 2 — 사전 계산한 예산 시연

Step 1과 Step 2는 같은 case ID, 기간, CTI 정의, 현재 구성요소를 공유한다. 예산 장면은 완성된 현재안·추천안·예상 효과를 파일에 하드코딩한다.

추천안을 작성할 때는 명시적인 수확체감 함수와 총예산/상하한을 사용해 계산하고 검산한다. 예시 함수:

```text
채널별 노출 I_j(b) = Q_j × log(1 + b / K_j)
총 자사 노출 = Σ I_j(b_j)
예상 M = 100 × 자사 노출 / (자사 노출 + 경쟁사 고정 노출)
예상 CTI = .35S + .25R + .20E + .20예상 M
Σ채널 예산 = 1,000만원
채널별 최소 예산 <= 추천 예산 <= 최대 예산
```

Q/K·집행 기간·통화·경쟁사 고정 노출은 콘텐츠 파일의 가정으로 명시한다. 기준 예산을 넣었을 때 현재 M/CTI가 재현되도록 기준점을 맞춘다. 작성 과정에서는 작은 계산 스크립트나 검산 함수를 활용할 수 있지만, 런타임에 최적화 서버를 만들 필요는 없다.

추천안은 가정과 제약 아래의 계산 결과로 정하고, 표에 넣을 예쁜 금액부터 만든 뒤 효과를 붙이지 않는다. '최적안'이라고 표현한다면 설정된 함수·제약에서 최적이라는 근거를 검산해야 한다. 단순 비교 계산이라면 '모의 재배분안'으로 표현한다.

현재 M=45, CTI=50.10에서 계산된 예상 M이 56.5라면, S/R/E 고정 조건의 예상 CTI는 `50.10 + .20×(56.5−45) = 52.40`이다. 이 숫자는 예시이며 실제 예산안·곡선에서 56.5가 나오도록 확인하기 전에는 최종 응답값으로 확정하지 않는다.

CTI 개선을 매출·ROAS·ROI 개선으로 표현하지 않는다. 리뷰 문제가 광고 재배분으로 해결된다고 쓰지 않는다. 보수/기본/낙관 값을 보여주면 명시적인 가정별 결과이며 통계적 신뢰구간이 아니다.

승인은 클라이언트 시연 상태로 충분하다. 승인 전에는 Mock 완료 버튼을 막고, 특정 고정안의 승인 후 'Mock 집행 완료 — 실제 광고 계정 반영 없음'을 표시한다. 서버 승인 저장·인증·실제 계정 연결은 추가하지 않는다. 새 시연을 시작하면 상태를 초기화한다.

## 9. UI 계약과 표시 일관성

전체 레이아웃은 기존 대시보드 + 사이드 채팅 + 넓은 캔버스를 유지한다.

- 단순 질문: 핵심 수치·변화·추이·짧은 요약.
- 비교 질문: 제품/국가별 수치·구성요소 차이·비교 범위.
- 진단 질문: 변화 워터폴·매체/리뷰 근거·가설·반대 근거·한계.
- 특정 가설: 판단·지지/반대·추가 검증.
- 예산 질문: 현재/추천 비교표·총액·가정·예상 CTI·승인.

같은 시나리오 객체의 값을 카드·차트·표·채팅에서 사용한다. JSX 안에 또 다른 CTI 숫자를 복사하지 않는다. 질문·답변은 하드코딩하되 수치 상수를 공유하거나 작성 시 검산하여 설명과 수치가 어긋나지 않게 한다.

원천 테이블은 시연 데이터의 근거로 제공한다. 실제 출처처럼 외부 시스템 이름을 붙이는 경우에도 가상 자료임을 명시한다. 'Mock 데이터 기반 고정 시나리오 데모' 라벨을 유지하고, 실제 AI 분석이 수행됐다고 주장하지 않는다.

기존 색상·글꼴·shadcn/Recharts를 활용한다. 워터폴을 핵심 시각화로 두고 수치·기간·단위·경쟁 범위를 가까이 표시한다. 확인된 계산/관측/가설/모의 효과는 텍스트로 구분한다. UI 완성도는 실제 브라우저에서 잘림·겹침·표 스크롤·키보드·상태 초기화까지 확인한다.

## 11. 테스트 기준

필요한 검사는 동적 분석 능력이 아닌 **작성한 시나리오의 정확성**이다.

1. 원천으로 점유율·CTI·기여도를 재계산하면 저장값과 일치한다.
2. 기여도 합계=CTI 변화, 워터폴 끝값=현재 CTI다.
3. 일/월 합계·리뷰 감성 합계·주제 인용·광고 효율 수식이 맞는다.
4. 기간·국가·제품·비교 집합·측정 기준이 장면 내부 및 이어지는 장면에서 일치한다.
5. 예산 합계·상하한·운영 가능 여부·현재 CTI·예상 CTI가 가정과 일치한다.
6. 설명의 모든 중요한 수치가 표·차트와 일치하고, 가설과 반대 근거가 모순되지 않는다.
7. 등록된 질문은 정해진 응답으로 연결되며 후속 버튼은 유효한 scenario ID를 가리킨다.
8. 승인 전 Mock 완료 표시가 없고, 실제 광고 집행으로 오인시키지 않는다.
9. 초기화·패널 열기·근거 펼침·좁은 화면에서 시연이 깨지지 않는다.

임의 질문 평가, 런타임 데이터 변이 대응, 자동 탐색 정확성, 모델 반복 평가, 정답 접근 차단 검사는 이번 범위에서 제외한다. 대신 콘텐츠 값을 편집할 때 검산을 다시 실행해 하드코딩된 결과의 불일치를 잡는다. 이것은 동적으로 반응하는 제품 기능이 아니라 작성물 품질 검사다.

## 12. 향후 실제 데이터에 적용한다는 의미

현재 목표는 **실데이터로 바꾸어 검토해도 타당한 계산·설명 논리**를 만드는 것이다. 입력 파일만 교체하면 실제 서비스로 동작하도록 만드는 것은 요구하지 않는다.

이를 위해 지표 정의·분모·기간·원천값·가정·근거·한계를 명확히 남긴다. 나중에 실제 데이터가 들어오면 같은 수식과 분석 관점을 적용해 시나리오 콘텐츠를 다시 작성할 수 있다. 실제 자동 분석 서비스로 발전시키려면 DB/조회/모델/동적 계산/인증을 별도 프로젝트 범위로 추가해야 한다.

이번 단계의 다음 작업은 **대표 6장면에 사용할 하나의 가상 데이터 사례와 고정 질문·응답을 완성하는 것**이다. 기존 앱은 그 콘텐츠를 일관된 화면으로 보여주는 역할을 맡는다.

## 13. 추가 품질 기준과 구현 현황 — 2026-10-08

사용자가 추가한 기준을 반영해 질문 수보다 데이터 상황의 해석 차이, 질문 목적별 정보량, 전문적인 근거의 타당성을 우선한다.

| 상황 | 강조 지표/그래프 | 결론·권고 방향 |
| --- | --- | --- |
| A 리뷰 경쟁력 하락 | 감성·긍정률·평점·불만 주제 | 고객 경험 개선 우선, 광고 문제 별도 검토 |
| B 경쟁사 급성장 | 자사 절대값 유지·경쟁사 성장 지수 | 상대 점유율 약화와 제품 품질 악화를 구별 |
| C 광고비 증가/성과 하락 | 광고비·노출·CPM 비교 | 비용 효율·캠페인 운영 점검 |
| D 복합 요인 | 양/음 구성요소 기여도 | 리뷰 하락과 광고 개선의 상쇄, 리뷰 우선 대응 |
| E 측정 문제 | 수집 상태·결측 | CTI 판단/예산 검토 보류 |
| F 성과 개선 | 구성요소 점유율 개선 | 유지 전략, 매출/수익 개선은 별도 검증 |

여섯 사례별 조회·진단·대응의 18개 고정 응답을 구현했다. 표시 기간은 2026년 4–9월, 비교는 4월 대 9월로 통일했다. 앞 장의 6월/9월 표는 산식 예시이며 구현의 기간 라벨은 위 기준을 따른다. 조회는 추이, 진단은 기여도와 상황별 근거, 대응은 우선순위와 Step 2 진입을 표시한다.

콘텐츠는 `lib/demo-scenarios.ts`에 하드코딩한다. 작성 전용 `scripts/author-demo.mjs`로 계산·정리한 결과이며 앱 런타임에서 생성·조회·분석하지 않는다. 총예산 1,000만원(사례 C는 관측 예산 1,200만원)을 유지하는 고정 예산안 다섯 개를 연결했다. E는 결측으로 차단한다. 예산 재배분은 사전 계산한 모의 비교안이며 최적안을 주장하지 않는다.

학문적 타당성 참고 자료는 화면에서 연결한다.

- [Google 구매 결정 연구](https://www.thinkwithgoogle.com/_qs/documents/9998/Decoding_Decisions_The_Messy_Middle_of_Purchase_Behavior.pdf): 리뷰와 사회적 증거를 고객 판단의 관련 단서로 검토한다. 특정 시연 제품의 매출 효과를 추정하지 않는다.
- [Meridian 반응 곡선](https://developers.google.com/meridian/docs/post-modeling/roi-mroi-response-curves): 평균 관측 성과와 추가 투자의 효과를 구별한다. 데모의 log 노출 곡선은 별도로 정한 가정이다.
- [Meridian 인과 방법론](https://developers.google.com/meridian/docs/causal-inference/about-mmm-causal-inference-methodology): 관측과 인과를 구별하고 가정·한계를 남긴다.

원천→CTI·기여도·월별 차트·리뷰/광고 합계·예산/곡선/효과 연결은 `tests/demo.test.ts`에서 검산한다. 이론은 고정 답변의 품질을 높이기 위한 참고이며 실제 분석 시스템 구현 범위에 추가하지 않는다.

### 기본 UI 구성 수정 — 2026-10-08

사용자 요청에 따라 마케터의 데이터 대시보드를 기본 화면으로 두고, 오른쪽 고정 사이드창에 AI 대화를 배치한다. CTI 추이, 접점 점유율, 채널별 광고비·노출·CPM, 리뷰 감성·평점·불만, 자사·경쟁사 원천값을 펼쳐 표시한다. 준비된 질문을 선택해도 대시보드를 유지하며, 답변의 “차트와 근거 보기”로 상세 분석을 연다. 상세 분석에서 대시보드로 복귀해도 대화와 승인 상태를 보존한다. 사례 변경 또는 시연 초기화는 기본 화면으로 돌아온다. 모바일 대응은 범위에 포함하지 않으며 데스크톱 3열 레이아웃을 유지한다. 기본 화면·대화·상세 분석·예산 승인/Mock 집행·대시보드 복귀를 브라우저에서 확인했다.


### 채팅 내 응답 — 2026-10-08

예시 질문의 응답은 화면 전환 없이 오른쪽 채팅 안에서 완결되도록 표시한다. 조회는 CTI 수치와 추이, 진단은 기여도·관측 근거·접을 수 있는 가설/제한, 대응은 우선순위, 예산은 배분표·모의 효과·승인/Mock 집행을 포함한다. 상세 분석은 선택적 보조 화면이다. 응답 후 질문 선택 영역을 접어 대화의 가독성을 높인다.


### 지표 가독성 정리 — 2026-10-08

대시보드의 첫 영역은 CTI 현재값·기준값·pt 변화와 추이를 묶는다. 광고비·노출·리뷰 긍정률·CPM은 현재값, 단위, 증감, 4월 기준을 같은 위치에 표시한다. 비율 변화는 %p, 상대 증감률은 %, CTI 변화는 pt로 구분한다. 점유율은 비교 표, 리뷰는 감성 구성과 수집 건수로 구분하며 원천값·광고 채널 표는 아래에 유지한다. 채팅 기여도는 변화폭 최대 항목을 강조하되 산술 변화로 설명한다. 결측은 미수집/계산 불가로 표시한다.


## 판단·실행 시연 보강 — 현재 구현 기준

앞선 동일 재배분안/예산 즉시 Mock 집행 설명은 이 절로 대체한다. A/B/D는 조사와 현행 예산 유지, C만 현행 유지 대비 조건부 실험, E는 계측 복구와 판단 보류, F는 현행 유지·모니터링이다. 승인 대상은 업무/실험 계획이며 Mock 요청 등록만 시연한다. 각 실행안에는 팀·기한·입력 자료·완료 산출물·성공/중단 조건·후속 판단이 있다. 가상 데이터의 원천·비중·가중 기여도와 다섯 단계 분석 경로를 채팅 안에 포함한다. 월별 변화는 사건별로 작성하고 사건이 전체 변화를 설명하지 못하는 범위도 밝힌다. 전체 내용은 scenario-playbook.md에서 검토한다. 판단 규칙·임계값·실험 성공 조건은 PoC 가정이고 실측 효과가 아니다. 시간 절감은 파일럿에서 검증할 목표다. 화면의 식별 문구는 CTI 판단 v3이다.
