# 503 수동 재개·근거 요약 표시 수정

2026-10-20 · 계획 → 독립 검토 → 수정 → 검증 기록

## 최초 계획 v1

- 공통 모델 어댑터의 HTTP 503을 `model_unavailable`로 구분하고 기존 `paused → resume` 경로를 사용한다. 자동 재시도·키 전환은 하지 않는다.
- 실행 ID·조회 이력·자료 해시·누적 호출 수를 유지한다. 재개 성공 뒤 이전 오류 안내를 정리한다.
- 핵심 요약과 상세 표가 공통 근거 분류를 사용하도록 한다. 빈 지지·반대 배열은 미분류이며 영향 없음으로 표현하지 않는다.
- 기존 자료와 모델 응답 대역으로 회귀 검사한다. 원천 자료·스키마·Git 상태·실제 광고·외부 모델 호출은 변경하지 않는다.

## 독립 검토와 반영

별도 `strict_review` 에이전트의 조건부 승인 사항을 담당 에이전트에게 전달받았다.

- 복구 대상으로 503만 추가한다. 500·502·504·401은 기존 일반 실패로 유지하며 요청당 fetch 한 번을 검사한다.
- 이전 `reason`과 `resumeConditions`는 실제 `running` 전환 때만 정리한다. `stopped` 이벤트는 보존하고 호출 상한에서는 새 `call_limit` 사유를 남긴다.
- 동시 재개는 동일 AgentFlow의 기존 보호만 검증한다. 다중 프로세스 잠금은 추가하지 않는다.
- 예산 실행은 SQLite 재연결 후 분석 ID·버전·계산 이력·누적 카운터 보존까지 검사한다.
- 요약의 기존 가설 순서와 최대 두 개 표시를 유지한다. 반대 근거만 있는 경우의 실제 지지 0건은 유지한다.
- 과거 `held/model_failed` 기록을 소급 변경하지 않는다.

## 최종 구현 기준 v2

1. 모델 어댑터에 503 오류 코드 하나를 추가하고 실행기의 기존 일시 중단 분류에 연결한다. 재개 버튼과 공개 API는 재사용한다.
2. `running` 전환에서 이전 오류 안내만 제거한다. 누적 호출 상한·입력 해시·동시 실행 보호와 중단 이벤트는 유지한다.
3. 화면의 공통 근거 행에 요약 문자열을 추가한다. 핵심 요약은 원래 가설 순서를 따라 두 개까지 표시하고 상세와 같은 분류를 사용한다.
4. 어댑터·복원·호출 상한·동시 재개·과거 기록·표현 회귀와 전체 백엔드 및 화면 관련 시험·타입 검사를 실행한다.

## 제한

503은 공급자가 요청을 거절한 일시 장애로 취급한다. 사용자가 재개할 때마다 기존 호출 한도를 소모한다. 이전 일반 실패에는 상세 원인이 없으므로 자동 복구하지 않는다. 500·502·504 확대, 다중 프로세스 실행 제어, 실제 모델 재검증은 이번 변경에 포함하지 않는다.

## 실행 결과

503 분류·같은 실행 수동 재개·옛 오류 안내 정리·미분류 요약 통일을 구현했다. 독립 검토자는 최종 v2 계획의 필수 항목 반영을 승인했다.

- 백엔드 전체 123/123, 화면 관련 20/20, 화면 TypeScript 검사 종료 코드 0. 신규 복원·오류 회귀 9개도 단독 실행에서 통과했다.
- 최초 백엔드 검사는 샌드박스의 로컬 HTTP 연결 실패 후 중단했다. 로컬 루프백을 허용한 동일 명령으로 전체 통과를 확인했다. 이 실패를 기능 결함으로 기록하지 않는다.
- 외부 모델·실제 광고 호출은 0회다. 원천 자료·스키마·기존 SQLite 기록을 변경하지 않았고 커밋·스테이징·발행도 수행하지 않았다. 새 시험용 SQLite는 임시 폴더에서 생성·삭제했다.
- 새 브라우저 캡처와 실제 공급자 재검증은 미실행이다. UI의 분류·오류 문구와 기존 호출·복원 계약은 자동 검사했지만 사용자 화면 수용 검사를 대신하지 않는다.
- 실행 명령·종료 코드·제약: [검증 결과](../../evidence/v0.4.0/resilience-20261020/result.json).

구현 후 독립 `strict_review` 검토에서도 차단 사항이 없음을 확인했다. 화면 순서 보호 시험의 `source.includes` 검사는 구현 문자열에 결합된 한계가 있으나 완료 차단 사유는 아니라는 의견을 기록한다. 공급자 오류 검사는 HTTP 응답 대역을 사용하며 실제 서비스의 가용성이나 자유 질문 품질을 검증한 결과가 아니다.
