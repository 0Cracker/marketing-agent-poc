# 전체 데이터 연결 — 2026-10-18

사용자 요청 ‘모든데이터를 다 대시보드에 연결해’에 따라 이전 D007 선택 연결과 상세 표 중심 구현을 확대했다. 원래 데이터 저장소의 배치 source 폴더를 모두 읽고, **91개 JSONL 파일·22,242행 전체**를 대시보드에서 조회할 수 있도록 연결했다. 이전 단계 기록의 ‘D005/D006 목록 점검만 수행’, ‘신규 유형 상세 표 우선’, ‘기본 D003B’ 제한은 이 후속 작업으로 해소했다.

| D005 | 534 | 534 | 전체 원천·표준 필드·원문·CSV |

미적합 790행을 제외하거나 새 값으로 보완하지 않았다. `_contract_gaps`는 원래 카탈로그의 검증 결과이며, `_source`는 원래 JSONL 행 그대로다. 원본 탭·원본 복사는 보존 원문을 사용한다. 배치·국가·기간·정의가 다른 값을 성과 합계로 합치지 않는다. 전체 배치의 차트는 배치별 원천 행 수를 표시하고, 검증된 D007 분석과 구분한다.

## 화면 동작

- 진입 시 5배치를 모두 읽고 해시를 확인한다. 기본 화면은 D007 증강 데이터다.
- ‘데이터’에서 전체 배치, 각 배치, D003B 보존 화면을 선택한다. 전체 배치·기존 원천 선택 시 전체 국가·전체 기간으로 전환한다.
- 모든 국가·전체 기간을 선택하면 전체 원천을 탐색할 수 있다. D007의 ‘원천 레코드’ 보기는 집계 전 레코드와 전체 업무 필드를 보여준다.
- 표 검색·정렬·페이지·CSV·근거 패널을 기존 컴포넌트로 연결했다. CSV는 현재 페이지에 한정하지 않는다.
- 정규화 범위·실험·모형 선택은 KPI·차트·표에 함께 적용한다. 다른 범위는 선택기로 조회하고, 원천 레코드에서 한 번에 확인할 수도 있다.
- 긴 막대 차트는 6행씩 구간을 이동한다. 상세 표와 CSV에서는 필터 결과 전체를 제공한다. 축은 긴 대상·관측일을 두 줄로 표시하며 단일 관측 선그래프도 점을 표시한다.

## 검증과 보존

- `node scripts/import-all-catalog.mjs`: 원천 파일 전체 스캔 → 공식 카탈로그 → 물리 행수 대조. 기존 D007 조회본과 최신 원천의 레코드 일치 확인. 원천 생성·수정 없음.
- `node scripts/check-all-connected.mjs`: 41유형의 원천 행을 배치/ID 기준으로 한 번씩 방문해 22,242행 확인. 각 배치 행수, 원문 일치, 미적합 보존, 전체 CSV, 91파일 해시, 3국가 × 41유형의 차트/표를 검사했다. CRM 값·이벤트 건수·실험군 전환율을 별도로 대조했다.
- `node scripts/check-standard-query.mjs`: D007 123조회 통과. `node scripts/check-screen-contract.mjs`: D003B 496개 모델 결과 동일.
- TypeScript·변경 파일 ESLint·Vite build 통과. 빌드의 기존 500KB 초과 청크 안내는 유지된다.
- 실제 브라우저: D007 41화면, 전체 배치 41화면을 이동했다. 전체 화면 KPI 합계 22,242, 미적합 합계 790, 빈 화면 0. D003B 리뷰72·D006 A 리뷰1·D006 B 리뷰20·D005 검색36을 개별 선택해 확인했다.
- 미적합 D006 광고11행에서 누락 필드와 원본 source_profile·원래 시간대 값을 확인했다. 실험 선택 후 해당 실험군 2행만 표시되며, 긴 차트의 다음 구간도 데이터가 바뀌는 것을 확인했다.

작업 전 변경 파일은 상위 `dashboard-design-history/2026-10-18-before-all-data/`에 보존했다. 기존 확정 명세·CSS·원천·Git 참조·커밋을 변경하지 않았다. 연결 조회본은 약 36.6MB이며 로컬에서 전체를 읽는다. 대용량 운영 배포용 서버 조회는 도입하지 않았다.
