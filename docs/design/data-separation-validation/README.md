# 화면 보존·데이터 분리·D007 연결 실행 기록

**현재 상태(2026-10-19): [업무별 집계·국가/제품 비교 개편](../marketing-redesign-20261019/README.md)을 반영했다. 새 D008은 화면 시나리오이며 기존 Agent는 D007 지원 상태다.**

**이전 연결 상태(2026-10-18 후속): [5배치·91파일·22,242행 전체 연결](all-data-connection.md)을 완료했다.** 기본 증강 화면, 신규 유형 시각화, 미적합 원문 조회를 포함한다. 아래 1–6절은 이전 2–5단계 실행 당시의 보존 기록이며 당시 제한을 현재 상태로 해석하지 않는다.

실행: 2026-10-17–18. 대상: `feature/workbench-evolution`, 시작·종료 HEAD `4d286c505e8ac659c1d839b257631ef7280f31d6`의 미커밋 작업. 새 발행 버전이나 Iteration을 만들지 않았다.

사용자 요청에 따라 기존 화면을 먼저 고정하고, 화면 계약 추출 → 로더·조회·표시 분리 → 최신 데이터 점검 → 검증된 표준화 데이터 연결을 순차 수행했다. 디자인·차트 색·글꼴·기존 피드백 결과를 보존했다. 원래 저장소의 생성기 실행, 원천 수정, 커밋·푸시·브랜치 변경은 수행하지 않았다.

## 1. 보존 기준

- 작업 전 사본: 상위 `dashboard-design-history/2026-10-17-before-data-separation/`. 소스·설계·승인/작업 기록과 baseline.json을 보존했다.
- 확정 명세 `marketing-workbench-spec.md` SHA-256: `891eac80d6be827a20ba229877db7ac5d578bd01edc13cfe8dd71c260335126a`. 원문을 수정하지 않았다.
- D003B 11파일·1,652행, 기존 화면의 496개 조회 결과를 [기준 파일](d003b-baseline.json)에 고정했다. 41유형 × 3국가 × 4개월과 추가 필터 4건이다. 분리 후 모델 전체의 직렬화 해시가 모두 같다.
- 기본 선택은 `D003B · 고정 화면`이다. `D007 · 표준화 증강`을 명시적으로 선택하며, 전환 실패 시 오류를 알리고 기존 선택을 유지한다.

## 2. 구현 경계

```text
D003B 보존 원천 → baseline-source → legacy-query ─┐
                                                ├→ contract(Model) → 차트·표·KPI·근거
D007 검증 카탈로그 → 해시 확인 → standard-query ──┘
                                              presentation: 표시·정렬·CSV
```

`frontend/workbench/contract.ts`에 `workbench-model/1`과 조회 옵션을 분리했다. `baseline-source.ts`는 기존 읽기, `legacy-query.ts`는 기존 계산, `values.ts`는 금액·비율 연산, `presentation.ts`는 표시·정렬·CSV를 담당한다. `adapter.ts`는 기존 호출을 유지하는 호환 입구이고, `screen-service.ts`가 조회·필터 메타데이터를 화면에 전달한다.

`standard-query.ts`는 D007 표준 레코드를 조회하고 같은 화면 계약으로 반환한다. 검토된 시장·리뷰·광고·매출 계산은 기존 계산 경로를 재사용하되 근거는 D007의 실제 표준 레코드로 복원한다. 화면이 표준 스키마의 관계를 직접 따라가거나 원천 T12에서 캠페인을 읽지 않도록 변경했다.

실시간 API·DB·RDF 서버는 도입하지 않았다. 공통 명세가 바뀌면 변환·검증과 `standard-query` 매핑을 점검하고, 화면 계약의 의미가 같으면 UI를 유지한다. 단위·분모·지표 의미가 바뀌면 호환되지 않는 계약 변경으로 검토한다.

## 3. 실제 데이터 범위와 고정 방법

원래 `marketing-agent-poc`의 공식 카탈로그로 22,242행을 읽기 점검했다. D003B 1,652, D005 534, D006-CQ-A 3, D006-CQ-B 53, D007 20,000행이다. 전체 중 공통 명세 적합이 아닌 기존 790행은 이번 D007 조회본에 포함하지 않았다. 배치·시나리오가 다르므로 합산하지 않는다.

D007은 40파일(T02–T40·H01), 20,000행 모두 명세 적합·contract gap 0이다. T01 제품 6개는 기존 D003B의 공통 식별자를 재사용한다. 이 6개를 신규 20,000행에 더해 보고하지 않는다. 원래 배치의 manifest·result 통과를 확인하고 공식 카탈로그 검증을 거쳐 가져왔다.

`scripts/import-standard-catalog.mjs`는 생성기를 호출하지 않고 기존 값만 복사한다. 파일이 있으면 덮어쓰지 않는다. 읽기 전후 원천 45파일의 SHA-256을 대조하며, 원천 파일·스키마·정의·카탈로그 코드의 해시와 재사용 배치 목록을 [고정 기록](catalog-audit.json)에 남긴다.

조회본은 `frontend/public/workbench-data/D007/`의 catalog.json·lock.json·schema.json이다. catalog.json SHA-256은 `4318b1bdfd8013a3bc58f55683ba1c53685bdbce11b4b94d3fd839b4a17727ad`이다. 브라우저는 D007 선택 시에만 JSON을 읽고 해시·행수·배치·시나리오·화면 계약을 검사한다. 약 29.6MB의 로컬 조회본이므로 대규모 운영 배포의 전송 최적화까지 완료한 상태는 아니다.

기본 조회 가능 시각은 원천 생성 시각 `2026-10-17T04:40:18.787Z`로 고정하고 근거 패널에서 확인할 수 있다. 관측 시각과 조회 가능 시각을 구분하며, 생성 이전 시점에 자료를 소급 노출하지 않는다. 없는 기간·값·감성·승인 이력을 채우지 않는다.

## 4. 연결 범위·해석 기준

| 범위 | 표시 및 분리 원칙 |
| --- | --- |
| 시장·리뷰·광고·매출 | 기존 KPI·차트·상세 표 유지, D007 근거 연결. 광고 월간/일간 집계 수준 분리 |
| 리뷰 | 국가별 600개·제품별 100개·자사 200개 표본. 별점과 감성을 동일시하지 않음 |
| T25 주석 | 승인된 모의 규칙 주석으로 표시. 인간/LLM 판정·시장 전체 감성으로 설명하지 않음 |
| 가격·재고 | 같은 관측일·국가·비교군에서 판매처별 관측을 유지. 가격을 판매처 간 임의 평균하지 않음 |
| 검색 지수·실험 | 정규화 범위·실험군별 행 유지. 독립 표본을 하나의 지수·효과로 합치지 않음 |
| 예산·정책 | 저장된 모형·정책 상태만 표시. 제안 상태를 실제 승인·집행으로 바꾸지 않음 |
| 나머지 신규 유형 | 명시적 유형별 필드와 단위를 매핑한 상세 표 우선 연결. 모든 유형의 전용 분석 차트를 새로 구현한 것은 아님 |

D005/D006은 목록·적합 상태만 점검했다. D007과 합치거나 자동으로 최신 데이터에 덮어쓰지 않았다. D003B에서 없는 유형은 전체 데이터 미생성 대신 ‘선택 배치 미연결’로 안내한다.

표준화 조회 검사는 시장 분모 중복 방지·점유율 합계, 원천 광고비·CTR/CVR/ROAS, H01 금액 차감, 리뷰 수·제품별 표본, 3판매처 유지, 주석 집계, 원문 발췌, 결측·조회 시각, 필터 결과 전체 CSV를 확인한다. 결과는 [기존 수치](d003b-numeric-checks.json), [표준 조회](standard-query-checks.json), [브라우저](browser-checks.json)에 있다.

브라우저에서 D007-T24 근거 ID·원천 100건·조회 시각을 확인했다. 가격 검색 후 주석 CSV는 페이지의 25행에 한정되지 않고 114행을 내보냈다. 한국 리뷰 600개·평균 3.6·2점 이하 20.5%, D003B 복귀 시 24개·3.3·25.0%를 확인했다. 390px 모바일에서 문서 너비 375px이며 KPI 넘침이 없었다.

초기 브라우저 검사에서 표가 표준 레코드에 없는 `product_id`를 읽는 문제와 제거한 `product()` 참조가 남아 있는 문제를 발견했다. 화면 계약의 이름 필드로 계층·강조를 판단하도록 수정하고 다시 41화면을 이동했다. 수정 후 검사 구간의 런타임 오류는 0이다. 개발 중 HMR에 남은 이전 서비스는 새로고침 후 재검사했다.
