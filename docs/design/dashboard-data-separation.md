# 데이터 처리와 대시보드 분리 — 더블 다이아몬드

작성일: 2026-10-16. 갱신일: 2026-10-19. 현재 상태: [업무별 요약·비교용 D008·화면 개편](marketing-redesign-20261019/README.md) 반영. 아래는 기존 분리 구조와 연결 과정의 보존 기록이다. 10월 18일 상태: 화면 계약·로더·조회·표시 분리 및 [5배치·22,242행 전체 연결](data-separation-validation/all-data-connection.md) 완료. 발행 버전·새 Iteration은 확정하지 않는다.

아래 Discover부터 Deliver까지는 10월 16일의 조사·제안 기록이다. 사용자가 증강 완료 후 현재 화면 보존과 후속 2–5단계 실행을 요청해 구현했다. 실제 범위·검증·남은 한계는 [실행 기록](data-separation-validation/README.md)을 기준으로 확인한다.

사용자는 표준화 데이터를 기준으로 조회·집계한 결과를 프론트에 전달하는 방향을 논의한 뒤, 분리 관련 다이아몬드 문서 작성을 요청했다. 이 문서는 현황·문제·대안·제안·수용 기준을 정리한다. 데이터 재생성·변환 실행·DB 도입·새 배치 연결 완료를 의미하지 않는다. 기존 확정 화면 명세와 원천은 보존한다.

## Discover — 실제 흐름과 사용자 문제

대시보드는 현재 `frontend/workbench/adapter.ts`에서 D003B JSONL을 직접 로드해 필터·참조 연결·집계·표시 형식을 처리한다. 결과인 `Model`을 차트·표·지표·근거 패널이 소비한다. 모든 데이터 처리가 온톨로지를 거친 상태는 아니다.

원래 checkout인 `marketing-agent-poc`에는 D003B 1,652행, D005 534행, D006 A/B 56행이 존재한다. 별도 대시보드 checkout에는 D003B만 있다. 파일 행수와 LF 정규화 SHA-256을 manifest와 대조했다. D005의 30유형528행과 지원 T01 6행을 구분하고, D006은 질문별 추가 검증 범위이므로 전체 기본 데이터에 자동 합산하지 않는다. 생성된 유형도 현 화면에서 미생성으로 표시되는 문제가 있다.

원래 checkout의 처리 계층은 원천 규격 검사, D005 프로필 정규화, 명시적 공통 명세 변환·검사, 메모리 RDF/제약/재조회·질문별 검산으로 나뉜다. 배치 내부 규격 통과와 전체 공통 명세 적합은 별도다. 다른 checkout에서 계속 개발 중이므로 과거 보고서 결과를 현재 전체 코드의 최신 적합 결과로 단정하지 않는다. 실제 데이터·외부 공급자 연결은 사용자 결정으로 범위 밖이다.

사용자 문제: 온톨로지·명세가 계속 바뀌더라도 대시보드 개발을 진행해야 한다. 원천 필드와 개념 이름이 UI까지 전파되면 수정 범위가 커지고, 별도 구현된 계산이 서로 달라질 수 있다.

## Define — 용어·경계·성공 기준

| 용어 | 이 문서의 의미 |
| --- | --- |
| 원천 데이터 | 배치별로 보존된 JSONL 값 |
| 데이터 명세 | 필드 의미·형식·단위·필수/조건부 조건·참조 규칙. 기존 문서의 공통사전 |
| 온톨로지 모델 | 제품·브랜드·관측 등 개념과 관계·추론 규칙 |
| 표준화 데이터 | 명시적 변환 후 선언한 데이터 명세의 검증을 통과한 값 |
| 화면용 데이터 계약 | 프론트에 전달할 값·단위·범위·품질·근거의 구조와 의미 |

부분 변환·검증 실패 결과를 표준화 완료로 부르지 않는다. UI는 원천 프로필 A/B/C나 RDF 관계 이름을 직접 해석하지 않는다. 계산 정의가 바뀌면 단순 필드명 변경과 구분한다. 클릭수와 유일 클릭자 수, 별점과 감성, 자사 표본과 시장 전수는 서로 대체하지 않는다.

성공 기준은 원천 구조 변경이 변환 계층 안에서 처리되고, 같은 의미의 조회 결과라면 UI 변경 없이 동작하는 것이다. 값·단위·기간·국가·분모·결측·근거가 기존 검증과 일치해야 한다. 의미가 달라지면 계약 변경이나 별도 지표로 드러나야 한다.

## Develop — 대안 비교와 제안

| 방안 | 장점 | 비용·위험 | 판단 |
| --- | --- | --- | --- |
| 원천 직접 집계 | 현재 코드 활용, 빠른 UI 개발 | 원천 결합·계산 중복 | 기존 화면의 한시적 호환 경로 |
| 표준화 데이터 직접 UI 연결 | 원천 차이 축소 | UI가 명세 구조에 결합 | 중간 경계로만 사용 |
| 조회·집계와 화면 계약 분리 | 모델/UI 독립 개발·계산 재사용 | 명시적 계약과 대조 필요 | 기본 제안 |
| 화면별 그래프 직접 조회 | 관계 탐색에 유리 | 모델 변경·쿼리 관리 부담 | 필요한 조회 함수 내부에 한정 |

제안 흐름:

```text
보존 원천 → 배치별 해독·명세 변환 → 검증된 표준화 데이터
                                    ↓
                              조회·집계 함수
                                    ↓
                              화면용 데이터 계약
                                    ↓
                              KPI·차트·표·근거
```

온톨로지 관계 조회가 필요하면 조회·집계 함수 내부에서 사용한다. 프론트가 직접 그래프 구조를 따라가지 않는다. 초기에는 로컬 실행으로 생성한 화면용 JSON 묶음과 검증 결과로 충분하며, 서버·그래프 DB·이벤트 버스는 도입하지 않는다. 필터에 필요한 세부 집계 수준을 유지하고, 비율은 합산용 분자·분모 또는 정의된 조회 함수를 통해 계산한다.

기존 `Model`을 출발점으로 원천 읽기, 지표 계산, 화면 계약을 분리한다. 과도한 범용 엔진이나 40유형 동시 이행은 피한다. 계약에는 값, 단위/통화, 대상/기간/집계 수준, 지표 정의, 품질·불완전 상태, 사용 원천 ID를 포함한다. 화면은 레이아웃·표시 형식·정렬·페이지·상호작용을 담당한다.

원천 폴더와 manifest는 유지한다. 표준화 결과와 화면용 결과는 원천과 다른 경로에 두고 원천 배치·해시, 명세/모델, 변환, 집계, 화면 계약의 리비전을 기록한다. 검증한 조합을 명시적으로 선택하며 다른 checkout의 최신 파일을 자동 참조하지 않는다. 작업 수정은 Git 커밋, 새 원천은 배치 ID, 호환되지 않는 의미/형식 변경은 계약 버전, 정식 발행은 사용자와 확정한 버전으로 구분한다.

기존 D003B 직접 집계를 당장 제거하지 않는다. 동일 화면 계약을 내보내는 호환 경로로 명시하고, 표준화 경로를 검증한 유형부터 교체한다. 부족한 유형은 생성됨·매핑 대기/자료 부족으로 구분한다. 검증 실패 시 raw로 몰래 되돌아가거나 기본값으로 채우지 않는다.

## Deliver — 이행 순서와 수용 기준

1. 현재 화면용 `Model`과 지표 정의를 추출하고 기존 수치·원천 범위를 고정한다.
2. D003B 로더·집계·표시를 분리하고 기존 결과와 대조한다. 이 단계는 온톨로지 연결 완료가 아니다.
3. 검증한 유형부터 표준화 입력으로 교체하고 배치 중복·동일 ID·정정판·국가/통화 혼입을 검사한다.
4. D005/D006의 범위·검증·매핑 상태를 확인해 명시적으로 선택한다. 별도 승인 없는 생성·보완은 하지 않는다.
5. 기존 입력 경로와 새 경로의 수치·결측·근거를 대조하고 대표 화면·필터·CSV·패널을 브라우저에서 검증한다.

| 수용 항목 | 확인 방법 |
| --- | --- |
| 원천 보존 | 파일 건수·SHA-256 전후 일치 |
| 집계 의미 | 시장 분모 중복 없음, 국가·통화·기간 분리, 광고 비율 분자/분모 대조 |
| 결측·부족 | null·미관측·미생성·매핑 대기를 구분하며 0으로 대체하지 않음 |
| 근거 계보 | 집계→사용 레코드→원천 필드·계산 정의 추적 |
| 호환성 | 원천 필드 변경이 UI로 전파되지 않고 의미 변경은 명시적으로 거부/변경 |
| 버전 선택 | 동일 입력/리비전 조합 재실행 결과 일치, 이전 검증 조합 재선택 가능 |

현재 Deliver 결과는 이 문서와 대시보드 발전 과정의 커밋 정리다. 위 코드 분리·표준화 연결·새 계약 검증은 미구현이며 완료로 표시하지 않는다. 새 Iteration·발행 버전·dev 병합·푸시·태그는 이번 요청에서 수행하지 않는다.
