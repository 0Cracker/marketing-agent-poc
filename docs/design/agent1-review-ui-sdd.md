# Agent1 리뷰 분석 UI/UX SDD

## 2026-11-05 화면 주석 후속 결정

- 분포 그래프의 대분류 행을 누르면 해당 세분류 그래프로 이동한다. 대분류 전체 버튼으로 복귀하며 판매처, 작성일, 정렬을 유지한다. 반복된 세부 분류 보기 줄은 제거한다. 원문 필터는 하단 카테고리 선택으로 제공한다.
- 판매처와 카테고리 필터, 기간과 보기 전환 등 유사한 선택 UI는 frontend/components/ui/selection-button.tsx의 SelectionButton을 재사용한다. 기존 Button을 기반으로 하며 모서리는 공통 --selection-control-radius 값 8px을 사용한다. aria-pressed, disabled, ref와 일반 버튼 속성을 전달할 수 있다.
- 같은 성격의 캠페인 탐색 모드와 AI 답변의 그래프/표 전환도 이 컴포넌트를 사용한다. 리뷰 카테고리 배지도 같은 모서리 값을 쓴다.
- 리뷰 원문은 두 줄 안에 모두 보이면 더 보기 버튼을 표시하지 않는다. 실제 줄 넘침 또는 검색 문맥 생략이 있으면 펼침을 제공하고, 창 너비와 폰트 변경에 따라 다시 측정한다.
- 리뷰 원문을 원문 확인보다 앞에 둔다. 원문 확인은 마지막 열이다.

## 1. 목적, 우선순위, 범위

- **최신 UI 행동의 우선순위:** 2026-11-03 사용자가 재확정한 **C01 왼쪽, C02~C32 오른쪽** > UI/UX 인터뷰 1~66 > 과거 UI SDD/HTML 시안. 특히 **화면 배치(C01)는 기존 성과 현황의 ROAS 아래 리뷰 섹션**이며, 인터뷰 66은 B안(가로 스크롤 시 고정 열 없음)이다. 상충하는 별도 리뷰 탭 지시는 무효다.
- **데이터의 의미와 품질:** [Agent1 Intent](agent1-intent.md), [리뷰 데이터 SDD](agent1-review-data-sdd.md), [데이터 승인 기록](../research/marketing-ontology/data-proposal.md)의 범위를 유지한다. UI 결정만으로 신규 스키마나 신규 리뷰 생성을 승인하지 않는다.
- 사용자는 마케터이며, 대시보드는 **리뷰 분류를 조회하고 원문을 검증**하는 읽기 전용 도구다. 분석의 해석은 사용자에게 맡긴다. ROAS와 리뷰 사이의 원인, 귀속, 상관관계를 자동 판정하거나 설명하지 않는다.
- 리뷰는 **상품 1, EDU-P1** 전용이며 별도의 상품 선택기를 만들지 않는다. 다른 상품의 기존 ROAS 데이터 및 탐색은 유지한다. 공통 품목의 구체 표시명은 데이터 SDD에서 승인된 상품 메타데이터를 사용한다.
- 모든 사례(S01~S18)의 리뷰 자료 제공 여부를 구분한다. 현재 데이터 SDD의 **예정된** 범위는 S16/S17의 상품 1 리뷰 각 24건, 총 48건, 나머지는 미제공이다. 48건은 **생성 및 검산 완료된 실데이터라고 간주하지 않는다**.
- 리뷰 검색, 판매처, 작성일, 분류, 원문 열람 외에 **분류 편집/저장, 수기 오류 수정, 별도 상품 선택, Agent1 자동 해석, 리뷰와 주문/캠페인/고객 연결**은 범위 밖이다.
- 과거 Intent의 분석 적합성 A(같은 측면의 상반 경험), B(전체와 판매처별 변화 방향 차이), C(작성, 수집, 보고의 시간적 선후)는 **데이터 검수 목표로 계속 유효**하다. 다만 화면에 이전 방식의 두 기간 대조표와 경험 비교 패널을 강제로 복원하지 않는다. 최신 화면만으로 A/B/C를 사용자가 충분히 검증할 수 있는지는 §12의 남은 인수 쟁점이다.

## 2. 화면 배치와 기본 레이아웃

### 2.1 성과 화면 진입

- **기존 `성과 현황` 화면 안에서 ROAS 분석 및 전체 지표 영역 아래에 `리뷰 분석, 상품 1` 섹션을 추가한다(C01 왼쪽 확정).** 별도의 ROAS/리뷰 탭, 새 라우트, 독립 메뉴를 만들지 않는다. 기존 ROAS 구성과 순서를 유지하며 리뷰 부분만 하단에 덧붙인다.
- 기존 ROAS 표, 수치, 필터, 정렬, 펼침, 스크롤, 다른 상품의 정보에 영향을 주지 않는다. **ROAS 필터와 리뷰 필터의 집계 범위는 독립적이되, 이를 설명하는 안내문을 화면에 항상 고정 노출하지 않는다(C05, 최신 오른쪽안 채택).** 필요한 정보는 접근 가능한 기존 도움말/범위 설명 패턴으로 확인할 수 있어야 한다.
- 리뷰 화면의 고정 세로 순서: **요약 카드 → 카테고리 분포 → 리뷰 원문 테이블**. 필터는 각 영역의 정해진 위치에 배치한다.
- 리뷰 섹션 상단에는 **현재 선택 사례와 그 사례의 리뷰 제공 상태만 표시한다(C04 오른쪽 확정).** S01~S18 전체 사례의 제공 현황 목록이나 상시 범위 안내는 추가하지 않는다. 사례 변경 시 새 사례의 상태로 갱신한다. 원문 수만으로 미제공을 추정하지 않고 유효한 coverage/사례 카탈로그를 기준으로 미제공, 0건, 오류를 구분한다. 현재 예정된 제공 대상은 S16/S17이지만 자료가 확인되지 않은 상태에서 성공 표시를 하지 않는다.

### 2.2 요약 카드, 정확히 3개

1. **전체 리뷰 수:** 현재 판매처와 작성일 필터에 일치하는 서로 다른 리뷰 ID 수, `N건`.
2. **평균 평점:** 같은 집합에서 유효한 평점만 대상으로 평균을 계산한다. 평점이 전부 없으면 `—`. 0점을 누락값의 대용으로 사용하지 않는다.
3. **최다 언급 카테고리:** 동일 집합의 카테고리별 언급 리뷰 수로 선정한다. 동률이면 공동 1위 모두 인정하고 **2개까지만 직접 표시, 나머지는 `+N`으로 접어 표시**한다. 분류 결과가 없다면 `—`로 표시한다.

- 세 카드는 나란히 배치하되 기존 디자인 시스템의 카드 형식을 따른다.
- **분류 완료율, 긍정/부정 2분법, 자동 평가, 증감 분석 KPI**는 추가하지 않는다.
- 카테고리 필터 및 키워드 검색은 세 카드의 수치에 영향을 주지 않는다.

### 2.3 필터 위치

- **판매처, 리뷰 작성일**: 카테고리 그래프 위에 배치하며 요약 카드, 그래프, 원문 테이블에 공통 적용한다.
- **분류 카테고리**: 리뷰 원문 테이블 바로 위에 배치하며 **원문 테이블에만 적용**한다. 그래프 막대 클릭과 동일한 선택 상태를 사용한다.
- **리뷰 원문 검색**: 리뷰 원문 테이블 영역에 배치하며 **원문 테이블에만 적용**한다.
- 필터 변경은 적용 버튼 없이 즉시 반영한다. 키워드 검색만 입력 디바운스를 적용한다.

## 3. 필터, 상태 및 초기화

### 3.1 판매처

- 데이터에서 확인된 판매처를 선택지로 제공하는 **다중 선택**이다. 기본값은 `전체 판매처`.
- 여러 개 선택 시 **OR** 조건이고, 리뷰 ID당 한 번만 집계 및 표시한다.
- 판매처를 하나씩 비교하기 위한 별도 병렬 패널은 추가하지 않는다.

### 3.2 작성일, PoC 고정 14일 구간 (2026-11-03 사용자 최신 결정)

- 기간 선택지는 **비교기간 14일(`baseline`), 분석기간 14일(`current`), 두 기간 전체(`both`)** 세 가지다. **최근 7/30/90일, 임의 날짜 지정, 오늘 기준 상대 기간 선택은 제공하지 않는다.**
- 최초 선택과 전체 필터 초기화 후 기본값은 **분석기간 14일**이다. 기본은 기존 데이터 SDD의 원문 목록 제안을 따르되, 두 기간 전체를 선택해 총 28일의 제공 원문을 탐색할 수 있다. **두 기간 전체는 독립적인 14일 비교 구간이 아니라 비교기간과 분석기간의 합집합**이다.
- 각 14일의 실제 시작일/종료일은 현행 ROAS 사례의 기간 정의를 참조한다. 현재 S16/S17의 기준: 비교기간 **2026-08-03~08-16**, 분석기간 **2026-08-17~08-30**(날짜 표시의 양 끝 포함, 원천 시각 범위는 시작 포함, 다음 날 00:00 미포함).
- 필터 판정은 오직 리뷰 **작성일(`writtenAt`)**을 사용하고, **수집일(`collectedAt`)은 보고 기준 적격성** 검증에만 사용한다. 작성일 결측의 방어적 UI 표시는 유지하되, 어느 14일 구간에 속하는지 확인할 수 없으면 **선택한 모든 구간에서 제외**한다. 원시 필수 작성일 조건을 완화하거나 없는 날짜를 생성하지 않는다.
- 판매처와 기간 선택은 3개 요약 카드, 카테고리 그래프, 원문 테이블에 공통 적용한다. **기간을 전환하여 비교**하되 기존 인터뷰에 없는 별도 기간 비교표/추세 카드나 자동 평가를 추가하지 않는다.
- 현재 두 기간 밖의 임의 날짜 검색이나 자료 확장은 하지 않는다. 두 기간에 대한 실제 리뷰가 없으면 데이터 제공 여부와 필터 결과 0건을 구분한다.

### 3.3 카테고리

- 다중 선택, **OR** 조건. 선택값에 해당하는 리뷰가 하나라도 일치하면 테이블에 포함한다. 한 리뷰가 복수 항목에 걸쳐도 한 행만 표시한다.
- 카테고리 목록의 구분선 아래에 **`미분류`** 선택지를 별도 제공한다. `미분류`는 실제 분석 카테고리가 아니라 분류 상태이며, **정상적으로 분류되지 않았음이 검증된 데이터**만 해당한다. 분류 오류나 검수 보류를 미분류로 둔갑시키지 않는다.
- 선택된 카테고리와 미분류는 테이블 위 제거 가능한 필터 칩으로 표시한다.
- 그래프 막대 클릭은 기존 선택에 해당 항목을 **추가하거나 해제(toggle)** 한다. 선택이 모두 해제되면 카테고리 필터 없는 전체 리뷰 결과를 표시한다.
- 카테고리 필터로 결과가 0건이어도 선택을 유지하고 `조건에 맞는 리뷰가 없습니다`를 표시한다. 자동 해제하지 않는다.

### 3.4 초기화 및 상태 전이

- **`전체 필터 초기화` 버튼 하나**를 제공한다. 판매처=전체, 작성일 구간=**분석기간 14일**, 카테고리 선택 해제, **검색어 삭제**를 한 번에 처리한다. 검색어만 지우려면 검색창의 ×를 사용한다.
- 판매처, 작성일, 카테고리, 검색어 변경, 정렬 변경, 페이지당 건수 변경, 전체 초기화 시 **1페이지로 이동하고 펼친 리뷰 원문을 모두 접는다**.
- 페이지 이동 시 펼친 리뷰 원문을 모두 접고, 이전 페이지로 돌아와도 접힌 상태다.
- **별도 ROAS/리뷰 탭은 없다(C01).** 동일 사례의 같은 성과 현황 화면에서 ROAS 섹션과 리뷰 섹션을 스크롤하여 오가더라도 리뷰 필터, 페이지, 정렬 상태를 유지한다. 단순 스크롤만으로 원문 펼침 상태를 초기화하지 않는다. 인터뷰 45의 탭 복귀 시 원문 접기 규칙은 탭 전환이 없어 **적용 대상이 없다**.
- **사례 자체를 변경**하면 필터, 검색어, 정렬, 페이지, 페이지당 건수, 그래프 펼침을 포함한 리뷰 탐색 상태를 초기 기본값으로 되돌린다. 이전 사례 데이터를 새 사례 이름으로 잠시 표시하지 않는다.

## 4. 카테고리 분포 그래프

- **가로 막대그래프**. 카테고리별로 **언급한 고유 리뷰 건수**와 **전체 리뷰 대비 비율**을 함께 보여준다.
- 분모는 **현재 판매처와 작성일 필터에 해당하는 전체 고유 리뷰 수 N**, 분자는 해당 상위 카테고리가 지정된 서로 다른 리뷰 ID 수 n이다. 표시 비율 = `100 × n / N`. 동일 리뷰가 여러 카테고리에 속하면 범주별로 각각 집계하므로 **비율 합계는 100%를 초과할 수 있다**. 이 사실을 그래프에 설명한다.
- 막대의 **수평 축은 항상 0~100% 고정**이다. 필터 변경이나 정렬 변경 시 축을 최댓값에 맞춰 확대하지 않는다.
- 그래프의 모든 카테고리 막대는 기존 디자인 시스템의 **동일한 강조색**을 사용한다. 선택 상태는 체크/윤곽 등 별도 시각적 표시로 구별하며, ROAS의 개선/악화 의미 색상을 전용하지 않는다.
- **기본 5개**만 표시하고 `전체 보기`로 모든 카테고리를 펼칠 수 있다. `접기`는 기본 5개 보기로 돌아간다.
- 정렬 옵션은 **언급 많은순(기본), 언급 적은순, 가나다순**이다. 언급 건수가 같으면 가나다순으로 결정적으로 정렬한다. 선택한 정렬의 앞 5개가 기본 노출 대상이다.
- 테이블 드롭다운 등에서 선택한 카테고리가 **현재 그래프 상위 5개에 없으면 자동으로 전체 보기**로 전환한다. 사용자가 이후 직접 접을 수 있다.
- 막대 클릭은 §3.3의 카테고리 필터를 추가/해제한다. 그래프와 테이블 필터가 양방향으로 동기화된다.
- **카테고리 선택과 키워드 검색은 그래프의 데이터 집합을 축소하지 않는다**. 판매처와 작성일만 그래프 집계에 반영한다.
- `미분류`는 실제 카테고리 막대로 그리지 않으며 드롭다운 필터에서만 선택한다. 카테고리 자체가 없는 집합은 설명 가능한 빈 그래프 상태로 표시한다.
- N=0일 때 **0%라는 계산 결과를 임의로 만들지 않는다**. 그래프는 빈 결과 메시지를 표시하고 수치가 계산 불가능함을 유지한다.

## 5. 리뷰 원문 테이블

### 5.1 열 구성

| 순서 | 열 제목 | 테이블 기준 너비 | 기능 |
| --- | --- | ---: | --- |
| 1 | 판매처 | 12% | 헤더 클릭 정렬 |
| 2 | 작성일 | 12% | 헤더 클릭 정렬 |
| 3 | 평점 | 8% | 헤더 클릭 정렬 |
| 4 | 분류 카테고리 | 32% | 복수 카테고리 칩, `+N` |
| 5 | 원문 확인 | 9% | 원본 링크 |
| 6 | 리뷰 원문 | 27% | 두 줄 미리보기, 펼침/접기 |

- 테이블 제목 옆에 **카테고리, 검색어까지 모두 적용한 조회 결과 건수**를 `리뷰 원문 128건` 형태로 표시한다. 요약 카드의 `전체 리뷰 수`와 다를 수 있다.
- 기본 정렬은 **작성일 최신순**. 정렬 가능한 열은 작성일, 평점, 판매처뿐이다. 분류 카테고리, 원문 확인, 리뷰 원문은 헤더 정렬하지 않는다.
- 동일 정렬값의 순서는 안정된 리뷰 ID 등의 고정 키를 보조 기준으로 사용한다. **평점 누락, 작성일 누락은 오름차순과 내림차순에서 항상 맨 아래**다. **리뷰 ID를 보여주는 별도 상세 화면이나 ID 상시 노출 UI는 이번 범위에 추가하지 않는다(C32, 최신 오른쪽안 채택).** ID는 데이터 결합, 고유 건수 검산, 테스트 근거로 내부에서 보존한다.
- **평점이 없는 셀, 작성일이 없는 셀은 `—`**로 표시한다. 누락 평점을 0점으로 해석하지 않는다.
- 해당 리뷰에 분류 카테고리가 하나도 없고 유효한 미분류 상태로 확인되면 중립색 **`미분류` 칩**으로 보여준다. 단순 분류 조회 실패는 이 상태로 표기하지 않는다.
- 카테고리 칩은 **최대 3개** 노출, 4개 이상이면 `+N`으로 나머지 개수 표시. `+N` 클릭 시 **해당 셀 내부에서 전체 카테고리를 펼치고**, `접기`로 되돌린다. 팝오버를 사용하지 않는다. 카테고리 펼침과 원문 펼침은 독립적이다.
- 원문 URL이 확인되면 `원문 보기`와 외부 링크 아이콘을 표시하여 **새 탭**으로 연다. 안전한 외부 링크 속성을 사용한다. URL이 없으면 `링크 없음`. URL 존재만으로 외부 페이지 접근 성공을 보증하지 않는다.
- 리뷰 텍스트가 없더라도 리뷰 행은 유지하고 원문 셀에 **`원문 없음`**으로 표시한다. 해당 원문 셀은 펼치지 않으며 원문 URL이 있다면 원본 링크는 별도로 유지한다.
- 분류, 링크, 원문이 전부 확인되지 않더라도 제공 여부나 유효한 리뷰 ID를 임의로 만들어 결측을 보완하지 않는다.

### 5.2 원문 펼침/접기

- 원문은 기본적으로 **2줄 미리보기**를 보여준다.
- **`리뷰 원문` 셀 전체가 클릭 영역**이다(셀의 여백 포함). 셀 클릭 또는 같은 셀의 `더 보기/접기`로 원문을 **같은 셀 안에서** 펼치고 접는다. **행 전체 클릭은 금지**한다.
- **여러 행의 원문을 동시에 펼칠 수 있다.** 각 행은 독립적으로 접힌다. 전역 아코디언이나 별도 `전체 접기` 버튼을 필수로 만들지 않는다.
- 원문을 펼치면 생략 없이 원래 순서대로 전체 텍스트를 표시한다. 링크/카테고리 셀 클릭이 원문 펼침을 일으켜서는 안 된다.
- 필터, 검색, 정렬, 페이지당 건수 및 페이지 변경, 사례 변경, 탭 복귀에 따른 원문 펼침 초기화는 §3.4를 따른다.

### 5.3 페이지네이션

- 기본 **20건/페이지**, 사용자가 **10, 20, 50건** 중 선택 가능하다.
- `이전`, `다음`, **페이지 번호 직접 선택**을 제공한다. 기본 페이지는 1페이지다.
- 필터/검색/정렬 변경 시 1페이지로 돌아간다. 페이지 크기 변경도 1페이지에서 시작한다.
- 결과 0건이면 0건 상태를 보여주며 유효하지 않은 페이지 번호를 생성하지 않는다. 중복 카테고리가 있는 리뷰도 한 번만 페이지네이션에 반영한다.

## 6. 리뷰 원문 키워드 검색

- 원문 텍스트에 대해 **사용자 입력 문구가 순서대로 연속해 포함되는 부분 문자열 검색**을 수행한다. 단어별 AND나 OR 검색, 카테고리 이름 검색은 기본 기능이 아니다.
- 영어 대소문자는 구분하지 않고 **검색어 앞뒤 공백을 제거**한다. 중간 공백은 입력된 구문의 일부로 취급한다.
- 입력 후 약 **300ms 동안 변경이 없으면 자동 적용**한다. **Enter**를 누르면 즉시 적용한다. 검색 버튼 클릭을 강제하지 않는다.
- 검색은 **원문 테이블만** 필터링하며, 요약 카드/카테고리 그래프의 집계를 바꾸지 않는다. 판매처, 작성일, 카테고리 필터와 함께 적용된다.
- 결과는 테이블 제목 옆 건수에 반영한다. 검색이 실제 적용되면 1페이지로 돌아가며 펼친 원문은 모두 접힌다.
- 일치 문구가 기본 첫 2줄에 없으면, 접힌 셀에는 **첫 일치 문구 주변의 2줄 분량**을 보여준다. 검색어 삭제 후에는 원래 원문의 시작 부분 2줄로 돌아간다.
- 일치하는 문구가 한 리뷰에 여러 번 있으면 **모든 위치를 강조**한다. 펼친 원문 전체에서도 전부 강조한다. 검색어 강조는 표시일 뿐 원본 텍스트를 변경하지 않는다.
- 검색 결과가 없으면 필터 및 검색어를 유지한 채 **빈 결과 안내**를 표시한다. 검색어 삭제는 검색창의 × 또는 전체 필터 초기화로 수행한다.
- 강조는 안전한 텍스트 렌더링을 사용한다. 사용자 입력이나 리뷰 원문을 임의 HTML로 삽입하지 않는다.

## 7. 수집일, 보고 기준 및 데이터 해석

- **작성일**은 리뷰 기간 필터, 시간적 비교와 테이블 정렬에 사용한다.
- **수집일**은 자료를 실제 확보한 시점과 ROAS 보고 기준(asOf) 적격성 검증에 사용한다. 작성일로 대체하지 않으며, 수집일을 리뷰 작성일이나 제품 사용일, 구매일이라고 설명하지 않는다.
- 데이터 SDD의 현재 원천 제안은 오프셋을 포함하는 ISO 8601 작성시각 `writtenAt`, 수집시각 `collectedAt`, 보고 기준 `asOf`를 사용한다. 승인된 데이터 계약이 요구하는 `writtenAt ≤ collectedAt < asOf` 같은 경계 검사를 **임의로 약화하지 않는다**.
- 리뷰 원문 **테이블 하단**에 `전체 데이터 수집 기간: YYYY.MM.DD ~ YYYY.MM.DD`을 표시한다. 기간은 **현재 사례, 상품 1의 현재 보고 기준에서 유효하게 확보된 전체 리뷰 원천**을 대상으로 한다. 판매처, 작성일, 카테고리, 검색어 필터를 바꿔도 **해당 전체 수집 기간을 고정 유지**한다.
- 제공된 데이터에서 수집일을 확인할 수 없으면 `수집일 확인 불가`로 표시한다. 미제공 사례의 전용 안내 화면에 수집 기간을 가짜로 표시하지 않는다.
- 수집일은 본 테이블의 6개 컬럼에 추가하지 않는다. 데이터의 원본 시간 정보는 검증 및 필요시 후속 데이터 조회 계약에서 보존한다.
- 자료가 합성 교육용 표본이라면 실측 고객 리뷰, 대표 표본, 통계적 인과 분석처럼 표현하지 않는다.

| 상태 | 판정 | UI 및 동작 |
| --- | --- | --- |
| **리뷰 자료 미제공** | 현재 사례의 상품 1에 제공 선언 자체가 없음 | **리뷰 섹션 유지**, 요약/그래프/테이블 대신 `이 사례에는 상품 1 리뷰 분석 자료가 없습니다` 전용 안내. `0건`이라고 표시하지 않음 |

| **필터 결과 0건** | 제공된 리뷰 중 현재 필터 조합에 일치하는 원문이 없음 | 선택한 필터를 유지, 테이블 제목 `0건`, 빈 결과 안내. 카테고리/검색만 적용한 경우 상단 카드/그래프는 불변 |
| **전체 조회 오류** | 리뷰 자료 조회/검증 자체를 완료하지 못함 | 데이터 미제공/0건으로 바꾸지 않고 **전용 오류 화면**, `리뷰 데이터를 불러오지 못했습니다`, `다시 시도` |
| **부분 조회 오류** | 일부 리뷰만 처리 불가하고 나머지는 유효함 | **정상 리뷰를 계속 표시**하고 화면 상단에 부분 오류 안내. 요약/그래프/테이블은 처리에 성공한 리뷰만으로 계산, 불완전한 집계임을 명시. 전체 건수와 오류 건수는 실제 검증 가능한 경우에만 표시 |
| **분류만 오류 또는 미승인** | 원문을 조회할 수 있지만 분류 연결을 신뢰할 수 없음 | 원문 열람을 가능한 범위에서 유지, 잘못된 카테고리 수치/미분류 건수를 생성하지 않음. 분류 결과에 문제가 있음을 표시하고 분류 부분만 재시도 가능할 때 그 범위로 제한 |
| **로딩** | 데이터 요청 중 | 선택한 사례의 식별 정보와 로딩 상태를 표시, 이전 사례의 수치를 새 사례 아래 섞어 표시하지 않음 |

- 모든 오류 상태는 같은 화면의 **기존 ROAS 영역에 전파하지 않는다**. `다시 시도`는 실패한 리뷰 조회를 다시 수행하며, 성공을 보장하는 버튼이 아니다.
- 원문이 없는 정상 레코드는 §5.1의 `원문 없음`으로 표시한다. **실제 파싱/계약 오류**가 원인인 결측은 검증된 부분 오류 수에 반영해야 하며, 근거 없는 자동 복구나 누락값 생성은 금지한다.
- 검증되지 않은 분류나 대기 상태를 `미분류`로 합산하지 않는다.
- 사례/보고 기준을 연속 변경한 경우 늦게 도착한 이전 요청 결과가 최신 화면 상태를 덮지 않도록 한다.

## 9. 좁은 화면, 키보드 접근성

- 좁은 화면에서도 **6개 열과 동일한 순서**를 유지한다. 셀을 과도하게 줄이지 않도록 테이블 최소 너비를 제공하며, 테이블 내부에 **가로 스크롤**을 허용한다.
- 가로 스크롤 시 **고정 열(sticky column)은 사용하지 않는다(인터뷰 66 B안)**. 판매처 및 작성일도 다른 열과 함께 스크롤한다.
- 좁은 화면에 관한 추가 디자인 인터뷰는 진행하지 않는다. 이 절은 이미 확정된 65, 66번의 동작만 명세한다.
- 테이블 헤더 정렬, 원문 셀 펼침, 카테고리 `+N`, 필터, 검색, 재시도, 페이지 이동은 키보드로 작동해야 한다. 클릭 영역 전체의 동작은 적절한 접근 가능 컨트롤/이벤트로 구현한다.
- 표의 제목/머리글, 필터 레이블, 확대 상태(`aria-expanded`), 오류/조회 건수의 상태 알림, 스크린리더 이름을 명확하게 제공한다. 원문 확인 외부 링크에는 새 탭 동작을 알린다.
- 색상만으로 강조 또는 선택 여부를 전달하지 않으며, 기존 대시보드 디자인 시스템의 대비 및 포커스 스타일을 따른다. 좁은 화면 외의 UI 스타일을 새로 만들기 전에 기존 컴포넌트/토큰을 확인한다.

## 10. 데이터 SDD와 읽기 전용 인터페이스 경계

이 절은 **필요한 의미**를 명세하는 것이며 데이터 파일, 테이블, API의 신규 스키마를 승인하는 규격이 아니다.

| 데이터 항목 | UI 요구 | 현재 계약 상태 및 주의점 |
| --- | --- | --- |
| 사례, 상품, 제공 여부 | S01~S18별 제공/미제공/제공된 0건/오류, 상품 1 한정 | 데이터 SDD의 coverage 및 전체 사례 제공 상태 확인 필요. 원문 수만으로 미제공을 추정 금지 |
| 원문 | 안정된 리뷰 ID, 판매처 표시명, 작성일, 수집일, 평점, 원문 텍스트, 선택적 외부 링크 | 원문 파일의 실제 생성/검산 및 URL 필드 계약 검토 필요. 원문 없음/평점 없음/작성일 없음 UI는 **방어적 표시**이며 데이터 생성 규칙을 변경하지 않음 |
| 복수 카테고리 | 리뷰 ID별 상위 카테고리 식별자/표시명 0개 이상 | 승인된 분류 저장소와 원문 ID 참조 검증 필요 |
| 미분류 | 명시적으로 검수된 미분류 상태 | 대기, 오류, 미검수와 구별되는 상태 계약 필요 |
| 분류 검수 | 분류 버전 및 완결성/오류 상태 | 분류 누락 시 임의 추론 금지, 오류 안내 필요 |
| 기간 조회 | **비교기간 14일, 분석기간 14일, 두 기간 전체** 및 수집일 보고 적격성 | 현행 ROAS 사례의 `baseline/current` 경계를 참조해 실제 제공된 원문을 필터링. 기간을 임의 확장하거나 데이터 생성 금지 |
| 원문 URL | 있다면 `원문 보기`, 없다면 `링크 없음` | 현행 원천 필드에 없는 경우 신규 필드 추가는 별도 승인. 임의 URL 생성 금지 |
| 상품 공통 메타데이터 | 모든 사례의 EDU-P1 품목 의미 일관성 | 데이터 SDD의 별도 공통 메타데이터 파일/필드 승인 대기 |

- 표본 N과 카테고리 n은 **리뷰 ID 기준 중복 제거**한 개수이다. 판매처, 날짜, 카테고리의 결합에서 중복 카운트를 허용하지 않는다.
- 리뷰 건수와 평균 평점 계산은 **평점 누락 여부를 분리**한다. 평균 평점은 유효 평점만 분모로 사용한다.
- 분류 검수나 분류 오류 수정은 **별도 데이터 검수 과정**에서 처리한다. UI에 저장/수정 버튼을 만들지 않는다.
- 가용성/분류/원문 계약이 승인되기 전에는 실제 데이터가 준비된 것처럼 표시하지 않는다. 구조만 먼저 구현할 수 있더라도 더미 데이터를 승인된 실데이터로 혼동시키지 않는다.

## 11. 구현 권장 분리 및 인수 검증

### 11.1 구현 순서

1. 기존 `성과 현황`의 ROAS 분석과 전체 지표 영역을 보존하고 그 **아래에 리뷰 분석 섹션을 추가한다(C01)**. 신규 탭은 만들지 않는다.
2. 승인된 데이터 계약과 분리된 **표시 컴포넌트**로 요약 3종, 카테고리 그래프, 원문 테이블 및 상태 화면을 만든다.
3. 리뷰 선택자/집계와 UI 상태를 분리하여 필터, 검색, 정렬, 페이지네이션을 구현한다.
4. 데이터 SDD와 원천이 실제 승인되면 읽기 전용 조회 계약을 연결한다.
5. ROAS 회귀 테스트, UI 상태 테스트, 데이터 경계/집계 테스트와 키보드 접근성을 확인한다.

**데이터 스키마 변경 또는 새 가상 리뷰 데이터 생성은 목적, 범위, 생성 규칙, 검산 계획을 제시해 명시적으로 승인받은 뒤 별도 실행한다.**

## 12. 기존 문서와의 충돌 및 아직 남은 계약 문제

### 12.1 폐기한 구형 **UI** 지시

| 이전 UI/UX SDD의 구형 내용 | 최신 확정 결정 | 상태 |
| --- | --- | --- |
| ROAS 화면 내 리뷰 섹션 배치 vs 별도 탭 | **C01 왼쪽: 기존 ROAS 영역 아래 리뷰 섹션 추가** | **별도 탭 설계 폐기, 하단 리뷰 섹션 유효** |
| 판매처/기간별 대조표와 세부 경험 비교 패널을 기본 중심 구조로 배치 | **3개 요약 카드 → 가로 카테고리 그래프 → 6열 원문 테이블** | 구형 기본 구조 폐기 |
| 자유 키워드 검색 제외 | **원문 문구 검색과 검색어 강조 제공** | 구형 제외 지시 폐기 |
| 기간 UX의 한때 확정된 상대일/임의일 필터 | **비교기간 14일, 분석기간 14일, 두 기간 전체** | 사용자 최신 PoC 범위 결정으로 대체, 2026-11-03 |
| 최초 12건과 12건씩 더 보기 | **20건 기본, 10/20/50, 페이지 번호** | 구형 목록 UI 폐기 |
| 단일 판매처, 단일 카테고리, 세부 경험 선택기로만 탐색 | **판매처와 카테고리 다중 선택 OR, 미분류 별도 항목, 그래프 클릭 연동** | 구형 선택 UI 폐기 |
| 원문 카드 및 행 펼침 중심 | **리뷰 원문 셀 내부만 펼침, 2줄 미리보기, 여러 셀 동시 펼침** | 구형 행 조작 폐기 |
| 수집일을 각 원문 행에 표시 | **수집 기간을 원문 테이블 하단에 고정 표시** | 구형 7열 이상 UI 폐기 |
| 좁은 화면에서 특정 열 고정 가능성 | **가로 스크롤, 고정 열 없음** | 인터뷰 65 A, 66 B 기준 확정 |

**이 표는 이력 대조표일 뿐 구형 UI 구현 지시가 아니다.** 원본 리뷰 데이터의 기간 구분, 복수 세부 경험 분류, QA 증거는 데이터 SDD에 따라 계속 보존한다. 데이터 자체를 폐기하거나 재작성하지 않는다.

### 12.2 구현 준비도 검증 결과, 2026-11-03

**판정: 프론트엔드 UI 구현 착수 가능.** 최신 인터뷰에 없는 새로운 선택 인터뷰나 이전 화면 설계를 다시 끌어오는 작업은 선행 조건이 아니다. 다만 실제 리뷰와 분류 데이터의 **완전한 연동 및 출시 승인은 별도**다.

| 점검 항목 | 확인 및 처리 | 프론트 착수에 대한 영향 |
| --- | --- | --- |
| 인터뷰 1~34 개별 차이 확인 | 최신 UI SDD에 핵심 화면 구조는 반영했지만 인터뷰 1~34의 **질문, 선택지, 확정 답변 원문과 번호별 대응 검증은 미완료**다. 이전 SDD와 다른 항목을 우선 사용자에게 항목별로 공개하고 확인받는다. 미확인 선택을 확정했다고 적지 않는다 | **화면 상세 확정 검토 대상**, 이미 검증된 UI 작업은 병행 가능 |
| 작성일 기간 UI와 데이터 범위 | **사용자 최신 결정으로 해소**: 선택기는 `baseline` 14일, `current` 14일, `both`만 제공한다(§3.2). 원문은 ROAS의 두 기간으로 판정하며 추가 기간/원문은 생성하지 않는다 | **충돌 해소, UI 구현 가능** |
| Intent A/B/C와 최신 3영역 UI | **C01의 기존 ROAS 하단 리뷰 섹션, C02~C32의 3카드, 분포 그래프, 원문 테이블**이 화면 구현 기준이다. 이전의 기간별/판매처별 동시 비교표, 세부 경험 패널을 임의 복원하지 않는다. A/B/C는 **원문 데이터 생성 및 품질 검산 기준**으로 보존한다. 화면에서 동시 비교를 얼마나 할 수 있는지는 별도 제품 인수 쟁점이며 현재 UI를 충족으로 허위 판정하지 않는다 | **UI 비차단**, 직접 비교 UX 범위 제한을 인수 시 명시 |


**착수 순서:** (1) 기존 ROAS 아래 읽기 전용 리뷰 섹션과 표시 UI 개발, (2) 승인된 계약과 분리된 필터/검색/정렬/페이지 상태 선택자 개발, (3) 데이터 담당자의 신규 원시/분류/상품/제공 선언 스키마 승인과 독립 로더 준비 후 통합, (4) 전체 인수 및 ROAS 회귀.

**의사결정 종료 기준:** 이미 확정된 인터뷰의 재질문은 하지 않는다. 저장 구조, 필드 타입, 조회/배포 방식 같은 **신규 데이터 계약**은 이 UI 명세가 임의 승인하지 않으며 데이터 담당자가 변경안과 검산 방법을 제시해 사용자 승인 후 연결한다.

## 13. 문서 및 작업 상태

- **이번 개정에서 변경한 것:** UI SDD의 유효 화면 계약, 구형 지시 폐기, 데이터 연동 경계, 인터뷰 35~66 추적. 2026-11-03 사용자 정정에 따라 **C01 왼쪽안(기존 ROAS 아래 리뷰 섹션), C02~C32 모두 오른쪽안**으로 확정했다. 특히 C04는 현재 사례 제공 상태만 표시, C05는 독립성 고정 안내문 없음, C32는 리뷰 ID 별도 노출 UI 없음.
- **변경하지 않은 것:** 코드, 기존 ROAS 원천, 데이터 SDD의 원문 생성/검수 규칙, 분류 스키마 승인, 테스트/CI, 리뷰 레코드.
- **아직 완료됐다고 주장할 수 없는 것:** 인터뷰 1~34 원문 번호별 전수 대조, 48건 데이터 생성 및 검수, 분류 API 승인/구현, 브라우저 UI 동작, 빌드 및 테스트 통과, Intent A/B/C의 최종 제품 인수. **프론트 구현 착수 가능**과 **최종 제품 인수 완료**는 구별한다.
- 사용자에게 새로운 인터뷰를 계속 요청하지 않는다. 구현 중 **실제로 차단되는 데이터 또는 제품 계약 충돌**이 확인된 경우에만 근거와 대안을 보고한다.
