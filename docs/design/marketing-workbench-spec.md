# 마케팅 데이터 워크벤치 상세 화면 명세

## 1. 확정 방향과 데이터 범위

**R01·R02의 밝고 정돈된 디자인에 R11·R13의 높은 정보 밀도를 결합한다. 9개 도메인에 40개 데이터 유형을 배치하고, 표현 방식과 상호작용은 아래 명세로 고정한다.**

사용자가 확정한 사항:

- 디자인·레이아웃·그래프 분위기: **R01 Untitled UI + R02 Attio**
- 정보 밀도: **R11·R13 수준의 촘촘한 업무 화면**
- 탐색: **왼쪽 9개 도메인 + 도메인 내부 세부 탭**
- Agent: **필요할 때 여는 우측 패널**
- 범위: **설계된 데이터 40종 전체 매칭**

현재 존재하는 데이터는 **T01–T40 중 10개 유형과 역사 판매 보고서 H01**, 총 **11개 파일·1,652건**이다. 나머지 30개 유형은 설계만 존재한다. 아래 `●` 표시는 현재 D003B에 해당 유형의 데이터가 있다는 뜻이며, 일반 스키마의 모든 필드가 채워졌다는 뜻은 아니다.

현재 데이터의 실제 필드와 전체 유형 스키마는 다르므로 어댑터를 분리한다. 기존 CTI 데모의 검색·감성·예산 수치를 D003B 화면에 섞지 않는다.

### 레퍼런스에서 가져올 부분

| 레퍼런스 | 채택 | 채택하지 않을 부분 |
|---|---|---|

아래 픽셀·배색·배치 수치는 **우리 화면을 위한 설계 결정**이다. 해당 제품이 동일한 수치를 사용한다는 의미는 아니다.

## 2. 모든 도메인에 적용할 화면·표현 규칙

### 2.1 화면 구조

기준 검토 화면은 **1440×900**, 추가 검토 화면은 1920×1080·1280×800·768×1024·390×844로 한다.

| 영역 | 확정 규격 |
|---|---|
| 왼쪽 탐색 | 너비 216px. 아이콘 18px + 도메인 이름 14px. 선택 항목은 연한 보라색 배경과 진한 글자 |
| 상단 헤더 | 높이 56px. 왼쪽에 현재 도메인·세부 화면, 오른쪽에 `가상 데이터`·`Agent 열기` |
| 공통 조건 | 국가·카테고리·기준월·비교 기준. 높이 최소 56px, 좁아지면 줄바꿈 |
| 세부 탭 | 높이 40px. 밑줄로 선택 표시. 작은 화면에서는 가로 스크롤 |
| 본문 | 좌우 20px, 12열 그리드, 영역 간격 12px |
| 요약 지표 | 높이 80px의 연속된 지표 띠. 개별 카드 그림자 없이 세로 구분선 사용 |
| 분석 영역 | 기본 `8열 주 차트 + 4열 보조 차트`, 높이 280px |
| 상세 표 | 분석 영역 아래 전체 너비. 페이지당 25행 |
| 설명문 | 화면 맨 위의 긴 서술문 대신 차트 아래 한 줄 주석, 나머지는 상세 패널 |

1440×900에서 **조건·요약·주요 차트·상세 표 첫 6행 이상**이 보이도록 한다. 원문·소재·사건처럼 구조가 다른 화면에는 차트 자리를 억지로 만들지 않는다.

본문의 사용 가능 너비가 960px 미만이면 분석 영역을 한 열로 쌓는다. 넓은 표는 표 내부에서만 가로 스크롤한다.

### 2.2 글자와 색

글꼴은 **Pretendard Variable 1.3.9를 로컬 제공**한다. 한글과 영문·숫자를 같은 계열로 정리하기 위한 선택이며, 공식 배포물과 라이선스를 함께 보존한다. [Pretendard 공식 자료](https://github.com/orioncactus/pretendard)

| 항목 | 규격 |
|---|---|
| 페이지 제목 | 24px / 600 |
| 영역 제목 | 15px / 600 |
| 본문·필터·표 값 | 14px / 400 |
| 표 머리글 | 13px / 500 |
| 차트 눈금·보조 설명 | 12px / 400 |
| 주요 지표 숫자 | 26px / 600 |
| 숫자 | `tabular-nums`, 오른쪽 정렬 |
| 이름·문장 | 왼쪽 정렬 |
| 표 행·머리글 | 기본 높이 32px. 원문·소재 행만 별도 높이 사용 |

고밀도는 작은 글씨보다 **여백·반복 요소·정보 배치**로 확보한다. Carbon 역시 밀도에 따라 표 크기를 구분하고, 촘촘한 데이터를 위해 표에 충분한 너비를 배정하도록 안내한다. [Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)

기본 배색:

- 화면 배경 `#F8FAFC`
- 패널 `#FFFFFF`
- 본문 `#101828`
- 보조 글자 `#475467`
- 구분선 `#EAECF0`
- 선택·주요 강조 `#6941C6`

차트의 브랜드 색은 자사 보라색, 경쟁 B2 파란색, 경쟁 B3 청록색, 기타 회색으로 고정한다. 브랜드와 매체 색상표는 별도로 관리하며, 같은 화면에서 브랜드 색의 의미를 매체 색으로 바꾸지 않는다.

상승·하락은 기본적으로 중립색과 `↑/↓`로 표현한다. 광고비 상승이나 리뷰 수 증가를 자동으로 좋은 결과로 칠하지 않는다. 목표·판정 기준이 있는 경우에만 긍정·주의·오류 상태색을 사용한다.

### 2.3 차트 종류 선택

| 표현 | 사용 조건 | 이번 화면의 결정 |
|---|---|---|
| 가로 막대 | 브랜드·제품·매체처럼 이름이 긴 범주의 수치 비교 | 순위·점유율·별점 분포의 기본 |
| 세로 막대 | 날짜·월별 건수나 기간 합계 비교 | 일별 이벤트·발송·주문량 등에 사용 |
| 직선 추이 | 시간에 따른 관측값 변화 | 판매·광고·검색의 기본 추이 |
| 전년 점선 | 같은 정의·해상도·범위의 전년 자료 존재 | 현재 실선, 전년 `6 4` 점선 |
| 계단선 | 값의 변경 시각과 그 사이의 유효 상태가 확인됨 | 설정·정책 변경에만 사용 |
| 부드러운 곡선 | 모형이 실제로 정의한 연속 반응 함수 | T39 반응 모형에만 사용 |
| 100% 누적 막대 | 상호 배타적인 구성요소가 전체를 이룸 | 국가별 브랜드 구성, 유효한 예산안 구성 비교 |
| 원·도넛 | 작은 수의 구성비를 단일 전체로 표현 | 기본 화면에서는 사용하지 않음 |
| 점·구간 | 추정값과 수치형 불확실성 범위 비교 | 패널·설문·실험에 사용하되 실제 구간이 있을 때만 |
| 히트맵 | 동일한 단위·정의의 행렬에서 패턴 확인 | 날짜별 수집 상태, 일부 세그먼트 비교 |
| 타임라인 | 시작·종료·발생 시각이 중요한 자료 | 행사·협업·변경·장애 |
| 글·원문 | 문맥과 근거가 숫자보다 중요 | 리뷰·문의·기사·정책 |

범주 비교는 가로 막대, 추세는 선으로 분리한다. 막대의 수치 축은 0에서 시작한다. [ONS 막대 차트](https://service-manual.ons.gov.uk/data-visualisation/chart-types/bar-charts)

전년 자료는 비교 맥락으로 활용하지만, 결측 구간은 끊는다. 가격·재고 스냅샷은 관측 사이의 실제 상태를 모두 안다고 가정하지 않는다. [ONS 선 차트](https://service-manual.ons.gov.uk/data-visualisation/chart-types/line-chart), [Datawrapper 결측 표현](https://www.datawrapper.de/academy/patchy-data)

R01·R02의 분위기는 색·선 두께·여백으로 가져온다. 관측되지 않은 움직임을 곡선으로 만들어 비슷하게 보이게 하지 않는다.

원형 차트 대신 막대를 기본으로 정한 이유는 **집단 간 수치 비교와 공간 효율**이다. 여러 원형 차트의 비교, 불완전한 전체, 중복 응답에는 원형 차트가 적합하지 않다. [ONS 원·도넛 차트](https://service-manual.ons.gov.uk/data-visualisation/chart-types/pie-and-doughnut-charts)

추가 고정 규칙:

- 선 두께 2px, 현재 선택 계열 2.5px.
- 한 차트의 선은 최대 4개. 브랜드 3개 비교와 전년 비교는 별도 모드로 분리한다.
- 범주 차트는 상위 8개를 기본 표시하고 전체는 표에서 확인한다.
- 순위 막대는 값 내림차순, 동률은 대상 ID 오름차순.
- 시계열은 시간 오름차순.
- 결측을 0으로 바꾸거나 연결하지 않는다.
- 기본 화면에서 이중 Y축·3D·레이더·워드클라우드·장식용 게이지를 사용하지 않는다.
- 단위가 다른 지표는 같은 축에 겹치지 않고, 같은 시간축의 별도 작은 차트로 배치한다.
- 월간 차트에는 월중 사건을 정확한 일별 성과 위치처럼 표시하지 않는다. `8월 관련 사건 2건`으로 연결한다.
- 일별 차트에는 확인된 사건 시각·기간만 수직선·기간 밴드로 표시한다.

### 2.4 용어와 숫자 배치

각 차트의 텍스트 순서는 다음과 같다.

1. 왼쪽 위: `금액 기준 시장점유율`처럼 내용이 명확한 제목.
2. 바로 아래: 국가·제품 범위·실제 표시 기간.
3. 오른쪽 위: 단위와 로컬 지표 선택.
4. 차트 아래: 출처·범위·결측·표본 주석.
5. `데이터 표 보기`와 `근거 보기`.

차트 제목은 확인하지 않은 인과 결론을 쓰지 않는다. 제목·부제·단위·출처를 각각 다른 역할로 배치한다. [ONS Chart text](https://service-manual.ons.gov.uk/data-visualisation/guidance/chart-text)

| 항목 | 화면 표현 |
|---|---|
| 시장점유율 | `금액 기준 시장점유율` |
| 플랫폼 전환 | `보고 전환` |
| 플랫폼 귀속 금액 | `귀속 매출` |
| 직접 판매 보고 | `자사 순매출` |
| 리뷰 수 | `수집 리뷰 표본` |
| 검색 지수 | `검색 관심지수` — 검색량과 구별 |
| 비율 차이 | `%p` |
| 상대 증감률 | `%` |
| ROAS | `1.25배`, 설명에 귀속 매출÷광고비 |
| 예측 | 제목과 값 옆에 `모형 예측` |
| 미확인 값 | `—`와 사유. 0으로 표시하지 않음 |
| 과거 스냅샷 | `2026.08.30 관측`처럼 시점 명시 |

표의 금액은 KRW·JPY 정수, USD 소수 2자리로 표시한다. ROAS는 소수 2자리, 비율은 기본 소수 1자리, 평균 별점은 소수 1자리다. 계산은 표시 전 반올림하지 않는다.

금액 축약은 지표·축에서만 허용하고, 표는 천 단위 구분이 있는 전체 값을 사용한다. 정확한 원천값은 근거 패널에서 확인한다.

## 3. 9개 도메인·40개 데이터 유형의 상세 매칭

각 유형의 표에 적은 열은 **왼쪽부터 기본 열 순서**다. 명시하지 않은 필드는 공통 상세 패널 규칙에 따라 제공한다.

### 3.1 시장·경쟁

**세부 탭:** 시장 현황 / 구매 패널 / 경쟁 활동 / 외부 환경  
**기본 탭:** 시장 현황

기본 배치:

- 요약: 시장 판매액 / 자사 금액 점유율 / 자사 시장 판매액 / 전년 동월 점유율 차이.
- 왼쪽 8열: 자사 점유율 12개월 추이와 전년 비교.
- 오른쪽 4열: 선택 월 브랜드별 점유율 가로 막대.
- 아래 전체 너비: 브랜드→제품 상세 표.

시장 비교의 필터 구조는 [Similarweb](https://support.similarweb.com/hc/en-us/articles/360018977477-Web-Intelligence)을 참고하되, 웹 트래픽 비중을 제품 판매 시장점유율로 취급하지 않는다. 우리 판매 비교는 T03의 동일 시장 분모를 사용한다.

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T03 ● 소매·시장 측정** | 브랜드별 점유율 가로 막대 + 자사 12개월 추이 | 브랜드/제품 → 판매액 → 판매량 → 금액 점유율 → 전년 판매액 → 전년 점유율 → 점유율 차이. 판매액↓ | 분모·커버리지를 항상 표시. 자사만 색 강조. 기타 시장 금액은 분모에서 선정 제품 합계를 뺀 값으로 분리 |
| **T04 구매·사용 패널** | 침투율 점 그래프 + 분기 추이 | 브랜드 → 지표 → 추정값 → 표본 수 → 가중 방식 → 조사 기간 | 기본 지표는 명시적으로 바인딩된 침투율. 없으면 `침투율 미제공`. 분기 자료를 월별로 쪼개지 않음 |
| **T10 공개 경쟁 광고** | 소재 미리보기와 관측 목록. 시간 정보는 보조 타임라인 | 광고주 → 공개 광고 ID → 형식 → 문구 → 관측 지역 → 최초/최종 확인 → 관측일. 관측일↓ | 공개 광고 수를 광고비·노출량으로 표시하지 않음. 이미지가 없으면 문구만 표시 |
| **T11 기사·발표·사건** | 날짜순 사건 목록 + 원문 상세 | 발생일 → 게시일 → 브랜드 → 제목 → 발행 주체 → 중복 기사군. 발생일↓, 없으면 게시일↓ | 발생일과 게시일을 별도 표시. 자동 요약 대신 원문 제목·확인된 발췌를 우선 |
| **T15 경매 경쟁** | 광고주별 노출 점유율 가로 막대 + 비교 표 | 광고주 → 노출 점유율 → 중복률 → 상위 게재율 → 우위 비율 → 보고 기간 → 임계 상태 | 경매 비율끼리 합쳐 100%로 만들지 않음. 시장점유율과 다른 이름 사용 |
| **T33 공표 통계** | 국가별 작은 추이 차트 | 통계 항목 → 지역 → 값 → 단위 → 기준년 → 계절조정 → 발표/개정일 | 국가별 기준년·단위가 다르면 한 축에 겹치지 않음. 최신 개정 여부 표시 |
| **T34 날씨·휴일·시즌** | 기상은 항목별 일별 차트, 휴일·시즌은 기간 타임라인 | 유형 → 지역/관측소 → 항목/일정명 → 값·단위 → 기간 → 품질 | 기온과 강수는 별도 축 영역. 휴일과 매출의 동시 발생을 원인으로 표시하지 않음 |

경매 지표는 각기 다른 정의의 비율이므로 원형 구성비로 만들지 않는다. [Google Ads 경매 분석](https://support.google.com/google-ads/answer/2579754?hl=en)

시장 분모는 국가·월·커버리지별로 중복 제거한다. 브랜드·제품 표시 필터를 바꿔도 시장 전체 분모를 선정 제품 합계로 바꾸지 않는다.

### 3.2 브랜드·소비자

**세부 탭:** 리뷰 / 검색 수요 / VOC·문의 / 브랜드 조사  
**기본 탭:** 리뷰

기본 배치:

- 요약: 수집 리뷰 표본 수 / 리뷰가 있는 제품 수 / 평균 별점 / 2점 이하 표본 비율.
- 왼쪽 8열: 제품별 평균 별점과 표본 수.
- 오른쪽 4열: 5→1점 순서의 별점 분포 가로 막대.
- 아래: 원문 리뷰 표. 감성·주제는 별도 주석 데이터가 있을 때만 표시.

검색 지수와 소비자 반응은 같은 지표로 통합하지 않는다. Google Trends는 0–100으로 정규화한 관심도이며 검색 횟수나 인지도 조사 결과가 아니다. [Google Trends 정의](https://support.google.com/trends/answer/4365533?hl=en)

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T05 검색 관심** | 동일 요청 내 검색어별 직선 추이, Y축 0–100 | 검색어/주제 → 지수 → 비교값 → 지수 차이 → 정규화 요청 → 검색 표면 → 기간 | 같은 `query_id`의 비교만 허용. Google 관심지수와 네이버 쇼핑 클릭지수는 별도 보기 |
| **T06 키워드 수요·비용** | 검색 근사량 가로 막대 + 입찰 범위 점·구간 | 키워드 → 월 검색 근사량 → 경쟁 수준 → 경쟁 지수 → 입찰 하단 → 입찰 상단 → 언어/지역. 검색량↓ | 입찰 범위는 실제 CPC가 아님. 검색량과 금액은 같은 축에 표시하지 않음 |
| **T24 ● 리뷰 원문** | 별점 분포 + 제품 비교 표 + 원문 목록 | 작성일 → 제품 → 별점 → 본문 미리보기 → 구매 확인 → 언어 → 근거. 작성일↓ | 본문 2줄까지, 펼치면 전문. `verified_purchase=null`은 `구매 확인 미제공`. 낮은 별점을 부정 감성으로 자동 분류하지 않음 |
| **T25 리뷰 주제·감성** | 측면별 주석 언급 수 가로 막대 + 감성별 세부 표 | 측면 → 감성 → 주석 언급 수 → 연결 리뷰 수 → 표본 → 분류 기준/버전 → 검토 상태 | 클릭하면 해당 원문 구간 강조. 다중 측면 때문에 합계가 리뷰 수를 넘을 수 있음을 표시. 전체 긍정 리뷰율을 추정하지 않음 |
| **T26 문의·CS** | 상태별 건수 막대 + 문의 표 | 생성일 → 제목 → 제품 → 상태 → 우선순위 → 채널 → 해결일 → 연결 수준. 미해결 우선, 생성일↓ | 주문·제품 연결의 확인/추정/미연결 구별. 처리시간은 생성·해결 시각이 모두 있을 때만 계산 |
| **T32 설문·브랜드 리프트** | 브랜드별 점 비교 + 조사 조건 표 | 조사 → 질문 → 브랜드 → 응답 지표 → 표본 수 → 조사 기간 → 모집/가중 방식 → 불확실성 | 다중 응답률을 원형 차트로 표시하지 않음. 수치형 구간이 없으면 점과 불확실성 설명만 표시 |

점·구간과 예측 밴드는 실제 상·하한과 구간 의미가 있어야 그린다. 현재 `uncertainty_text`만 있는 자료에서 임의의 95% 구간을 생성하지 않는다. [ONS 불확실성 표현](https://service-manual.ons.gov.uk/data-visualisation/guidance/showing-uncertainty-in-charts)

현재 T24는 제품·국가별 4개 표본이다. 장기간 전체 리뷰 추세나 시장 전체 불만률을 나타내는 선 차트를 만들지 않는다.

### 3.3 광고·소재

**세부 탭:** 성과 / 세그먼트 / 운영 설정 / 소재  
**기본 탭:** 성과

**표가 주역인 도메인**으로 고정한다.

- 요약: 광고비 / 보고 노출 / 보고 클릭 / 보고 전환.
- 중간: 선택 매체의 광고비·클릭률·클릭 후 전환율·ROAS를 같은 시간축의 별도 작은 차트로 표시.
- 하단 전체 너비: 매체별 그룹화된 성과 표.
- 기본 그룹은 매체, 캠페인 행은 펼치기.
- 기본 정렬은 광고비 내림차순.
- 합계에서 보고 전환·귀속 매출의 중복 귀속 가능성을 명시한다.
- **전체 ROAS를 대표 KPI로 만들지 않는다.**

ROAS·전환은 원천의 전환 정의와 귀속 설정에 연결해야 한다. [Google Ads 전환 보고](https://developers.google.com/google-ads/api/docs/conversions/reporting), [Northbeam의 공통 귀속 조건 구성](https://www.northbeam.io/features/overview-page)

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T12 ● 운영 설정** | 캠페인 설정 표 + 읽기 전용 속성 패널 | 캠페인 → 매체 → 홍보 제품 → 목표 → 상태 → 설정 예산 → 입찰 방식 → 유효기간 | 설정 예산과 집행비 구별. 현재 D003B에 없는 목표·상태·예산·입찰은 `미제공`; 유효기간만으로 `운영 중`을 추정하지 않음 |
| **T13 ● 광고 성과** | 고밀도 비교 표 + 지표별 작은 추이 차트 | 캠페인/매체 → 광고비 → 노출 → 클릭 → CTR → 보고 전환 → 클릭 후 CVR → CPA → 귀속 매출 → ROAS → 수집 상태 | 광고비·전환·ROAS는 600 굵기. 통화·귀속 창·전환 정의를 표 상단에 노출 |
| **T14 광고 세그먼트** | 세그먼트별 가로 막대 + 같은 단위 지표의 히트맵 표 | 분해 차원 → 세그먼트 → 광고비 → 노출 → 클릭 → 전환 → CPA → ROAS → 억제 상태 | 기본 차원은 기기. 제공되지 않으면 선택 불가. 전체 성과와 세그먼트 행을 함께 합산하지 않음 |
| **T16 소재·메시지** | 썸네일이 있는 성과 비교 표, 버전별 상세 | 소재 → 버전 → 형식 → 메시지 → CTA → 적용 기간 → 연결 캠페인 → 근거 | 소재 성과는 광고와 소재의 연결·유효기간이 확인된 경우만 표시. 캠페인 전체 성과를 모든 소재에 복제하지 않음 |

성과 표에는 세 가지 고정 열 구성을 제공한다.

| 보기 | 열 구성 |
|---|---|
| **종합 — 기본** | 이름, 매체, 광고비, 노출, 클릭, CTR, 보고 전환, CVR, CPA, 귀속 매출, ROAS, 수집 상태 |
| **노출·클릭** | 이름, 매체, 광고비, 노출, 클릭, CTR, CPC, CPM, 수집 상태 |
| **전환·가치** | 이름, 매체, 광고비, 보고 전환, CVR, CPA, 귀속 매출, ROAS, 귀속 창, 수집 상태 |

고정 열은 이름·매체다. 원천별 정의가 다른 전환·가치 지표를 묶은 비율은 계산하지 않는다.

계산식:

- CTR = 클릭÷노출
- 클릭 후 CVR = 보고 전환÷클릭
- CPC = 광고비÷클릭
- CPM = 광고비÷노출×1,000
- CPA = 광고비÷보고 전환
- ROAS = 해당 매체의 귀속 매출÷광고비

분모가 0이거나 정의·범위가 맞지 않으면 `—`와 이유를 표시한다. 비율 평균 대신 호환되는 원시 분자·분모 합으로 계산한다.

### 3.4 웹·전환

**세부 탭:** 유입 / 구매 단계 / 사이트 품질  
**기본 탭:** 유입

유입은 경로 비교, 구매 단계는 순서·이탈, 사이트 품질은 성능·장애를 중심으로 분리한다.

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T07 자연 검색 유입** | 클릭 추이 + 검색어/페이지별 성과 표 | 검색어/페이지 → 클릭 → 노출 → CTR → 평균 순위 → 기기 → 검색 유형. 클릭↓ | 미공개 검색어는 `검색어 미제공`. 평균 순위는 원천 집계값을 표시하고 서로 다른 범위의 평균을 단순 평균하지 않음 |
| **T17 웹·앱 이벤트** | 유입 경로별 가로 막대 + 일별 이벤트 수 | 날짜 → source/medium → 캠페인 → 이벤트명 → 이벤트 수 → 확인 가능한 세션 수 → 동의 상태 | 가명 사용자·세션이 없는 경우 이용자·세션 수를 추정하지 않음. 원시 ID는 상세 패널에서 확인 |
| **T18 구매 단계** | 동일 세션의 순서가 확인되면 닫힌 퍼널 형태의 가로 막대 + 이탈 표 | 단계 → 도달 세션 → 이전 단계 대비 비율 → 이탈 세션 → 이탈률 | 상품조회→장바구니→결제시작→구매. 중간 다른 이벤트는 허용, 같은 세션에서 순서 충족, 세션당 1회. 연결 키가 없으면 이벤트 수 막대와 `퍼널 계산 불가` |
| **T37 사이트 품질·장애** | 성능 지표별 점·추이 + 장애 타임라인 | 페이지 → 기기 → LCP → INP → CLS → 집계 창 → 장애 상태 → 시작/복구 | rolling 성능과 당일 장애를 분리. 장애시간은 실제 시작·복구가 있을 때만 계산 |

퍼널은 단계별 이벤트 수를 임의로 연결한 그림과 구별한다. 진입·순서·반복 집계 규칙이 결과에 영향을 준다. [GA4 Funnel exploration](https://support.google.com/analytics/answer/9327974?hl=en)

T37은 원천이 같은 정의의 p75 지표를 제공할 때만 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하를 `양호` 기준으로 사용한다. 다른 집계·실험실 측정값에 그대로 적용하지 않는다. [Google Web Vitals](https://web.dev/articles/vitals)

### 3.5 매출·고객

**세부 탭:** 판매 요약 / 주문·환불 / 원가·마진 / 고객 / CRM 캠페인  
**기본 탭:** 판매 요약

현재 H01을 이용하는 기본 화면:

- 요약: 총판매액 / 반품금액 / 순매출 / 순판매수량.
- 왼쪽: 순매출 12개월 추이와 전년 비교.
- 오른쪽: 총판매액→반품금액→순매출 워터폴.
- 아래: 자사 제품별 판매 보고 표.
- H01의 판매수량으로 주문 수·고객 수·객단가를 만들지 않는다.

고객 코호트는 집단 정의와 시작·재방문 기준이 중요하다. [Amplitude Retention Analysis](https://www.amplitude.com/docs/analytics/charts/retention-analysis/retention-analysis-build)

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T19 주문 상품 행** | 일별 판매액 세로 막대 + 주문 표 | 주문 시각 → 주문 ID → 제품 → 수량 → 단가 → 할인 → 세금 → 상품 행 금액 → 결제/이행 상태. 주문 시각↓ | 상품 행 수와 주문 수 구별. 주문 수는 고유 주문 ID로 계산 |
| **T20 취소·반품·환불** | 처리일별 환불금액 막대 + 사유별 건수 | 처리일 → 종류 → 주문/행 ID → 수량 → 환불금액 → 사유 → 상태 → 재입고 | 요청과 처리 시각 구별. 같은 조정을 중복 차감하지 않음 |
| **T21 원가·마진 조건** | 제품별 단위원가 가로 막대 + 조건 표 | 제품 → 단위원가 → 출고비 → 결제 수수료율 → 채널 수수료율 → 프로모션비 → 적용기간 → 마진 정의 | 원가·비용이 불완전하면 이익 KPI를 계산하지 않음. 매출 ROAS를 이익률로 바꾸지 않음 |
| **T30 고객 코호트·영업 기회** | `구매 코호트`: 월별 재구매율 추이와 표. `영업 기회`: 단계별 금액 막대와 표 | 코호트: 집단 → 관측기간 → 인원 → 순매출 → 재구매율 → 획득 경로. 기회: ID → 단계 → 금액 → 종료일 | 두 하위 유형은 별도 보기. 현재 스키마에는 코호트 시작월·경과월 행렬이 부족하므로 삼각형 리텐션 히트맵은 사용하지 않음 |
| **T31 CRM 캠페인** | 캠페인별 고유 클릭률 가로 막대 + 전송·클릭·해지 표 | 캠페인 → 발송일 → 발송 → 반송 → 고유 클릭 → 클릭률 → 해지 → 연결 주문 → 오픈 계측 기준 | 오픈은 보조 열로 둔다. 프록시 영향을 포함한 오픈을 실제 열람자 수로 단정하지 않음 |

H01은 `제품 → 총판매수량 → 반품수량 → 순판매수량 → 총판매액 → 반품금액 → 순매출 → 비교값` 순서로 표시한다. T19·T20의 원시 주문이 있는 것처럼 가짜 주문 상세를 열지 않는다.

### 3.6 상품·유통

**세부 탭:** 가격·프로모션 / 재고 / 유통·배송  
**기본 탭:** 가격·프로모션

- 비교군 A를 기본 선택하고 A/B 전환을 제공한다.
- 가격 요약: 자사 관측 가격 / 경쟁 최저 관측 가격 / 가격 격차 / 기준 관측일.
- 가격은 비교 대상의 동일 관측일 자료를 사용한다.
- 날짜가 다른 마지막 관측값을 몰래 이어 붙이지 않는다.

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T08 ● 가격 스냅샷** | 제품별 관측 가격 점·직선 추이 + 동일 날짜 가격 비교 표 | 제품 → 판매처 → 관측 가격 → 100ml당 가격 → 자사 대비 격차 → 판매 상태 → 관측일 → 세금/배송 포함 | 기본 가격 비교는 관측 가격. 용량이 확인될 때만 단위 가격 계산. 품절 표시와 가격 값을 함께 유지 |
| **T09 ● 프로모션** | 제품별 행사 기간 타임라인, 상세 차트에 기간 밴드 | 행사 → 제품 → 판매처 → 시작 → 종료 → 할인 조건 → 근거. 시작일↓ | 종료는 exclusive 경계를 유지. 할인 일정과 실제 판매 효과를 분리 |
| **T22 ● 재고** | 제품·위치별 관측 수량 추이 + 날짜별 판매 가능 상태 행렬 | 제품 → 위치 → 판매 가능 수량 → 판매 상태 → 관측일 → 입고 예정 → 확정 여부 | 시점별 수량을 기간 합계로 더하지 않음. `품절 관측일 수`와 실제 품절 지속시간을 구별. 임의 재고 부족 기준 없음 |
| **T23 유통·배송** | `유통`: 채널별 지표 막대. `배송`: 주문 이행 상태와 약속·도착 비교 표 | 유통: 제품 → 채널 → 지표 → 값 → 기간. 배송: 주문 → 상태 → 약속 → 출고 → 도착 → 지연 여부 | 두 grain을 분리. 도착 미확인을 배송 완료로 취급하지 않음. 정시 도착률의 유효 표본 수도 함께 표시 |

현재 가격·재고는 2026년 8월 상세 관측만 존재한다. 다른 월을 선택하면 그 월의 가격·재고를 이전 값으로 채우지 않는다.

### 3.7 소셜·콘텐츠

**세부 탭:** 콘텐츠 / 댓글·언급 / 크리에이터 협업  
**기본 탭:** 콘텐츠

콘텐츠는 이미지와 정확한 수치를 함께 제공하는 표, 언급은 원문 목록, 협업은 일정과 계약 조건을 중심으로 한다.

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T27 공개 콘텐츠·반응** | 썸네일이 있는 콘텐츠 표. 플랫폼 선택 후 조회수 가로 막대 | 플랫폼 → 콘텐츠 → 게시일 → 관측일 → 누적 조회 → 누적 좋아요 → 누적 댓글 → 연결 제품. 관측일↓ | 콘텐츠별 최신 관측을 표시. 반복 스냅샷 합산 금지. 누적값을 선택 기간의 신규 반응으로 표시하지 않음 |
| **T28 댓글·언급** | 원문 2줄 목록 + 스레드 상세 | 작성일 → 플랫폼/콘텐츠 → 원문 → 언어 → 좋아요 → 연결 대상 → 근거. 작성일↓ | 답글 맥락을 함께 열기. 주제·감성 주석이 없으면 자동 태그를 붙이지 않음 |
| **T29 크리에이터 협업** | 예정 게시기간 타임라인 + 협업 대장 | 크리에이터 → 제품 → 예정기간 → 계약/게시 상태 → 확인된 비용 → 실제 콘텐츠 → 추적 링크 → 권리 | 예정과 실제 게시를 별도 표시. 공개 콘텐츠에서 계약금·귀속 매출을 추정하지 않음 |

콘텐츠 썸네일은 원천 파일이 있는 경우만 사용한다. 누락된 이미지를 생성 이미지로 채우지 않는다.

### 3.8 예산·실험

**세부 탭:** 예산안 비교 / 실험 / 정책·승인 검토  
**기본 탭:** 예산안 비교

이 도메인은 **관측 성과와 모형 예측을 분리**하는 것이 핵심이다.

| 유형 | 주 표현·배치 | 기본 표 열·정렬 | 강조·상세 규칙 |
|---|---|---|---|
| **T38 실험 설계·결과** | 실험군·대조군 점 비교 + 실험 조건·결과 표 | 실험 → 상태 → 가설 → 배정 단위/방법 → 집단 → 표본 → 결과 → 불확실성 → 기간 | 단순 전후 비교를 실험 효과로 표시하지 않음. 제공된 효과 추정이 없으면 집단 결과만 표시 |
| **T39 반응 모형·예산안** | 현행·후보 나란한 가로 막대 + 증감 막대 + 비교 표. 반응 곡선은 별도 영역 | 매체 → 현행 예산 → 후보 예산 → 차액 → 변경률 → 배분 비중 → 하한/상한 → 제약 상태 | 원형 차트 대신 정확한 변경액 비교를 우선. 목적·기간·통화·모형 버전·가정을 화면에 고정 노출 |
| **T40 목표·집행 정책** | 읽기 전용 정책 요약 + 제약·승인 조건 표 | 정책/버전 → 목표 → KPI 정의 → 대상 → 예산 한도 → 허용 매체 → 변경 제한 → 승인 역할 → 유효기간 → 정책 상태 | `정책 승인됨`과 `예산 집행 승인됨`을 구별. 정책 문장을 실제 집행 승인 이력으로 바꾸지 않음 |

예산 비교는 Meridian의 **배분 비교 표·매체별 변경액·반응 곡선**을 참고한다. 원형 배분 차트보다 현행과 후보의 금액 차이를 우선한다. [Meridian 최적화 결과 해석](https://developers.google.com/meridian/docs/post-modeling/interpret-optimizations)

예산 화면의 고정 순서:

1. 목표·대상 기간·총예산·통화.
2. 등록된 현행안·후보안 선택.
3. 예산 합계·차액·제약 충족 상태.
4. 매체별 현행/후보 비교와 상세 표.
5. 모형이 제공한 예상 결과.
6. 모형 버전·학습 범위·가정·검증 근거.
7. 정책·승인 검토.

다음 동작은 고정한다.

- 초기 구현은 **등록된 예산 시나리오 비교**로 제한한다.
- 임의 예산 입력으로 새 예측값을 만드는 슬라이더는 제공하지 않는다.
- 반응 함수·파라미터 문자열을 프론트에서 `eval`하지 않는다.
- 수치형 반응 곡선 입력이 없으면 곡선을 그리지 않고 모형 설명을 표시한다.
- 실제 불확실성 상·하한이 없으면 예측 밴드를 그리지 않는다.
- D003B에는 T38–T40이 없으므로 예측·최적화·승인 영역은 데이터 미생성 상태다.
- 별도 집행 승인 이력 계약도 없으므로 `승인`·`집행` 버튼은 활성화하지 않는다.
- 미생성 안내는 “예산안·모형·정책 데이터가 아직 없습니다”로 표시한다.

**기본 탭:** 수집 상태

R11처럼 상태를 짧게 요약하고 즉시 상세 목록으로 연결한다.

현재 D003B의 품질 화면은 다음을 그대로 반영한다.

## 4. 필터·상세 보기·결측·데이터 연결 계약

### 4.1 초기 상태와 기간 규칙

초기 상태:

- 국가: 일본.
- 카테고리: 샴푸.
- 기준월: 2026년 8월.
- 도메인: 시장·경쟁 → 시장 현황.
- 추이: 기준월까지 최근 12개월.
- 비교: 지원되는 월간 지표에서 전년 동월.
- Agent 패널: 닫힘.

공통 조건은 국가·카테고리·기준월이다. 브랜드·제품·매체·검색어·기기·상태는 관련 세부 화면의 로컬 필터로 둔다. 적용되지 않는 필터를 모든 화면에 반복하지 않는다.

| 데이터 성격 | 기간 적용 |
|---|---|
| 월간 보고 | 선택 월을 요약하고 최근 12개월 추이 제공 |
| 일별 상세 | 현재 D003B는 2026.08.03–08.30만 선택 가능 |
| 분기 패널 | 기준월 말일까지 완료된 최근 분기. 실제 분기를 부제에 표시 |
| 설문 | 기준월 말일까지 종료된 조사 목록에서 선택. 조사기간을 그대로 표시 |
| 가격·재고 | 선택 월 안의 기준 관측일. 해당일 자료가 없는 대상은 미관측 |
| 사건 | 발생일로 필터. 게시일만 있는 기사는 게시일 기준임을 명시 |
| 정책·설정 | 기준 시점에 유효한 버전 |
| rolling 지표 | 실제 집계 시작·종료를 표시하고 중첩 창 합산 금지 |
| 모형 | 학습기간·예측기간·검토 기준일을 각각 표시 |

일별 전년 자료가 없으면 일별 전년 비교를 비활성화한다. 리뷰 표본이 없는 월에는 “선택 기간에 수집된 리뷰 표본이 없습니다”라고 표시한다.

국가·기간을 바꾸면 해당 데이터 범위에 유효하지 않은 로컬 선택은 해제하고, 해제 이유를 짧게 알린다. 탭 전환·패널 열기로 조건을 초기화하지 않는다.

### 4.2 표와 차트의 동작

- 표는 기본 25행, 선택지는 25·50·100행.
- 검색·필터·정렬은 페이지 전체 데이터에 적용하고 페이지를 1로 돌린다.
- null은 정렬 방향과 무관하게 마지막에 둔다.
- 동률은 `record_id` 또는 대상 ID 오름차순으로 고정한다.
- 숫자는 줄바꿈하지 않는다. 이름은 말줄임 후 툴팁과 상세에서 전문 확인.
- 원문 목록은 2줄 미리보기, 소재 행은 높이 80px.
- 차트 클릭은 우선 해당 대상의 상세 패널을 연다. 숨은 전역 필터를 적용하지 않는다.
- 차트와 연결된 표를 좁힐 때는 `차트 선택 적용` 칩과 `선택 해제`를 표시한다.
- 툴팁에는 대상·날짜·값·단위·비교값·데이터 상태를 표시한다.
- 모든 차트에 같은 데이터를 읽는 `데이터 표 보기`를 제공한다.
- CSV는 현재 조건의 전체 결과를 정렬 순서대로 내보내며, 화면의 25행에 제한하지 않는다.

버튼·행 동작은 키보드로 접근할 수 있어야 한다. 기본 32px 컨트롤을 사용하고, 24px 미만의 좁은 아이콘 클릭 영역을 만들지 않는다. [W3C 최소 타깃 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### 4.3 우측 Agent·근거 패널

상단 `Agent 열기` 또는 표·차트의 `근거 보기`로 연다.

- 1600px 이상: 400px 도킹 패널, 본문 재배치.
- 1600px 미만: 너비 420px의 오버레이. 화면이 더 좁으면 전체 너비.
- 패널 안 세부 탭: `분석 / 근거 / 원본`.
- 닫기·Esc 후 호출한 버튼으로 포커스를 돌려준다.
- 현재 도메인·국가·기간·선택 대상은 패널 상단에 계속 표시한다.
- 도메인 분석과 예산 검토의 문맥을 분리한다.
- 해당 데이터에 연결된 준비된 응답이 없으면 분석 결과를 만들지 않고 안내한다.
- 원본 보기와 근거 탐색은 Agent 응답 유무와 독립적으로 작동한다.

근거 패널에는 다음 순서로 표시한다.

1. 표시 값과 지표 정의.
2. 계산식·분자·분모.
3. 실제 기간·시간대·범위.
4. 연결된 원천 레코드.
5. 원문 발췌 또는 필드값.
6. 품질·귀속·표본·모형 가정.
7. 원본 JSON과 복사 가능한 근거 ID.

### 4.4 모든 필드의 표시 위치

기본 표·차트에 지정하지 않은 필드를 구현자가 임의로 버리지 않는다.

| 필드 형태 | 고정 표시 위치 |
|---|---|
| 식별자·출처·가상 여부·원천 경로 | 근거 패널의 출처 영역 |
| 공통 시간·품질·값 생성 방식 | 근거 패널의 범위·품질 영역 |
| 기본 표에 없는 단순 필드 | 상세 속성 목록, 스키마 순서 |
| Money·Quantity·Period | 금액+통화 / 수량+단위 / 시작·종료·시간대 형태로 표시 |
| 긴 본문·정책·가정 | 원문 영역에 전문 표시 |
| EvidenceSpan | 원문과 연결하고 확인된 offset만 강조 |
| 단순 배열 | 앞 3개와 `전체 N개`, 펼치면 전체 |
| 지표 배열 | 지표명 → 값 → 단위 → 정의·상태의 작은 표 |
| 나머지 중첩 구조 | 원본 JSON에서 손실 없이 확인 |

이 규칙으로 공통 필드와 유형별 추가 필드까지 표시 위치가 정해진다. 원천에 없는 필드를 UI용 사실처럼 추가하지 않는다.

### 4.5 데이터 상태와 계산

| 상태 | 화면 동작 |
|---|---|
| 정상 자료 | 값·차트·표 표시 |
| 부분 자료 | 확인된 값 표시 + `부분 자료` + 유효 범위·수신률 |
| 필터 결과 없음 | 조건에 맞는 수집 자료 없음 + 조건 초기화 |
| 유형 미생성 | 유형 설명 + 필요한 데이터 + 비활성 기능 사유 |
| 원천 필드 미제공 | 셀 `—`, 사유 `원천 미제공` |
| 억제 | 값 대신 `비공개 처리`와 원천 사유 |
| 분모 0 | 비율 `—`, 사유 `분모가 0입니다` |
| 정의·통화·범위 불일치 | 원시 값은 개별 표시, 비교·합산은 차단 |
| 수치형 불확실성 없음 | 점 추정 또는 값·설명만 표시, 구간 생성 금지 |

계산은 표시 컴포넌트에서 분산 수행하지 않는다.

- 금액은 소수 문자열을 보존하고 정확한 십진 계산 후 표시한다.
- 날짜는 원천 시간대와 exclusive 종료 경계를 유지한다.
- 월간·일간, 전체·세그먼트, 원본·개정본 중복 합산을 막는다.
- 가격·재고·누적 반응을 기간 흐름값처럼 합산하지 않는다.
- 평균·비율은 정의된 가중·분모가 있을 때만 재집계한다.
- 같은 브랜드명이라는 이유로 원천을 연결하지 않는다.
- 현재 D003B의 `product_id`·`campaign_id`를 사용하고 없는 variant ID를 생성하지 않는다.

## 5. 구현 인계·검증·보존

### 5.1 구현 경계와 내부 인터페이스

기존 독립 워크트리에서 `/workbench`를 추가한다. 기존 CTI 데모와 D003B 워크벤치의 데이터·응답 문맥은 분리한다.

기존 React·Recharts·UI 컴포넌트를 사용한다. 새 차트 라이브러리·표 라이브러리·범용 대시보드 편집기를 도입하지 않는다.

구현 구조는 다음으로 고정한다.

- **D003B 어댑터:** 현재 11개 원천 파일의 직접 필드에 대응.
- **유형별 화면 명세:** 40개 유형의 위치·표현·열·정렬·상태 정의.
- **표시 컴포넌트:** 준비된 값·상태·근거를 렌더링.
- **미생성 유형:** 정해진 안내 상태를 렌더링.
- **Agent 문맥:** 필터·대상·근거 참조를 전달하고 없는 분석 응답을 생성하지 않음.

내부 화면 모델에는 최소한 다음이 포함된다.

- 표시 상태와 사유.
- 국가·대상·기간·단위·시간대·커버리지.
- 요약 지표와 비교 가능 여부.
- 차트 계열과 실제 관측 시점.
- 표 열·행·정렬.
- 원천 레코드·필드·계산 근거.
- 사용 가능한 필터·동작과 비활성 사유.

프론트 컴포넌트가 원천 필드 이름을 보고 지표 의미·집계 방식·비교 가능 여부를 추정하지 않도록 한다. 새로운 외부 API·DB·실제 광고 집행은 이 화면 작업의 완료 조건에 포함하지 않는다.

### 5.2 구현 순서

1. 디자인 토큰·왼쪽 탐색·공통 조건·우측 패널.
2. 공통 표·추이·범주 비교·상태·원문 표현.
3. 현재 데이터가 있는 시장, 광고, 리뷰, 판매 요약, 가격·재고, 품질 화면.
4. 나머지 유형의 고정된 미생성 화면.
5. 도메인 간 근거 이동·필터 복원·키보드·CSV.
6. 수치 대조와 화면 검증.
7. 초안과 구현 결과의 스냅샷·명세 보존.

### 5.3 수용 기준

| 검사 | 통과 기준 |
|---|---|
| 유형 누락 | T01–T40 각각 주 도메인·세부 탭·표현·열·정렬·상태가 존재 |
| 데이터 경계 | 현재 10개 T유형+H01과 미생성 30개 유형을 정확히 구분 |
| 원천 보존 | 기존 11개 파일·1,652건과 원문·null을 수정하지 않음 |
| 시장 분모 | 제품별 반복 분모를 한 번만 사용하고 기타 시장을 보존 |
| 통화 | 국가 변경 시 통화 변경, 국가 간 금액 합계 없음 |
| 광고 | CTR·CVR·CPC·CPM·CPA·ROAS를 호환되는 분자·분모로 계산 |
| 결측 | 일본 소셜 8/26·8/27의 선이 끊기며 0으로 표시되지 않음 |
| 수집률 | 일본 소셜 26/28을 표시. 정상화된 행 수와 수신 수를 혼동하지 않음 |
| 기간 | 완전한 월 보고와 28일 상세 합계를 합치거나 같은 값으로 요구하지 않음 |
| 리뷰 | 72개 표본을 전체 시장 리뷰로 표시하지 않고 감성 라벨을 만들지 않음 |
| 판매 | H01 판매수량으로 주문 수·고객 수·객단가를 생성하지 않음 |
| 가격·재고 | 8월 밖의 관측을 채우지 않고, 관측 수량을 기간 합계로 표시하지 않음 |
| 예산·승인 | 모형·예산안·정책·집행 승인 이력이 없을 때 기능이 활성화되지 않음 |
| 밀도 | 1440×900에서 조건·요약·주요 차트·표 첫 6행 이상 표시 |
| 반응형 | 본문 전체 가로 넘침 없음. 넓은 표만 내부 스크롤 |
| 접근성 | 키보드로 필터·정렬·상세·닫기 사용 가능, 색 외의 상태 구별 제공 |
| 근거 | 표시 값에서 실제 레코드·필드·계산식·원문으로 이동 가능 |

검증은 현재 승인된 원천을 읽어 수행하며, 검사용 마케팅 수치를 별도로 생성하지 않는다.

### 5.4 인계 문서와 기록

실행 단계에서 다음 세 문서를 작성하고 상호 연결한다.

1. `docs/design/marketing-workbench-spec.md`  
   이 응답의 화면·시각화·상호작용·용어 명세.

2. `docs/design/marketing-workbench-type-map.json`  
   40유형의 도메인·세부 탭·필드 위치·차트·열·기본 정렬·가용성 매핑.

3. `docs/design/marketing-workbench-acceptance.md`  
   원천별 수치 검증·브라우저 검증·스냅샷 위치·남은 데이터 제약.

구현자는 이 명세의 차트 종류·기본 배치·용어·결측 처리·집계 의미를 다시 선택하지 않는다. 원천이 부족한 경우에는 위에서 정한 안내·차단 동작을 구현하며 수치를 보완하지 않는다.

현재는 계획 모드이므로 **이번 상세 명세의 파일 저장과 프론트 변경은 수행하지 않았다.** 기존 레퍼런스 보드와 초안 보존본은 그대로 유지한다.
