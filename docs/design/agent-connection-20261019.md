# Agent 패널의 로컬 분석·예산 연결

## 2026-10-19 후속 · 대화형 패널

사용자는 Gmail Gemini 참고 이미지와 함께 채팅 영역의 구분·여백·질문 말풍선·AI 정체성이 부족하다고 지적했다. 패널을 화면 가장자리에서 띄우고, 옅은 보라색 헤더·아이콘·480px 폭으로 대시보드와 구분했다. 데스크톱1200px 이상에서는 배경을 어둡게 덮지 않고 대시보드 옆 공간을 확보한다. 작은 화면에서는 여백 있는 모달로 표시한다. 진입 버튼은 ‘AI와 대화’, 분석 탭은 ‘대화’로 바꿨다.

질문은 오른쪽 말풍선, AI 답변은 왼쪽 본문으로 이어진다. 앞선 대화를 접힌 목록 대신 같은 대화 흐름에 표시한다. 입력창은 하단에 고정하고 실제 내역만 스크롤한다. Enter 전송·Shift+Enter 줄바꿈·IME 조합 중 전송 방지·입력 높이 조정·처리 상태·응답 후 입력 포커스를 연결했다. 시작 질문 버튼은 입력을 채우며 사용자가 전송하기 전에는 분석을 실행하지 않는다. 범위·분석 설정·수치·근거·조회 과정은 펼쳐 보는 구조이며 근거 검증과 가상 승인 경계는 유지한다.

검증: [15개 시험](agent-chat-20261019/tests-final.txt), 전체 TypeScript 검사, Vite 빌드가 통과했다. 브라우저에서 첫 질문·후속 질문·이전 대화·근거 원문 링크·키보드 줄바꿈/전송·입력창 고정·Esc 닫기/포커스 복귀를 확인했다. 데스크톱에서 내역 스크롤 전후 입력창 rect는 top575/bottom621로 같았다. 모바일390px에서는 패널 left8/right367, width359, clientWidth/scrollWidth357로 화면 안에 들어왔다. [최종 데스크톱](agent-chat-20261019/chat-final.jpg), [최종 모바일](agent-chat-20261019/chat-mobile-verified.jpg), [시작 화면](agent-chat-20261019/chat-welcome.jpg)을 보존했다.

시행착오: 기준정보 로딩 중 빈 제품 배열을 브랜드 행으로 렌더링하다 화면이 중단됐다. `legacy-query.ts`에서 기준정보가 없을 때 빈 상태를 반환하고 `str(undefined, ...)`를 안전하게 처리했다. 빈 제품/시장 배열의 조회를 별도로 확인했으며 새 마케팅 값을 만들지 않았다. 모바일의 `100vw`가 스크롤바 폭을 포함해 패널 왼쪽이 잘리는 문제는 좌우8px 고정으로 수정했다. 병행 데이터 통합으로 자료 해시가 바뀔 때는 기존 실행을 억지로 복원하지 않고 오프라인 검증 서버를 재시작해 최신 자료와 맞췄다. 기존 데이터 통합·모델 연결 작업은 이번 UI 변경의 실적으로 포함하지 않는다. 실제 LLM·Ads 호출, 신규 원천 생성, 패키지 설치, Git 상태 변경은 수행하지 않았다.

## 2026-10-19 후속 · 답변 요약 형식

사용자가 질문별 조회·판단 흐름과 간결한 답변 예시를 검토한 뒤 다음 작업 진행을 요청했다. 기존 패널에 **결론 → 핵심 근거 → 한계 → 다음 행동** 순서를 반영했다. 원인 후보의 지지·반대 건수와 짧은 `[1]` 근거 링크를 먼저 표시하고, 수치·원인 후보 상세와 실제 조회 기록은 펼쳐서 확인한다. 질문 입력도 결과 확인 뒤에는 접어 요약이 먼저 보이게 했다. 기존 색상·레이아웃과 병행 중인 화면·결과 표시 변경을 보존했다.

`agent-answer.ts`는 검증된 실행 상태·가설 평가만 표현한다. 근거 충돌·미확보·이전 분석 대체·제안 무효·가상 승인을 확정 인과나 실제 집행으로 바꾸지 않는다. 예산 모의 결과는 같은 가정 안의 수치 비교로 표시한다. 출력 형식 변경이며 모델의 자유 질문·인과 추론 품질을 새로 입증하지 않는다. 원천·명세·백엔드·광고 연결은 수정하지 않았다.

검증: [답변 상태6시험과 클라이언트 시험](agent-answer-20261019/tests.txt), 기존 화면 계약496조합 통과. 답변 시험은 상태와 빈 근거 집합의 표현을 확인하며 새 마케팅 관측·금액·원천 근거를 생성하지 않는다. 브라우저에서 기존 D007 저장 분석을 복원해 요약·원문 링크·실제 조회 단계·예산 승인 상태를 확인했다. 모바일390px 패널의 clientWidth/scrollWidth가 모두389px로 가로 넘침이 없었다. [요약 화면](agent-answer-20261019/answer-summary.jpg), [모바일 화면](agent-answer-20261019/answer-mobile.jpg)을 보존했다. 기존 데이터 분리·비교 데모·결과 차트 등 다른 미커밋 변경은 이번 요약 작업의 구현 실적으로 포함하지 않는다.

최종 확인: 답변6개·클라이언트8개 총14시험 통과, 전체 TypeScript 검사·Vite 빌드 통과다. 중간 타입 검사는 병행 추가된 `agent-presentation.test.ts`의 부분 실행 객체 단언으로 실패했으며, 해당 파일과 함수 입력 타입이 정리된 최신 상태에서 재실행해 통과했다. 빌드의 500kB 초과 청크 안내는 남아 있다. 이번 작업에서 백엔드104시험 전체를 다시 실행하지는 않았다.

아래는 최초 연결 당시의 기록이다.

기존 화면의 국가·제품·월·asOf·지표 이름·선택 근거 ID를 `workbench-model/1` 문맥으로 전달한다. 화면의 집계·조회·원천 파일과 명세는 변경하지 않는다. D007을 선택하고 Agent의 분석 탭에서 사용한다.

`../marketing-agent-poc`에서 `node scripts/agent-server.mjs`, 이 저장소에서 `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort`를 실행한다. Vite는 `/agent-api`를 로컬 포트8788로 전달한다. API 서버는 외부 LLM과 실제 Ads를 연결하지 않고 기존 가상 자료의 절차를 검증한다.

| 파일 | 역할 |
| --- | --- |
| `frontend/workbench/agent-client.ts` | 명시 범위·범위별 복원 키·세션 토큰·변경 요청 재전송 제한 |
| `frontend/workbench/agent-conversation.tsx` | 분석 질문·원인 선택·근거 원문·예산 인계·모의 결과·수정·가상 승인 |
| `frontend/workbench/agent-conversation.css` | 기존 패널 안의 대화·검토 표시 |
| `frontend/workbench/panel.tsx` | 기존 분석 탭에 연결, textarea와 보이는 입력의 키보드 순환 |
| `frontend/workbench/workbench.tsx` | 선택 범위 전달과 범위 변경 시 대화 분리 |
| `vite.config.ts` | 로컬 API proxy |

질문·숫자·근거를 클라이언트에서 만들어 답하지 않는다. 서버가 조회·검증하며 화면은 원인별 지지/반대 근거와 추가 조사 권고를 보여준다. 모의 예산은 기존 가상 시나리오를 사용한다. 실제 계정의 현행이나 실증 예측으로 표시하지 않는다. 수정·후속 분석은 기존 승인을 무효화하고 실제 집행 버튼은 비활성이다.

브라우저 저장소에는 실행 ID만 남긴다. 국가·제품·월·asOf·근거 ID가 같은 문맥에서만 복원한다. 응답을 받지 못한 변경을 자동 재시도하지 않는다. 다중 사용자 인증·실제 LLM 질문 이해·최초 생성 응답 유실 시 ID 탐색·중단/재개 화면은 후속 범위다.

검증: [클라이언트7시험](agent-ui-20261019-client-tests.txt), 타입 검사·Vite 빌드 통과, 기존 화면 계약496조합 통과, [기존 수치12조합](agent-ui-20261019-numeric-checks.json) 통과. 빌드의 큰 청크 안내는 남아 있다. 실제 브라우저에서 분석·근거·예산 인계·가상 승인·수정 후 재승인·후속 분석 무효화·새로고침 및 API 재시작 복원, 모바일390px의 패널 가로 넘침 없음을 확인했다. 백엔드104시험·입력102파일 보존 결과와 화면 증거는 sibling `marketing-agent-poc/docs/design/agent-ui-20261019.md`에 연결했다.
