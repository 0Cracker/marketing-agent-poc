# 충돌 조사·의미 검수·후속 수정 실행

## 최신 반영 상태

사용자가 의미 검수 의견·새 실제 모델 예산24회·수식 변경·문서 갱신·커밋을 승인했다. [반영 결과](semantic-changes-20261020.md): 재고 상태 문구, CURRENT 더미 확보시각 제외, 성능 대표12행, 채널별 Hill 모형을 구현했다. 백엔드126·화면20·오프라인33·독립 예산36·통합328검사가 통과했다. 실제 모델 최종4/4, 누적 시도23/24다. 아래 ‘입력 대기·미실행·자료 미변경’은 이 변경 전 실행 이력이다.

2026-10-20 · 사용자 요청: 85행 충돌 설명, 컨펌 가능한 의미 검수, 두 후속 작업의 병렬 계획·독립 피드백·수정·실행.

## 병렬 계획과 독립 검토

담당 `fix_plan`과 `evaluation_plan`이 각각 현재 코드를 조사해 v1 계획을 작성했다. 별도 `strict_review`가 두 계획의 필수 수정 사항을 제시했고, 담당자가 v2에 반영한 후 구현했다. 검토자는 최종 구현도 확인했으며 파일을 직접 수정하거나 외부 호출을 하지 않았다.

## 실제 변경과 확인 수준

503은 `model_unavailable`로 구분해 기존 paused·수동 resume 경로를 사용한다. 같은 실행 ID·이력·자료 해시·누적 한도를 보존하며 자동 재시도·키 순환이 없다. 과거 held/model_failed는 상세 원인을 알 수 없어 변경하지 않았다. 500/502/504·401은 기존 held 상태로 처리한다.

핵심 근거 요약과 상세 표는 공통 분류를 사용한다. 지지·반대가 모두 빈 배열이면 ‘원인 평가 미분류’, 검토하지 않은 후보는 ‘미검토’, 분류된 실제 0건은 0건으로 유지한다. 주 에이전트의 Windows 브라우저 후속 확인에서도 `재고: 원인 평가 미분류`가 요약·상세에 일치했고 `지지 0·반대 0`은 없었다. 이는 오프라인 대역의 렌더링 검사이며 질문 이해 검사가 아니다.

## 새로 분리한 공백

자연어로 국가·기간을 바꾸라는 요청이 현재 화면 범위를 자동 변경하거나 모순을 탐지하지 않는 공백 2건이 있다. 단순한 오프라인 일본 정상 응답을 질문 이해 성공으로 세지 않았다. 자연어 범위 파싱은 이번에 추가하지 않았고, 범위 확인·안내 설계의 후속 후보로 남겼다.

## 85행과 사용자 의미 검수

- [85행 조사](../../../marketing-dashboard-drafts/docs/design/site-performance-conflicts-20261020.md): 12묶음의 성능 자료 85행 전부가 보류이며 활성 23행은 장애 사건이다. 실제 사이트 오류가 아닌 가상 측정 식별 문제다. 조사만 수행했고 값·스키마·보류 상태는 바꾸지 않았다.
- [대표 의미 검수 6항목](semantic-review-20261020.md): 시장 분모, 가격 근거, 재고 미분류, 확보시각, 예산 승인, 성능 충돌. 모두 사람 검수 대기다. 대화 안에서 사례를 선택하고 동의·수정·추가 설명과 의견을 정리하도록 구성했다. 시험 선택은 미검수로 초기화했으며 자동 컨펌은 없다.
- 검수 동의는 대표 해석에 대한 의견이며 새 자료·스키마·85행 해제·실제 집행 승인이 아니다.

## 실제 모델 평가

새 실제 모델 호출 예산 24회 또는 0회 선택을 사용자에게 질문했다. 이 기록 시점에는 답변이 없어 외부 호출 0회를 유지했다. 기존 21/24회 검증은 이전 실행이며 이번 예산으로 재사용하지 않는다. 현재 33건 통과는 국가·초점·제품·기간·결측·보류·원문·단위의 명시 범위 계약 검사이며 실제 LLM 질문 이해·답변 품질은 미실행이다.

실제 평가에는 사전 고정한 대표 질문과 수치·근거·비인과·후속 평가 기준을 사용한다. 실패를 포함한 호출 수를 요청 직전에 저장·차단하고, 재개 때도 누적하며 독립 DB를 사용한다. 예산을 확정하지 않고 새 외부 호출을 시작하지 않는다.

커밋·스테이징·발행·원천 자료·마케팅 스키마 변경·실제 광고 호출은 수행하지 않았다. 의미 검수 답변과 실제 모델 예산 선택은 사용자 입력 대기다.
