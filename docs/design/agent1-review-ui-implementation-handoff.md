# Agent1 리뷰 분석 UI 설계 및 구현 인계 지시서

2026-11-04 코드 위치 변경: [ROAS와 구 대시보드 분리](roas-legacy-separation.md)를 현재 코드 경로와 서버 경계의 기준으로 함께 읽는다. 기존 frontend/workbench의 현재 기능은 frontend/roas, training과 ROAS 공용 계산은 shared/roas, 현재 도구와 서버는 scripts/roas와 backend/roas로 분리했다. 이전 분석, 예산 서버 구현은 legacy/backend에 보관했다. 아래 확정 기능 정책은 유지하며 구현 전 경로와 연계 지점은 이 분리 결과를 대조한다.

## 1. 이번 작업의 한 문장 목표

**기존 ROAS 대시보드를 손상시키지 않고, 같은 '성과 현황' 화면의 ROAS 분석 및 전체 지표 영역 아래에 상품 1(EDU-P1) 전용 '리뷰 분석' 섹션을 실제로 구현한다.** 별도 ROAS/리뷰 탭, 메뉴, 라우트를 새로 만들지 않는다.

설계 문서만 다시 쓰고 끝내지 말 것. 승인된 입력과 기존 구조로 할 수 있는 프론트엔드 구현을 진행하고, 실제 데이터 연동 의존성은 분리하여 명확히 보고한다. 추가 일반 UI/UX 인터뷰는 하지 않는다.

## 3. 결정 우선순위, 절대 변경 금지

**최종 선택은 C01만 왼쪽, C02~C32 전부 오른쪽이다.** 기존 1~66 인터뷰 중 이 결론 또는 후속 기간 결정과 충돌하는 표현은 최신 결정을 따른다.

- **C01 왼쪽**: 리뷰 영역은 기존 성과 현황의 ROAS 화면 **아래에 추가하는 섹션**. 별도 ROAS/리뷰 탭을 만들지 않는다.
- **C04 오른쪽**: **현재 선택한 사례의 리뷰 제공 상태만** 표시한다. S01~S18 전체 사례 제공 목록을 화면에 항상 표시하지 않는다.
- **C05 오른쪽**: ROAS 필터와 리뷰 필터의 **계산 범위는 독립적**이다. 하지만 이를 설명하는 긴 안내문을 항상 고정 표시하지 않는다.
- **C32 오른쪽**: 리뷰 ID는 고유 집계, 원문-분류 매칭, 테스트와 내부 추적에 사용한다. **별도의 ID 노출 상세 화면/상시 표시 UI는 만들지 않는다.**
- **최신 PoC 기간 지시**: 최근 7/30/90일, 자유 날짜 선택은 하지 않는다. **14일 비교기간(baseline), 14일 분석기간(current), 두 기간 전체(both)**만 선택한다. 기본값/전체 초기화 후 기본값은 **분석기간 14일**이다.
- **인터뷰 65 A, 66 B**: 좁은 화면의 6열 테이블은 테이블 내부에서 가로 스크롤, **고정 컬럼 없음**. 이 주제로 추가 인터뷰를 하지 않는다.
- 이전의 12건씩 더 보기, 자유 검색 제외, 단일 판매처/카테고리, 두 기간 비교표와 세부 경험 패널 중심 화면은 복원하지 않는다. Intent의 분석 목표 A/B/C는 데이터 검산과 인수 평가에 유지하되 **이를 위해 미확정 UI를 추가하지 않는다**.
- 분류 정정/편집, 감성 해석, 리뷰와 광고의 인과 자동 분석, 상품 선택기 추가는 범위 밖이다.

## 4. 구현할 화면의 정확한 구성

기존 ROAS 분석 아래에서 리뷰 섹션의 세로 순서는 다음과 같다.

1. **요약 카드 3개**: 전체 리뷰 수, 평균 평점, 최다 언급 카테고리
2. **상위 카테고리 분포 가로 막대그래프**
3. **리뷰 원문 테이블**

현재 사례/상품 1의 식별과 리뷰 자료 제공 상태는 리뷰 섹션 상단에서 확인 가능해야 한다. 판매처와 기간 필터는 그래프 위, 카테고리 선택과 원문 검색은 테이블 위에 둔다. 전체 사례 제공 현황 리스트를 추가하지 않는다.

### 4.1 필터와 요약 카드의 계산 범위

- 판매처는 다중 선택 OR, 기본 전체. 기간은 baseline/current/both 중 단일 선택, 기본 current.
- 두 필터는 **요약 카드, 그래프, 원문 테이블 전체**에 적용한다.
- 카테고리 필터는 다중 선택 OR, 미분류 선택을 포함하고 **원문 테이블에만 적용**한다. 그래프 막대 클릭과 선택 상태를 양방향 동기화한다.
- 키워드 검색도 **원문 테이블에만 적용**하고 요약 카드 및 그래프 수치를 변경하지 않는다.
- 카드의 '전체 리뷰 수'와 테이블 제목 옆의 '현재 검색/카테고리 필터 적용 결과 건수'는 달라도 정상이다.
- 모든 건수는 고유 리뷰 ID로 계산하고, 평균 평점은 실제 유효한 평점만 분모로 사용한다. 최다 카테고리가 공동 1위라면 두 개를 직접 표시하고 나머지는 +N 형태로 접는다.
- 작성일로 baseline/current를 구분하고 수집일은 해당 스냅샷 보고 기준 적격성 검증에만 사용한다. S16/S17 원천 예시의 비교기간은 2026-08-03~08-16, 분석기간은 2026-08-17~08-30. 실제 조회는 **사례별 ROAS 원천 기간**과 시작 포함/종료 미포함 시각 경계를 사용한다.
- 사용자가 두 기간 전체를 선택하면 14일 두 구간을 합친 범위를 조회한다. 새로운 리뷰나 미제공 기간을 생성하지 않는다.

### 4.2 카테고리 그래프

- 가로 막대, 모든 카테고리에 동일한 기본 강조색, **0~100% 고정 축**.
- 각 카테고리의 언급 고유 리뷰 수 n과 기간/판매처 전체 고유 리뷰 수 N의 비율 n/N을 보여준다. 복수 분류로 비율 합계가 100%를 넘을 수 있음을 안내한다. N=0일 때 계산 불가를 0%로 위장하지 않는다.
- 언급 많은순(기본), 적은순, 가나다순. 빈도 동률은 가나다순 고정.
- 기본 상위 5개, 전체 보기/접기 지원. 현재 선택된 카테고리가 상위 5개 밖이면 자동으로 전체를 펼치되 사용자가 다시 접을 수 있다.
- 막대 클릭은 카테고리 선택 추가/해제. 카테고리 선택이나 원문 검색으로 그래프 집계 자체가 변경되면 안 된다.
- 미분류는 그래프 막대로 그리지 않고 테이블 필터 선택지만 제공한다.

### 4.3 리뷰 원문 테이블

6개 열과 너비 비율을 유지한다.

| 순서 | 열 | 비율 |
| --- | --- | ---: |
| 1 | 판매처 | 12% |
| 2 | 작성일 | 12% |
| 3 | 평점 | 8% |
| 4 | 분류 카테고리 | 32% |
| 5 | 원문 확인 | 9% |
| 6 | 리뷰 원문 | 27% |

- 작성일 내림차순 기본, 작성일/판매처/평점 헤더 정렬 제공. 날짜/평점이 없는 값은 '—'로 표시하고 오름차순/내림차순 모두 항상 마지막에 놓는다.
- 분류 카테고리는 최대 칩 3개 후 +N, 해당 셀 내에서 나머지 펼침/접기.
- 리뷰 원문은 기본 **2줄 미리보기**. **원문 셀을 클릭할 때에만** 같은 셀 안에서 전체 원문 펼침/접기. **여러 리뷰의 원문을 동시에 펼칠 수 있고, 행 전체 클릭은 금지**한다.
- 원문 텍스트가 없으면 '원문 없음', 원문 URL이 없으면 '링크 없음'. 유효한 URL이 제공될 때만 '원문 보기' 새 탭 링크를 사용하고 URL을 임의 생성하지 않는다.
- 페이지네이션은 20건 기본, 10/20/50 선택, 번호 이동/이전/다음.
- 테이블 제목 옆에 실제 **필터 및 검색 적용 결과 건수**를 표시한다. 화면 너비가 좁으면 테이블 안에서 좌우 스크롤하며 컬럼을 sticky 처리하지 않는다.
- 원문 테이블 하단에 **현재 사례 전체 적격 원문 기준의 수집 기간**을 표시한다. 사용자 필터가 바뀌어도 수집 범위 문구는 그대로 유지한다.

### 4.4 원문 검색

- 판매처, 카테고리 또는 별점이 아닌 **리뷰 원문 텍스트**에서만 검색한다.
- 입력 문구 앞뒤 공백 제거, 내부 공백 유지, 연속 부분문자열 매칭, 영문 대소문자 무시.
- 입력 중단 **약 300ms** 후 자동 적용, Enter 즉시 적용. 별도 검색 버튼 불필요.
- 일치 문구가 원문 첫 2줄 뒤에 있으면 접힌 미리보기는 **첫 일치 주변 2줄 분량**으로 바꾸고, 펼친 전체 원문에서는 **모든 일치 위치**를 강조한다. 원본 텍스트는 수정하지 않는다.
- 검색어 삭제 × 제공, 전체 필터 초기화 시 검색어도 비운다.

### 4.5 상태 전환 및 예외

- 필터/검색 적용, 정렬, 페이지당 건수 변경 시 1페이지로 이동하고 펼친 리뷰 원문을 접는다. 페이지 변경 시에도 접는다.
- **같은 사례에서 위아래 스크롤만 하는 경우**에는 검색, 필터, 정렬, 페이지, 펼침 상태를 모두 유지한다. **별도 탭이 없으므로 탭 전환 로직을 새로 만들지 않는다.**
- **사례 변경 시** 리뷰 필터, 검색어, 정렬, 페이지, 페이지 크기, 그래프 펼침, 원문 펼침 상태를 전부 초기화한다.
- **미제공/제공된 0건/필터 결과 0건/전체 조회 오류/부분 조회 오류/분류만 오류/로딩**을 의미대로 분리한다. 미제공은 0건이 아니고, 오류는 미제공이 아니다. 오류 시 해당 리뷰 영역에 재시도 제공, 정상 ROAS에는 오류 전파 금지.
- 데이터 일부만 검증되면 정상 데이터만 제공하고 '일부 결과만 집계됨'을 명확히 알린다. 검수 전 분류를 미분류로 바꾸지 않는다.

## 5. 데이터 안전 및 통합 경계

- 해당 UI는 승인된 리뷰 원문 및 분류 결과를 **읽기 전용**으로 사용한다. 현재 확인 시점(2026-11-03)에 data/roas-reviews.json과 별도 분류 파일은 저장소에 아직 존재하지 않았다. **다음 에이전트는 작업 시점의 실제 파일과 승인 상태를 다시 확인**한다.
- 데이터 담당 작업에서 승인된 roas-reviews/1 원문 계약 및 ID/판매처 코드와 최신 증거를 확인한다. **리뷰 48건 생성 승인과 별도 분류 파일/조회 DTO/상품 공통 메타데이터/로더 승인 여부를 혼동하지 않는다.** 현재 유효한 승인 범위만 사용한다.
- 데이터 SDD에서 원문 48건은 S16 24건, S17 24건, 각 사례 baseline/current 각각 12건이 계획돼 있다. 실제 생성, 1,128쌍 중복 검사, A/B/C 독립 검산 및 분류 연결 완료 여부는 **검사 증거 없이는 완료라고 표시하지 않는다**.
- 캠페인, 기기, 광고, 고객, 주문 ID와 리뷰 사이의 가상 관계를 생성하지 않는다. 기존 ROAS 원천의 필드나 숫자를 수정/재생성하지 않는다.
- 별도 분류 원천이 준비되지 않았으면 카테고리 그래프를 가짜 값으로 채우지 않는다. 실제 승인 데이터가 없는 상태에서는 읽기 전용 뷰 로직과 상태 화면, 입력 경계 및 단위 테스트를 먼저 개발한다.
- 특히 기존 필수 manifest에 리뷰 파일을 무조건 추가하지 않는다. 잘못된 데이터가 ROAS 로더 및 빌드 전체를 중단시키지 않도록 오류 격리/데이터 계약을 승인 후 구현한다.
- **데이터 스키마, 새 파일, 신규 예시 레코드, 더미/seed 데이터 생성은 별도 명시 승인을 확인해야 한다**. 미승인 계약을 임의로 확정해 실제 데이터를 연결한 것처럼 표현하지 않는다.
- '분류 데이터를 검수하고 수정'하는 화면은 이번 구현 범위 밖이다. 현재 데이터 SDD의 A/B/C는 생성 및 검산 목표이지 자동 인과 판정 규칙이 아니다.

## 6. 구현 순서

1. 기존 성과 현황 구성, ROAS 상태 흐름, 데이터 소스를 파악하고 변경 전 회귀 기준을 확보한다.
2. **기존 ROAS 영역 아래**에 리뷰 섹션을 추가한다. 현재 사례/상품 식별자 및 제공 상태를 연결하되 기존 ROAS 탐색과 차트를 보존한다.
3. 요약 카드, 카테고리 그래프, 6열 원문 테이블을 기존 디자인 시스템과 공용 컴포넌트를 재사용하여 구현한다.
4. 리뷰 ID 중복 제거, 판매처/기간 필터, 카테고리 OR 필터, 검색 및 강조, 안정 정렬, 페이지네이션을 **UI 렌더링과 분리된 순수 함수/선택자**로 구현한다.
5. 리뷰 상태 변경, 사례 변경, 오류/비동기 경합 처리와 키보드 접근성 및 가로 스크롤을 구현한다.
6. 데이터 담당 작업에서 실제 승인된 입력과 검증 증거가 준비되면 **해당 계약만** 연결한다. 미승인 상태면 UI를 검증한 범위까지만 완료 처리한다.
7. 기존 ROAS 및 신규 리뷰 검증과 CI 반영을 마친 뒤 결과를 보고한다.

## 7. 테스트와 인수 기준

기존 스크립트가 존재하는지 확인하고 **코드 변경 후** 아래를 실행한다.

- npm test
- npm run test:roas
- npm run test:training
- npm run lint
- npm run build

추가 자동 테스트의 핵심은 다음과 같다.

- **C01/C04/C05/C32:** ROAS 아래 리뷰 섹션, 별도 탭 없음, 현재 사례 제공 상태만 표시, 필터 독립성, 별도 리뷰 ID UI 없음
- 두 14일 기간의 **시작 포함/종료 미포함** 경계 및 current 기본값, both 합집합
- 판매처/기간이 카드, 그래프, 테이블에 반영되며 카테고리/검색은 **테이블에만** 적용
- 복수 카테고리, 중복 리뷰 ID 제거, 평균 평점의 유효 분모, 카테고리 0~100% 축과 동률 처리
- 원문 셀만 펼치기, 다중 펼침, 카테고리 +N, 검색 300ms/Enter, 반복 일치 강조
- 10/20/50건 페이지네이션, 정렬 시 결측 마지막, 필터/페이지 변경 시 펼침 접기
- 단순 스크롤 시 상태 유지와 **사례 변경 시 전체 초기화**
- 미제공/제공된 0건/검색 결과 0건/전체 오류/부분 오류/분류 오류, 리뷰 오류 시 ROAS 무영향
- 좁은 화면 가로 스크롤, **고정 열 없음**, 키보드/접근성
- **기존 ROAS KPI, 필터, 정렬, 캠페인/기기 분석, 상세 탐색 및 채팅 회귀** 확인

중요한 신규 테스트가 CI에서 빠져 있다면 현재 CI 워크플로를 확인하여 추가한다. 실패가 발생하면 기존 실패인지 이번 변경으로 생긴 실패인지 구분한다. 실행하지 않은 테스트를 통과했다고 적지 않는다.

## 8. 금지 행동과 완료 보고

**금지:** 새 UI 인터뷰 반복, 최신 결정 무시, ROAS 영역 재설계, 임의 비교표/상태/분류/리뷰 생성, 기존 데이터와 미커밋 작업 덮어쓰기, 근거 없는 성공 주장, 명시 승인 없는 커밋·푸시·병합·배포.

**최종 보고:** (1) 바뀐 소스 파일, (2) 실제 화면에서 작동하는 기능, (3) 미구현/데이터 의존성, (4) 실행한 테스트·린트·빌드 결과, (5) 기존 ROAS 회귀 결과, (6) CI 반영 및 브라우저 확인, (7) 사용자 추가 승인 필요한 항목, (8) Git 상태.

**완료 판정은 분리한다.** 프론트 화면과 상호작용 구현 완료, 원문 데이터 연동 완료, 분류 데이터 연동 완료, 최종 제품 인수는 서로 다른 상태다. 실제 데이터가 없으면 'UI 구현 가능 범위 완료, 원천 연동 대기'라고 정확하게 보고한다.
