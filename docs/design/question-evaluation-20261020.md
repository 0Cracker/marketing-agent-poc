## v1 → 별도 에이전트 리뷰 → v2

v1은 CURRENT의 3국가·4원인, 범위 변경·후속·경계·결측을 검사하는 독립 runner를 제안했다. 별도 strict reviewer는 오프라인 통과를 질문 이해로 오인할 위험, 사후 기대값 선택, 결측의 0 대체, 범위 모순의 과대 판정을 지적했다.

v2는 33개 ID와 정확한 상태·사유를 실행 전에 고정한다. 기대 금액·점유율은 원천 JSONL에서 별도 정수 연산으로 계산한다. 분모는 선택 제품 합계가 아닌 해당 국가·월의 원본 market_total_value이며, 현재 API의 소수 6자리 반올림 문자열과 정확히 대조한다. JP T13 기존 NULL 두 행을 모든 페이지에서 찾아 5필드의 null·missing·partial을 확인한다. 국가·기간 모순은 코드 경로의 capability gap 두 건으로 별도 표기하며 의도 이해 여부를 오프라인으로 판정하지 않는다. 새로운 마케팅 자료·스키마·원천 값은 만들지 않는다.

## 실행과 결과

구현 대조 리뷰에서 반환된 일부 필드만 검증하면 누락 필드를 놓치는 문제가 지적됐다. 원천의 전체 필드 집합·단위, 시장 product/period, 국가·월 분모 동일성, 비가격 관계의 정확한 타입·상위 24행 ID를 추가했다. 보강 후 별도 reviewer는 추가 차단 사항 없음을 확인했다.

예비 1차는 oracle가 캠페인 유효기간을 측정기간처럼 완전 포함하도록 잘못 검사해 30통과·3실패였다. 캠페인은 기간 중첩으로 판정한다는 기존 계약에 맞춰 oracle를 고쳤고, 예비 2·3차는 각각 33통과했다. 실패 Evidence는 보존했다. 이는 제품 코드의 세 버그를 수정했다는 뜻이 아니다.

`node scripts/evaluate-agent-questions.mjs --output evidence/v0.4.0/question-evaluation-20261020`로 새 출력 디렉토리에 기록한다. 기존 디렉토리는 덮어쓰지 않는다. SQLite는 메모리만 사용하며 기존 서버·DB는 변경하지 않는다. 구현 중 결과는 preliminary이며, 오류 처리 수정 완료 후 동일 최종 코드 해시로 재실행한 결과를 최종 증거로 삼는다.

2026-10-20 최종 실행은 `EVALUATION_STAGE=final`을 설정하고 위 명령으로 수행했다. [JSON 결과](../../evidence/v0.4.0/question-evaluation-20261020/report.json)와 [요약](../../evidence/v0.4.0/question-evaluation-20261020/report.md)은 명시 범위 계약 **33통과·0실패·0미실행**, 데이터·관련 코드 해시 불변, 외부 호출·신규 마케팅 자료·실제 Ads 0을 기록한다. JP T13은 5개의 관측 페이지를 순회했고, 기존 두 NULL 행의 10개 필드가 결측으로 유지됐다. 실제 LLM 질문 품질·UI 이해는 여전히 미실행이다.

**별도 발견사항:** 화면이 JP·8월일 때 질문에 “미국”, “7월”을 써도 클라이언트는 현재 화면 scope를 보낸다. 자연어로 범위를 바꾸는 자동 라우팅이 없으며 화면 필터를 직접 바꿔야 한다. 이 두 정적 capability gap을 33개 계약 통과나 실제 모델의 질문 이해 성공/실패에 합산하지 않는다.

## 실제 모델 후속 평가안

별도 명시 예산이 확정되기 전 실제 모델은 호출하지 않는다. 선택안은 KR 가격·US 가격·JP 재고·JP 후속의 4건, 각 최대 6회로 총 24회다. 요청 직전 영속 누적 카운터로 25번째 요청을 차단하고 실패·재개도 같은 예산에 포함해야 한다. 전용 DB와 새 Evidence를 사용한다. 사전 기준은 기대 도구 사용·원천 수치·반대 근거·비인과·부모 범위 보존이며, 질문 의도 적합성·설명 이해는 별도 사람 검수다. 이 runner는 해당 live 기능을 구현하지 않으며 `--live` 인자를 거부한다.
