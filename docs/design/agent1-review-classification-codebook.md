# Agent1 EDU-P1 샴푸 리뷰 분류 코드북, 2026-11-03

> 최신 범위는 아래 '2026-11-05 승인 증량 반영' 절을 따른다. 50건과 63개 경험에 관한 앞선 본문은 2026-11-03 당시의 기록이다.

## 승인 범위와 상태

- 사용자 확정: EDU-P1은 펌프형 샴푸(표시명 `쓱쓱샴푸`), 상위 카테고리 **5개**, 세부 경험 **18개**, 평가 방향 **긍정/부정/중립/혼합**. 사용자가 승인한 짧은 표시명을 그대로 사용한다.
- 자료 범위(최신 확정): `data/roas-reviews.json`의 **S16/S17 각 25건, 총 50건**, `REV-S16-001`~`025`, `REV-S17-001`~`025`. 앞선 48건의 원문, 평점, 날짜, 판매처와 기존 ROAS는 모두 보존하고, 승인된 2건만 추가했다. 비교기간은 사례당 12건, 분석기간은 13건이다.
- 산출물: `data/roas-review-classification.json`은 **별도 sidecar**이며 원문이 아니다. 계약 `roas-review-classification/1`, 분류 사전 버전 `1.0.0`, 기존 리뷰 원문 SHA-256에 결합된다.
- 원문 작성일로 baseline/current 소속을 정하고, 수집일은 보고 기준까지 확보되었는지만 확인한다. 리뷰와 캠페인/기기/실제 구매자 사이 관계를 추정하지 않는다.

## 적용 규칙

1. **한 리뷰에 복수 세부 경험을 허용**한다. 원문에 적힌 한 경험은 리뷰당 동일한 세부 코드로 **한 번만** 기록한다. 다른 상위 경험이 여러 개라면 상위 분류도 여러 개다.
2. `sentiment`는 리뷰 평점이 아니라 **해당 세부 경험에 대한 문장 내용**으로 판정한다: `positive`(좋다고 평가), `negative`(불편/불만), `neutral`(사실 기술이지만 명확한 선호 없음), `mixed`(**동일 세부 경험** 안에 장단점이 함께 존재). 서로 다른 경험의 긍정/부정은 `mixed` 하나로 합치지 않는다.
3. `evidenceQuote`는 반드시 해당 리뷰 `text` 안에 있는 **그대로의 연속 부분 문자열**이다. 문장 일부만 선택해 잘못된 판정이 되지 않도록, `mixed`의 양면성은 가능한 두 의견을 모두 담은 연속 구절로 인용한다.
4. `용량 표기`는 용량 글씨/인지/사진 대비 크기, `소진 속도`는 실제 사용 후 체감 소모, `사용량 안내`는 적정량 설명, `잔량 확인`은 현재 남은 양의 가시성을 각각 다룬다.
5. **배송 vs 제품 포장:** 택배 상자 손상/젖음, 도착 시각은 배송으로, 내부 완충재와 병 보호 구조는 제품 포장으로 분류한다. 같은 문장에 양쪽 사실이 있으면 양쪽 근거에 따라 복수 태그를 부여한다.
6. `누액 및 잔액`은 실제 내용물 묻음, 노즐 잔액, 조건부 새어 나옴을 포함한다. **잔액이 묻었다고 곧바로 용기 전체의 누수로 단정하지 않는다.** 손이나 머리에 남는 샴푸 느낌은 `잔여감`이다.
7. `향 지속`에는 사용 후 남는 시간뿐 아니라 드라이 과정에서 **향이 시간에 따라 변하는 경험**도 포함한다. 변화 자체를 별도 19번째 분류로 만들지 않는다.
8. 타인이 싫어한다는 언급만으로 **리뷰 작성자의 긍정**을 `mixed`로 바꾸지 않는다(S16-013). 별점이 2점이어도 '거품 만족'은 긍정이다(S17-001).
9. **강제 분류 금지:** 실제 근거가 없는 일반적 세정 만족이나 사용 설명에 관한 코멘트를 관련 없는 세부 항목으로 끼워 넣지 않는다. 분류하기 어려운 원문 일부는 검수서에 기록하고, 전체 리뷰의 다른 확정 경험은 그대로 유지한다. 신설 세부 코드가 필요하면 사용자 승인 후 사전 버전을 갱신한다.

## 저장 및 집계 계약

- 최상위: `contract`, `taxonomyVersion`, `productId`, `sourceReviewSha256`, `sentiments`, `categories`, `experiences`, `reviewClassifications`.
- `reviewClassifications[]`: `reviewId`, `status: classified|unclassified`, `assignments[]`을 포함. `classified`에는 최소 1개 이상의 근거 있는 경험이 있어야 한다. 검수 완료 후 근거가 없는 `unclassified`는 `assignments: []`이고, `pending`은 완료로 취급하지 않는다. `assignments[]`: `categoryId`, `experienceId`, `sentiment`, `evidenceQuote`.
- **검수 상태**는 원문 분류 준비 완료 여부만 가리키며, 사용자 또는 인간 2차 검수자가 인증했음을 뜻하지 않는다. 검수 과정은 별도 Evidence 문서에 둔다.
- 전체 표본수는 원문 ID 고유 개수(**미분류 2건 포함 총 50건**). 상위 건수는 그 상위를 한 번 이상 언급한 원문 ID의 **고유 개수**. 세부 경험도 각각 고유 ID 개수. 한 리뷰가 다수 상위에 해당하므로 **상위 합계 100%를 강제하지 않는다**.
- 기간과 출처별 집계는 리뷰 원문의 작성일과 판매처로 먼저 원문 모집단을 형성한다. 카테고리별 평가 방향 건수는 **세부 경험 단위**의 집계로 별도 표시하며 리뷰 전체 평가/별점과 혼동하지 않는다.
- 원문 SHA 변경, 누락된 리뷰, 근거 구절 불일치, 승인 밖 경험 코드, 중복 분류, 미완료 상태, 부모-자식 불일치가 나면 **조회 집계를 거부**한다.

## 검증과 현재 한계

- `node scripts/validate-roas-review-classification.mjs`, `node --test tests/roas-review-classification.test.mjs`로 자동 재검증한다. GitHub Actions `review-classification-validation.yml`에도 등록했다.
- 별도 Python 표준 라이브러리 경로로 최신 50개, 63개 경험 분류, 미분류 2건, 상위/세부 건수, 1,225쌍 정규화 중복 및 원문 부분 문자열 일치를 독립 재계산한다. 이전 48건, 1,128쌍 검수는 역사적 스냅샷으로 보존한다. 이는 **독립 언어/경로 자동 검산**이며 **서로 다른 인간 2명의 분류 합의는 아니다**.
- 최초 데이터 SDD에 남은 사람이 서로 다른 1차/2차 검수자 전수 검수와 이견 시 3차 판정 절차는 아직 별도 업무로 남는다. 인간 검수가 완료됐다고 기록하지 않는다.
- 세부 사용량이 1건뿐인 항목도 사용자 확정된 18개이므로 임의로 삭제하지 않았다. 작은 표본은 원인/인과 판단에 사용하지 않는다.

## 2026-11-05 승인 증량 반영

S16 신규 35건을 추가해 S16 60건, S17 25건, 전체 85건으로 확장한다. S16 비교기간 27건, 분석기간 33건이며 판매처별 비교 자사몰/쿠팡 9/18건, 분석 자사몰/쿠팡 20/13건이다. 기존 50건의 외부 표시명만 쿠팡으로 바꾸고 나머지 필드와 기존 50개 분류 항목을 보존한다.

신규 35건은 단일 경험 23건, 복수 경험 10건, 미분류 2건이다. 전체 경험 할당은 106개, 미분류는 기존 두 건과 REV-S16-040/060을 합한 4건이다. 040은 개봉 후 선물 전달만 하고 직접 사용하지 않은 후기, 060은 주문 과정만 평가한 후기로 경험을 강제 부여하지 않는다. 상위 5개와 세부 18개, 사전 정의와 버전 1.0.0은 바꾸지 않는다.

대표 주제 배분과 후기 작성 시점의 사용 맥락은 별개다. 포장과 배송을 평가해도 며칠 사용 후 작성할 수 있다. [맥락 검수표](../../evidence/review-expansion-20261105/contexts.json)의 첫 사용/개봉 12건, 며칠 사용 13건, 반복 사용 6건, 수령 직후 4건을 원문 문구로 확인한다. 이 표는 제품 스키마가 아니다.

독립 의미 검토에서 신규 038의 기존 022와 유사한 조합을 발견해 부위별 사용량 안내의 한계와 제형 도포 관찰로 구체화했다. 분류는 사용량 안내 부정, 제형 및 도포 중립이며 대표 주제와 총 할당 수를 유지한다. 이전 48/50건 검수 기록은 당시 스냅샷으로 보존한다. [이번 검증 기록](../../evidence/review-expansion-20261105/validation.md)
