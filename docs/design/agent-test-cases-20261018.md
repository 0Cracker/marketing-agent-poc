# 두 에이전트 단계별 테스트 케이스

입력 자료는 승인된 기존 카탈로그다. 아래의 오류 값·제어 응답·장애는 요청/실행 조건이며 마케팅 원천을 변형한 레코드가 아니다. 실제 테스트의 인자·전제·검산·부수효과 검사는 [테스트 코드](../../tests/agents/)에 있다. [설계·결과](agent-tdd-20261018.md)를 함께 따른다.

## 공급자 연결과 통합

| ID | 입력·실패 조건 | 기대 결과와 차단 위치 |
| --- | --- | --- |
| M01 | Gemini/Groq 정상 JSON 행동 응답 대역 | 공통 도구 호출로 해석. 키는 본문/로그에 없음 |
| M02 | 전송 허용 옵션 없음 | 객체 생성 거부·네트워크 0회 |

| M06 | HTTP 429 | quota_exhausted, 자동 재시도 0회 |
| M07–M08 | HTTP 503/401 | 안전한 model_failed, 응답의 키 문자열 노출 없음 |
| M09 | 타임아웃 | model_timeout, 흐름 저장 후 재개 가능 |
| M10–M12 | 빈 응답·잘못된 JSON·프로토콜 위반 | model_protocol |
| E01 | 실제 카탈로그→분석→예산→후속 질문 | 오프라인 대역임을 표시, 기존 제안 무효화, 외부 호출/새 원천 0 |
| E02 | 큰 정수·소수와 잘못된 금액 표현 | 정확한 정수 계산, NaN/부동소수/음수/과도한 정밀도 거부 |
| E03 | 시장점유율 계산 | 독립 분자/분모 계산과 표시 오차 범위 내 일치 |

일부 ID는 국가·오류·응답 상태별 반복 실행을 포함하므로 표의 ID 개수와 테스트 러너의 실제 실행 개수는 다르다. 실행 개수는 결과 보고서와 TAP 로그를 기준으로 한다. 실패 로그는 수정 후에도 보존한다.
