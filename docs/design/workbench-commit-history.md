피드백마다 전체 소스가 보존된 것은 아니므로 당시 상태를 추측해 복원하지 않았다. 두 번째 커밋은 논리적 변경 묶음이며 당시 소스 전체의 완전한 스냅샷은 아니다. 세 번째 커밋도 개별 후속 요청마다 가짜 중간 버전을 만들지 않고 결합했다. 기존 [10월15일 기록](workbench-refinement-20261015/README.md)과 [10월16일 기록](workbench-comments-20261016/README.md)의 실제 피드백·전후 화면을 함께 참조한다. 보존본을 인덱스에만 올려 현재 작업 파일을 이전 상태로 덮어쓰지 않았다.

보존 위치는 workspace 바깥의 `../dashboard-design-history/2026-10-16-before-feedback-commits/`이며 최초 modified/untracked 파일96개의 사본·SHA-256을 저장했다. 신규 자료 생성이 아니라 기존 작업 파일 보존이다. 커밋 과정에서 원천·명세 원문·이전 스냅샷을 수정하지 않았다. 명세 원문 SHA-256은 `891eac80d6be827a20ba229877db7ac5d578bd01edc13cfe8dd71c260335126a`다.

검증: 최종 소스의 TypeScript·워크벤치 ESLint·원천/수치 검사·Vite 빌드 종료0. 수치 검사는11원천/1,652행·12국가월 사례와 별점/단위/결측을 대조했다. 기존 Next pages 안내와500KB 청크 경고는 유지한다. 분리한 두 번째 커밋은 인덱스를 별도 사본으로 내보내 TypeScript 검사 종료0을 확인했다. 최초 구현은 실제 보존본과 당시 수용 기준·검증 자료를 사용했으며 이 커밋 분리 과정에서 최초 상태의 브라우저 검증을 새로 실행한 것은 아니다. 이번에 동작을 수정하지 않아 기존 최종 브라우저 검증과 캡처를 보존한다.

Git 작성자가 비어 첫 커밋 명령은 실패했다. 사용자가 제공한 작성자 정보를 이후 커밋 명령에만 지정했으며 전역·저장소 user 설정은 바꾸지 않았다. 원문 명세의 Markdown 줄바꿈용 공백과 폰트 라이선스 원문 공백은 수정하지 않고 보존했다.

[데이터 처리와 대시보드 분리 문서](dashboard-data-separation.md)는 방향과 이행 기준이다. 새 구조의 코드 분리·데이터 재생성·D005/D006 화면 연결·새 버전 발행은 수행하지 않았다.
