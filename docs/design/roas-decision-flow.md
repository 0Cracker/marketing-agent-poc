# 구매 매출 ROAS 의사결정 흐름

작성일: 2026-10-21. 브랜치: `feature/roas-decision-flow`. 시작 SHA: `19f63fc`. 발행 버전은 미정이며 기존 버전, 태그를 변경하지 않는다.

## 확정 범위

담당자 한 명이 특정 제품의 ROAS 하락을 확인하고 현황, 원인 후보, 인사이트, 광고와 구매 과정 수정안 또는 매체별 예산 검토안을 완성한다. 대표 KPI는 할인 후 상품 구매금액에서 확정된 취소, 환불을 중복 없이 차감하고 세금과 배송비를 제외한 구매 매출 기준 ROAS다. 매체 보고 ROAS를 별도 표시한다. 목표 ROAS나 예산 변경 비율은 임의로 만들지 않는다.

사용자는 업무 구축, 별도 브랜치, 필요 데이터 증강의 계획 수립을 요청하고, 상세 수량과 관계, 검산 제안에 “제안 범위 생성 승인”으로 응답했다. [승인 원문과 규칙 해시](../../evidence/roas-decision-flow-20261021/generation-approval.json)를 보존한다. 현재 원천, 결측값, 과거 승인과 검증 원본은 보존한다. 대시보드 재설계, 외부 모델, 실제 Ads, 발행은 범위 밖이다.

## 성공 기준과 검증 계획

1. 동일 14일, 요일 구성, 통화, 구매 목표, 귀속 기준에서 합계 분자와 분모로 ROAS를 계산한다.
2. 클릭 기준 전환율과 세션 기준 전환율을 구분한다. 구매 수와 상품 행 수를 혼용하지 않는다.
3. 세션 사건 순서, 구매와 주문, 취소와 환불, 리뷰와 문의의 참조 무결성을 확인한다.
4. 할인 후 상품금액의 두 산식을 대조하고 확정 금융 사건을 한 번만 차감한다. 부분 환불, 대기 상태, 완료 반품, 기간 뒤 환불을 구분한다.
5. 기준일을 명시하고 과거 평가기간의 원주문에 환불을 반영한다. 기준일 이후 처리는 반영하지 않는다.
6. 수치 분해는 산술 설명이다. 원인 후보, 반대 근거와 미확인 사항을 분리하고 근거 없는 예산 변경은 보류한다.
7. 검토서에 수정 대상, 수정 내용 또는 매체별 예산 검토 방향과 보류 조건을 남긴다. 예산 액수, 비율, 목표는 입력 없이는 산출하지 않는다.
8. 재실행 해시 일치, 기존 30,327행과 source/archive 불변, 기본 대시보드 조회 결과 불변, 관련 기존 회귀를 확인한다.

### 승인 후 구현과 검증

- [생성 결과](../../evidence/roas-decision-flow-20261021/generation.json): 정확히 3,470행, 물리 합계 33,797행이다. 기존 30,327행은 파일 바이트 접두부 해시로 불변을 확인했다. 원천 10파일을 해시 스냅샷으로 보존하고 provenance와 migration에 연결했다. 정의 메타데이터의 [식별자 등록 완료](../../evidence/roas-decision-flow-20261021/metadata-completion.json)는 마케팅 행 추가 없이 수행했고 기존 정의를 보존했다.
- 업무 필드는 추가하지 않았다. 구매 전 세션 사건 순서, 거래, 주문, 상품, 수량과 시각, 일별 매체 보고 구매 수와 구매 매출을 서로 대조했다. 이 첫 표본은 당일 구매로 제한한다. 7일 귀속 설정을 가졌다는 이유로 지연 구매나 여러 접점의 귀속 검증까지 완료했다고 보지 않는다.
- 서브 에이전트의 읽기 검토에서 주문 수와 세션 전환율의 분모 차이, 기준일 이후 사건, 구매와 주문 연결 검산, 금융 대표행 모순을 발견했다. 구매 전환율을 고유 구매 세션 기준으로 계산하고, 기준일과 당일 구매 범위, 거래와 세션 대사, 금융 대표행 상태와 시점을 검증하도록 수정했다.

### 2026-10-22, 검토안 저장 제안, 승인 대기

작업 시작 요청을 받아 현재 저장 경로를 확인했다. 검토안은 React 상태에만 있고 Markdown 내보내기는 가능하다. 기존 agent_documents는 로컬 Agent 실행과 승인 기록용이며 다중 사용자 로그인은 없다. 공개 화면은 정적 배포이며 D1 연결도 없다. 기존 Agent 기록에 새 검토안을 섞지 않는다. 스키마 항목의 개별 승인을 받기 전으로 저장 코드와 저장소, 검증용 데이터를 만들지 않았다.

첫 구현은 브라우저 저장과 JSON 검토안 파일 내보내기, 불러오기를 추천한다. 같은 브라우저와 같은 사이트 주소에서 복원하고 다른 PC에는 파일로 옮긴다. 다른 PC 자동 동기화가 필수라면 로그인과 사용자별 서버 저장으로 범위를 바꿔 별도 제안한다. 공유 사이트 최신화는 배포와 Git 이력 정리의 승인 대기 과제로 남아 있다.

| 제안 항목 | 타입과 규칙 |
| --- | --- |
| schemaVersion | 정수 1, 미지원 형식은 불러오기 거부 |

| title | 담당자 입력 문자열, 1~100자 |

| note | 담당자 메모 문자열 |

저장 키는 marketing.roas.reviews.v1로 기존 채팅 저장 키와 분리한다. 최대 20개 검토안, 수정 내용과 메모 각각 5,000자 이하, 불러올 파일 1MiB 이하를 제안한다. 원천과 계산 결과 전체를 복제하지 않고 작성 내용과 분석 기준만 저장한다. 기존 마케팅 행 생성과 변경은 0행이다. 최초 저장소는 비어 있고 사용자 저장 때만 검토안이 생긴다. 검증용 검토안은 최대 10개를 메모리, 임시 폴더와 검증용 브라우저 저장 공간에만 생성한다. 마케팅 데이터로 합산하지 않는다.

기능은 저장, 저장 목록, 다시 열기, JSON 내보내기와 불러오기다. 작성 중 다른 안을 열 때 교체 확인을 받고 파일 ID 중복 시 기존 안을 자동 덮어쓰지 않는다. 자료 해시나 비교 범위가 다른 안은 과거 초안으로 열고 현재 분석에 조용히 연결하지 않는다. 저장 실패와 잘못된 파일은 기존 안과 작성 내용을 보존한다. 다른 탭에서 저장 내용이 바뀌면 알리고 다시 읽도록 한다. 로그인, 서버 DB, 자동 동기화, 협업, 삭제와 이력 관리, 광고 실행은 첫 범위에서 제외한다.

검증 항목은 새로고침과 메뉴 전환 뒤 복원, 여러 검토안 분리, JSON 왕복 일치, 자료 불일치, 잘못된 형식과 근거 참조, 용량 초과와 저장 불가, 교체 취소와 파일 중복, 기존 Markdown 결과 일치다. 타입 검사와 빌드, PC 브라우저 확인, 기존 자료 해시 대조를 수행한다. 아직 실행하지 않았으며 통과로 기록하지 않는다.


### 검토안 저장, 승인 후 구현과 검증 진행

상세 항목의 승인 질문에 사용자가 “ㄱㄱ”으로 응답해 [개별 승인](../../evidence/roas-reviews-20261022/approval.json)을 기록했다. roas-review-store.ts는 구조와 길이, 비교 범위, 대상과 근거 관계를 검증하고 전체 저장 목록의 스냅샷과 revision을 대조한다. roas-reviews.tsx는 저장, 목록, 다시 열기와 파일 이동을 제공한다. 기본 분석 원천과 계산은 저장 파일에 복제하지 않는다. 브라우저 Web Locks를 사용해 같은 주소의 탭 사이 저장을 직렬화하며 지원하지 않는 브라우저에서는 파일 보관을 안내한다. 과거 자료의 초안은 별도 읽기 화면에서만 표시한다. 저장하지 않은 초안은 교체 전에 확인하고 Markdown에서도 의도적으로 비운 내용을 기본 문구로 되돌리지 않는다.

[17검사](../../evidence/roas-reviews-20261022/tests-final.txt), 타입 검사와 [빌드](../../evidence/roas-reviews-20261022/build.txt)를 통과했다. 린트 종료코드는 0이지만 같은 화면 파일에 다른 작업이 추가한 미사용 항목 경고가 있어 [로그](../../evidence/roas-reviews-20261022/lint.txt)를 보존했다. PC 브라우저에서 저장과 새로고침 복원, 선택과 예산 의견, 메모 복원, [JSON 내보내기](../../evidence/roas-reviews-20261022/export-check.json), [파일 불러오기](../../evidence/roas-reviews-20261022/import-check.json), 중복 ID 거부, [과거 초안 분리](../../evidence/roas-reviews-20261022/history-check.json), 목록에서 다시 열기를 확인했다.

기본 confirm 확인창에서 브라우저 조작이 막혀 HTML dialog로 교체했다. 교체 취소, 두 탭 상호작용과 최종 PC 화면 확인은 아직 완료로 기록하지 않는다. 같은 폴더의 차트와 검토서, 화면 파일에 다른 작업의 변경이 감지되어 사용자에게 동시 작업 여부를 확인했다. 그 변경을 되돌리거나 완료 결과로 가져오지 않는다. [검증 상태](../../evidence/roas-reviews-20261022/verification.json)를 분리해 남긴다. 저장은 같은 브라우저와 같은 주소에 한정되며 다른 PC에는 JSON 파일로 옮긴다. 원격 공유 배포와 자동 동기화, 서버 저장은 이번 구현에 포함하지 않았다.

### 2026-10-22, 엄격 검토 피드백 병렬 수정

사용자가 이 검토 작업에서 발견한 문제를 각각 병렬 수정하도록 요청했다. 검토서 출력, 원천 범위와 검토안 보존 점검을 분리했고, 주 작업은 화면 연결과 일별 차트를 수정했다. 같은 폴더의 별도 작업에서 구현 중이던 검토안 저장 구조를 재사용했으며 해당 저장 기능 전체를 이번 작업의 신규 구현으로 기록하지 않는다. 원천, 정의와 manifest는 변경하지 않았다.

화면에서 기존 데이터 탐색으로 이동해도 ROAS 컴포넌트를 유지해 입력 상태가 남도록 했다. 새로고침 전 저장 안내와 기존 미저장 이탈 경고는 유지한다. 이는 메뉴 전환 중 보존이며 자동 저장이나 PC 간 동기화는 아니다. 저장소 읽기 오류를 복구한 뒤에도 저장 버튼이 잠기던 문제를 수정했고, 빈 문자열의 저장과 JSON 복원 검사를 추가했다.

Markdown은 기존 분석 부분을 보존하고 Action 구간을 담당자가 선택한 수정안과 예산 의견으로 한 번만 교체한다. 선택한 빈 수정안은 내보내기를 막으며 미선택 후보를 담당자 안에 포함하지 않는다. 유지, 감액, 증액 검토에는 기존 메모의 `근거:`와 `재검토 조건:` 작성을 요구한다. 이 검사는 작성 여부만 확인하며 판단 내용의 타당성을 자동 승인하지 않는다. 출력에 자료 해시를 남긴다. 저장과 JSON 백업은 미완성 초안을 보관할 수 있도록 기존 동작을 유지한다.

성과 분석의 원천은 선택 매체와 두 비교기간의 광고, 유료 세션, 구매와 주문으로 제한했다. 전체 KPI와 제품 공통 의견은 이 매체 필터를 상속하지 않는다. 환불은 원주문 코호트와 확인 기준일을 따르고 원주문을 함께 조회할 수 있다. 현재 자료에서 해당 원천은 전체 3,276건, 검색 1,652건, 소셜 1,624건이며 기존 전체 조회에 섞이던 유기 방문 6건은 제외된다.

기본 추이를 대표 KPI와 같은 취소, 환불 반영 ROAS로 바꾸고 매체 보고값 전환을 제공한다. 일별 값은 백엔드의 기존 상품금액과 금융 대표행 계산을 재사용한다. 늦게 처리된 환불은 원주문의 유입 날짜로 반영하며 카드와 같은 기준일을 사용한다. 구매 흐름에는 직전 단계 대비 전환율을 추가했다. 원인 후보에 제품 공통 의견이라는 범위를 표시하고 사용감 만족을 배송 문제의 직접 반증으로 부르지 않도록 문구를 바꿨다.

[실행 검증](../../evidence/roas-feedback-20261022/validation.json)은 전체 Node 검사 177개, 이 중 ROAS 검사 28개와 독립 Decimal 검산 13항목 통과다. 일별 반영 매출은 두 기간과 두 매체의 카드 합계와 일치하며 기존 30,327행의 바이트 보존과 같은 데이터 해시를 확인했다. `test:roas`는 계산, 화면 응답, 출력, 저장, 원천 범위와 일별 추이 검사를 모두 실행하도록 바꿨다. 최종 타입, 린트와 빌드 로그는 같은 Evidence 폴더에 둔다.

PC 브라우저에서 기본 반영 추이, 전환 버튼과 기존 KPI 표시를 확인했다. 그러나 클릭과 키보드 활성화가 일반 버튼과 기본 details 모두에 전달되지 않았다. 새로고침, 새 탭과 브라우저 연결 초기화 후에도 같아 최종 화면의 메뉴 왕복, 저장 후 복원, 입력 오류 안내와 파일 내려받기를 완료로 기록하지 않는다. 별도 저장 작업의 이전 확인 결과와 이번 미검증 항목을 구분한다. 실제 모델, 실제 효과와 현업 유용성, 광고 집행과 배포는 검증하지 않았다. 별도 발행 버전이나 태그를 만들지 않았다.


### 2026-10-22, 마케터 조사 루프 피드백 반영

사용자의 후속 수정 요청에 따라 KPI 하락 확인, 문제 범위 축소, 설명 후보 비교와 다음 행동을 연결했다. 독립 에이전트는 기기와 의견 계산, 기존 메모를 통한 조사 복원, 수정안 검증을 분담했다. 기존 승인 자료만 재사용했고 마케팅 원천과 저장 스키마는 변경하지 않았다. 별도 발행 버전과 태그는 없다.

성과 요약에는 기준기간의 광고비 비중을 고정한 매체 내부 변화 성분을 표시한다. 소셜의 약 -116.18%p를 우선 조사 단서로 제공하되 인과 기여나 예산 우선순위로 해석하지 않는다. 성과 분석에는 매체와 기기별 유료 방문, 결제 시작, 구매, 완료율과 감소 건수를 연결했다. 소셜은 모바일 24→10건, PC 18→4건으로 각각 14건 감소하므로 완료율 낙폭만 보고 PC에 문제를 한정하지 않도록 한다. 기기 선택 뒤에도 기존 CPC와 ROAS 분해가 매체 전체 기준이라는 범위를 표시한다. 기기별 원천은 해당 세션과 광고 세부자료, 주문만 보여준다.

원인 후보에서는 제품 공통 의견을 전후 각각 28건에서 비교한다. 배송과 출고 언급은 0→23건, 결제 관련 언급은 0→18건이며 중복 가능한 분류다. 비교 후 주문 연결은 각각 16건, 12건이다. 이 자료는 구매 포기자의 원인 관측이나 매체와 기기별 인과 근거가 아니라고 명시한다. 배송과 금액 안내, 결제 기능, 유입 고객 구성, 측정과 집계를 나란히 두고 각 후보의 부족한 자료와 다음 확인을 제공한다. 초기에는 후보를 선택하지 않는다.

조사 매체, 기기, 단계, 후보와 판단 근거, 적용 조건은 기존 note 문자열의 읽을 수 있는 관리 구간에 저장한다. 기존 자유 메모의 바이트와 저장 형식은 보존한다. 저장 후 JSON 왕복과 다시 읽기에서 조사 범위를 복원한다. 손상된 구간은 원문을 보존하고 오류를 표시한다. 저장과 JSON 백업은 미완성 상태도 허용한다.

최종 Markdown 내보내기는 문제와 후보, 판단 근거와 적용 조건을 요구한다. 안내 수정안을 선택하면 대상 문제, 선택 이유와 적용 조건을 확인하며 조사 범위가 바뀐 뒤 이전 대상이 남으면 다시 연결하도록 막는다. 이미 작성한 이유와 조건은 유지하고 빈 필드는 연결 시 채운다. 결제 기능 등 다른 후보는 안내 수정안을 선택하지 않고 추가 확인 계획으로 내보낼 수 있다. 기능 오류의 실제 해결안 확정은 로그와 재현 등 추가 증거가 필요하다. 예산에는 목표 ROAS와 운영 제약의 부재를 표시하며 예산용 근거와 재검토 조건을 조사 조건과 분리해 검사한다. 원천 패널은 시점, 매체, 상태와 금액, 고객 원문을 먼저 읽고 JSON 상세를 확인하도록 바꿨다.

독립 재검토에서 전체 매체 기기 근거 누락, 빈 수정안 필드 재연결 실패와 예산 조건 혼동을 발견해 수정했다. [이번 검증 기록](../../evidence/roas-investigation-20261022/validation.json)의 Node 검사 193개, 타입 검사, 린트와 빌드가 통과했다. 독립 Decimal 검산 13항목과 기존 30,327행 보존, 데이터 해시 일치를 확인했다. 린트의 기존 pages 경로 안내와 빌드의 기존 폰트 런타임 해석 경고는 로그에 남긴다.

후속 독립 재검토에서는 조사 대상을 새 범위로 바꾸면서 이전 이유와 조건이 남는 오류를 추가 발견했다. 범위가 달라진 기존 판단은 자동 갱신하지 않고 내보내기를 막는다. 사용자가 명시적으로 현재 조사로 대상, 이유와 조건을 교체할 수 있게 했다. 비용과 환불 문제에 안내 수정안을 붙이는 경우도 차단한다. 마지막 수정 후 ROAS 검사 45개와 최종 타입, 린트, 빌드를 다시 통과했다.

최종 브라우저 상호작용은 미검증이다. 기존 탭이 이전 화면을 보여주며 새로고침은 미저장 초안 손실 가능성으로 자동 승인 검토에서 거절됐다. 기존 탭을 보존하고 허용 여부를 질문했다. 따라서 실제 클릭 왕복, 현재 UI의 저장과 내려받기, 시각 배치와 현업 마케터의 과업 성공을 통과로 기록하지 않는다. 자동 검사는 계산과 상태, 출력 계약의 검증이며 인과관계와 현업 유용성의 검증이 아니다.

#### 위 계획의 구현과 검증 결과

위 1~4번을 기존 자료와 저장 형식 안에서 구현했다. 조사 범위나 후보를 바꾸면 확인창이 뜨며, 취소 시 기존 상태를 유지한다. 확정 시 이전 범위, 후보와 판단을 자유 메모에 보존하고 새 판단을 비운다. 선택한 안내 수정안도 해제한다. 별도 저장 필드나 schemaVersion 변경은 없다. 관리 조사 구간을 일반 메모 입력에서 제외하고 결합해 저장하므로 직접 편집으로 포맷이 깨지는 경로를 제거했다. 기존의 손상된 구간은 원문 내려받기와 명시적 복구를 제공한다. 복구는 원문 구분자만 비활성화하고 원래 문장을 보존한다. 전체 메모 5,000자 제한은 유지하며 넘치면 기존 상태를 바꾸지 않는다.

비용은 노출, 클릭, 광고비, CTR, CPM과 CPC를, 구매금액은 주문, 수량, 수량 가중 정가, 주문당 할인과 상품금액을 비교한다. 취소와 환불은 선택 매체와 방문 기기의 원주문을 기준으로 조정 전 상품금액과 확정 차감률을 보여준다. 금액은 BigInt 최소단위로 계산하고 대기 요청과 같은 금융 사건의 별칭을 차감하지 않는다. 필요한 광고 기기 분할이나 주문 원천이 없으면 전체 매체의 값으로 대체하지 않고 미확인으로 남긴다. 전환은 기기별 모든 구매 단계와 직전 단계 전환율, 감소 건수를 분석 앞쪽에 배치한다. 기존 매체 전체 표는 기기 선택 미적용을 명시한 참고 펼침으로 옮겼다.

문제별로 후보와 다음 확인 안내를 바꾸며 원인 미확인 상태에서도 필요한 자료와 확인 계획을 남길 수 있다. 안내 수정안은 해당 문제와 안내 후보를 선택한 경우에만 표시한다. 현재 표본에 없는 경매, 운영과 실제 결제 실패 원인은 확정하지 않는다. 모든 화면에서 저장 이름, 상태와 저장 도구를 사용할 수 있다. 근거 목록은 날짜, 한국어 종류와 행동 또는 고객 문장, 금액을 먼저 보여주고 ID와 JSON은 상세로 옮겼다. 사건 발생일 기준 전/후/기간 밖 처리 필터, 자료 종류 필터와 날짜 정렬을 제공하며 내려받기는 현재 검색 결과와 일치한다.

검토서 제목과 본문은 보존하면서 앞부분에 선택한 조사 범위, 전후 수치, 원천 ID, 후보, 근거, 적용 조건과 미확인 사항을 넣는다. 기기별 분석 수치도 같은 함수를 사용한다. R001은 방문과 상류 단계가 고정되고 구매가 모두 방문 4분 뒤 발생하는 결제 이후 하락 주입 사례라는 점을 화면과 출력에 명시한다. 이는 추가 현실적인 데이터를 생성한 것이 아니다.

### 2026-10-22, 문서 작성 도구 제거와 데이터 대시보드 복원

대시보드 진입점에서 검토안 저장과 복원, 제목 입력, 현재 조사, 후보 선택, 판단 메모, 수정안과 예산 의견, 파일 내보내기와 검토서 작성 기능을 제거했다. 이전에 저장한 브라우저 자료와 JSON 파일을 삭제하지 않으며, 현재 대시보드는 저장소를 읽거나 쓰지 않는다. 과거 구현과 Evidence는 당시 기록으로 보존하고 현재 기능으로 안내하지 않는다. 신규 데이터와 저장 스키마 변경은 없다.

### 2026-10-22, ROAS 주지표 위계와 비교기간 명확화
